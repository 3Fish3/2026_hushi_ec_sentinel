## 2. 首轮交付范围

### 2.1 已确认的推进选择

2026-09-18 用户选择 **只读采集 APP 优先**. 将外部规划 A0 所需的 M0/部分人工标定取证前置, 提取 A2 的最小只读观察部分; 不把完整 A1+A2+A3 或整车首版塞入同一轮.

首轮软件交付:

1. 独立 `sentinel_capture` 固件角色. 接收 CAN1/CAN2、DR16、BMI088, 不携带执行器驱动命令; 为 DM 采集仅允许已核对的白名单参数读取与固定状态查询.
2. 最小 Python PC 工具: 指定串口、查看设备和原始数据、开始/结束记录、人工打点及导出. 复用现有项目级 `.venv` 和串口分帧能力, 不增加向导/验收打卡/自动调参.
3. 本车候选映射的九个 DJI 和一个 DM 接收槽、独立样本时间/有效性、逐 ID 统计、采集链路丢弃诊断. 未冻结机械量时仍可记录原始编码.
4. 原生接收/统计/时效测试、C++/Python 观测协议对照、F407 交叉构建和非驱动镜像检查. 软件交付不以硬件到场为前提.

不包含: 正式运动控制、PID 调试、执行权限入口、设备设置写入、任意 DM 查询/控制帧透传、自动置零/寻零、Flash 标定持久化、完整 Jetson bridge、ROS/三维界面、MuJoCo/Gazebo、整车高频全量原始 CAN 串口抓包.

**软件实现选择不是烧录/实测授权.** 后续烧录、设备供电、人工拨动机构分别按届时明确的硬件范围执行. 即使 pitch 正常停止已经选择 disable, 只读固件也不发送 disable 帧.

### 2.2 后续正式 APP 的顺序

- A1: 先闭合第 3 节所列目标/停止/会话语义, 再交付静态 APP、机构执行逻辑、模拟配置、九 DJI + 一 DM 装配、组提交及生命周期原生测试.
- A2: 正式业务协议、最小 host 接入和整车状态; 只读采集协议不自动成为长期整车控制协议.
- A3: 对应机构的真实配置、停止动作和试验边界冻结后, 单独授权最小动力验证.
- A4/A5: 主 yaw 惯性反馈重构与稳向、fire 相对控制和 pitch 联调. 主 yaw 稳向仍是整车首版目标, 不以编码器相对角控制冒充完成.
- A6/A7: Jetson 全链、约束、供电恢复及整车验收; 带弹另行授权.

当前不要求完整 CAD、全部惯量或正式赛事常量齐全才能做只读工具和纯逻辑. 也不把只读工具通过称作正式 APP 或主 yaw 稳向已完成.

## 5. 无主动驱动只读 APP 的设计

### 5.1 “只读”的准确含义

建议数据链: `CAN ISR 打点/入队 → 有界任务接收/解码/统计 → 一致快照 → USART6 → Python 显示/记录/人工标签`.

- 不发送 DJI 电流帧, **零电流帧也不发送**; 不发送 DM MIT、enable、disable、清错、置零或参数写入; 不启动 heater/PWM 或原 S5 控制路径. 唯一 CAN TX 为 CAN1 的 STD `0x7FF`, DLC=4: `01 00 33 RID` (固定寄存器白名单) 或 `01 00 CC 00` (固定状态查询).
- 正常 CAN 接收可保留硬件 ACK. 当前板级为 `CAN_MODE_NORMAL`, 所以“没有驱动命令”不等于总线电气完全静默; 本角色还有上述 DM 参数读/状态查询帧. 不默认改成 silent: 若总线上没有其它接收节点 ACK, 可能改变反馈与重传行为. 严格被动监听需求另行确定.
- PC 只请求观察数据; “此处为机械零位”等标签只记在 PC 日志, 不调用 MCU `reference_position`, 更不写电调零位. 日后经复核再形成标定配置.
- 无驱动路径不能保证机构物理不动. 试验前排除旧控制器/厂商工具正在发命令、残余动作和重力回落; 不能把接入本 APP 当作主动停车手段.
- 人工缓慢拨动是有机械运动的标定, 与完全静止观察分开授权. 不强推不可反驱减速机构, 不撞硬限位找零, pitch 按实际负载支撑.

### 5.2 最小观测内容

| 记录 | 字段/质量要求 |
|---|---|
| 身份 | 固件/构建标识, 日志 schema, 采集角色, 本轮记录 ID, 候选接线/标定版本; ELF 哈希写日志头, 字符串标签不能替代它 |
| CAN 每槽 | bus、标准数据帧 ID、DLC、最近原始 8 B、接收计数/时间、间隔统计、最后样本年龄; 扩展/RTR 在板级拒绝并计 ignored, 非法/未知分开计数 |
| DJI | 原始 encoder 0..8191、rpm、effort_raw; 同时显示转子 rad/rad/s; C610 无有效温度, 不填 0°C 假正常 |
| DM | node/status、p16/v12/t12 和原始帧、温度; 保存量程未确认时物理 p/v/t 标未标定, 不拿旧 12.5/30/10 冒充确定值 |
| 机构推导 | 仅在方向/传动/参考有证据时显示关节量; 原始转子单圈有效不等于关节绝对/多圈参考有效 |
| DR16/IMU | 通道/拨杆/键鼠, gyro/acc/temp, 各自时间/有效性; 不把姿态估计器输出当独立标定真值 |
| 采集质量 | 硬件 FIFO overrun、软件队列 overflow、高水位/排队年龄、未路由/解码拒绝、UART busy/丢弃与主机坏帧; 不混为一个丢帧数 |

当前 `DjiFeedback` 不保留原始 encoder 整数, 因此记录应保留原始帧, 从协议字段提取整数; 不从浮点角反算再称原始数据. 型号由候选安装表声明, 不靠 CAN ID 猜 C610/C620.

DM 问询式反馈已核对指定手册第 13 页, 不能靠被动监听保证收到状态. 实现采用第 17 页明确的 `0x7FF / 0x33` 参数读取, 第 21 页 `0x50 p_m` (转子推导的输出轴角) 与 `0x51 xout` (输出轴编码器角) 均为只读 float/rad. 另核对达妙官方 `motor-control-routine@ae6c1031056908d3d8059f003bd015a9d6b21894` 的 `read_motor_data` (确认 DLC=4) 与 `read_motor_ctrl_fbdata` (STD `0x7FF`, DLC=4, `CANID_L CANID_H CC 00`), 实现后者读取普通状态. 不通过修改控制帧高 3 位、enable、零 MIT 或空载荷请求反馈. 保存量程/模式/版本也仅从读取白名单取得, 不更改设置. 参数响应优先分流, 不作为普通 MIT 状态解码; 位置读取不依赖猜测 PMAX.

来源为 `DM_J4310_2EC_V1.1_Manual_V1.2_EN_20260908.pdf`, SHA256 `7107b810f2573a82712556030d8e74eec8162cc4835aa19ffcac8c43a223d886`; 第 13–21 页相关段落已读取. 装机是否支持该版寄存器仍待实物反馈; 未响应不自动使能或回退控制帧. 手册未明确参数读是否刷新通信超时计数, 所以该工具不用于证明电调失联停机时间, 也不应旁路接入正在驱动的其它控制器.

### 5.3 时序与带宽: 不能让测量工具制造假象

- 当前两总线共用 32 帧软件队列, 常规 10 ms 服务、最多消费 32 帧, 推导服务上限 3200 帧/s. 十电机实际反馈不明时不能直接用它证明整车帧率. 采集角色已使用独立高优先级 1 ms 接收任务、128 帧队列/每周期处理上限, 慢 SPI/串口仍在原 10 ms 任务. 这避免慢 SPI 阻塞接收服务, 但峰值空窗和队列容量仍需实测, 不能只凭配置证明无丢帧.
- 逐 ID 统计在 MCU 上按收到的每帧更新, PC 低频读取汇总. **PC 5–10 Hz 显示不能用于推算 1 kHz 反馈间隔**. 原始全速日志只在有界选轴 trace/足够预算下提供, 不承诺 115200 全量直传.
- 现有 CAN `HAL_GetTick()` 打点是 MCU 接收毫秒, 不是电调采样时刻. 采集角色另记录 ISR 的 DWT CYCCNT, 仅在相邻接收间隔小于 1 s 时计算 uint32 回绕差, 累计计数/min/max/sum; 用 168 MHz 换算短间隔. 长时间戳仍为本地毫秒, 不把 DWT 当长期或跨机时钟.
- BMI088 当前时间是调用方传入的轮询时间, 不保证 SPI 完成或芯片实际采样时刻; 顺序读取 acc/gyro 也不自动同步. 首轮低速安装核对可使用, 主 yaw 高频重构须另证时序与新样本识别.
- UART 分帧复用, 观测载荷独立版本, 超过 256 B 时分页/分流并注明样本各自时刻; 不无声改变旧面板载荷. 忙时拒绝/降采样计数, 不排队发送大量旧快照.
- CAN 接收到达率不等于电调配置发送率; 饱和、错误重传和 MCU 丢弃会造成差异. 135 bit/帧模型下 CAN2 七路 1 kHz RX + 两组 1 kHz TX 需求为 1.215 Mbps, 只是预算假设, 不是“实测负载 121.5%”. 无运动输出的采集也不能单独证明加上正式 TX 后预算成立.
- 历史 RX/drop 计数不人为清零; 用记录开始基线、结束差值区分本次窗口. 细分新计数的口径, 不把旧 `rx_dropped` 中设备表拒绝误称全部硬件丢帧.

### 5.4 人工标定操作与能得到的结论

在对应人工运动授权、供电/支撑明确后, 每次只处理一个可安全反驱的机构:

1. 静止记录候选 ID、原始值、样本新鲜度和帧率. 没有反馈不继续猜测机械量.
2. 人工放到已定义的机械标记/夹具位置, 在 PC 打点: 轴名、姿态标签、独立量角值/单位、当前原始帧序号及时间、照片/夹具证据入口. 若只知道“朝前”而无定量真值, 记录定性精度.
3. 朝明确的机构正方向小幅缓慢转动, 再次打点并回到标记, 核对哪个 ID 变化、符号、回程差异. 点击记录时保持该姿态直至对应页面的新快照返回; 日志分别保存点击与返回时刻. 变动多个串联轴时不能仅凭单个数值认定映射.
4. 首轮工具只保留原始单圈编码, 不自动累加圈数, `joint_rad/cumulative_rotor_rad` 为 null. 后续离线解算仅在连续、无丢帧且相邻转子增量可唯一解包时累加编码差; 低频快照本身不能保证该条件, 跨 4096 判圈也不保证正确. 用 `Δθ_rotor = 2π·ΣΔencoder/8192` 与独立 `Δq` 估计完整传动比及符号. 未知传动比时选机械允许的小角度, 不要求机构转满一圈.
5. DM 首选直接读取 p_m/xout 的 rad 值并保存寄存器原始 bits、请求/响应时刻; 若观察到普通状态帧也保留 p16. 后者仅在 PMAX 有证据时才可换算. 再由独立标记求机构零点与传动, 不重复套用内部减速比.
6. 比较多次标记的重复性; 形成待审核标定结果, 不自动刷入固件. 断电、丢帧或多圈歧义后建立新采集分段, 不沿用旧累计角.

可以得到: 候选 ID↔实物对应、局部正方向、标记处编码值、有限范围传动/回差线索、被观察区间以及时间质量. **不能仅凭编码器得到**机械硬限位/安全软限位、线束可转圈数、掉电前多圈绝对位置、电调电流模式保存值、动态稳定性或安全停车距离.

### 5.5 日志及软件退出条件

- 首轮用 Python JSONL 保存原始/推导值和质量, CSV 作为派生导出; 无值写 null 并附原因, 不写健康零值. 日志头记录版本/固件/机械标记, 每个打点关联具体样本, 不是 PC 点击时刻冒充 MCU 采样时刻.
- 原始大日志放项目 `build/` 下具名目录, 默认不入 Git; 获采纳的标定数值/哈希/证据位置回填 Checklist. 清理 build 前须保留仍有用的证据, 不把唯一标定依据留在易清理目录.
- 必要软件验证: 真实 codec 的原生解析和边界测试, encoder 跨圈/断流不得伪恢复, 统计计时回绕/队列丢弃, C++/Python 字节对照, PC 日志重读/导出, F407 链接与无执行器发送符号检查.
- 独立角色检查应覆盖 DJI/DM 命令及 CAN TX/PWM/S5 路径; 保留现有 `sentinel_s1` 默认无输出审计, 不靠放宽它证明新角色合格. 检查通过仅证明软件范围, 实机独立观察 TX 与完整接收效果另行验收.
