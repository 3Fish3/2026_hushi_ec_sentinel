# 哨兵应用配置与换算基线

## 1. 边界

本文是哨兵正式 APP **配置项、单位与旧参数换算依据**的唯一维护位置.

- 行为细则 (控制来源、停止动作、权限、故障依赖、操纵映射) 仍以 [现有能力与待确认 Checklist](现有能力与待确认Checklist.md) 为准, 本文不复制第二份行为契约.
- 本文不是实车参数表: 标注为"未提供"的项必须由机械/电控记录或限定实测补齐, 不在此处填猜测值.
- 代码入口 `robots/sentinel/app/sentinel_config.hpp` / `.cpp`; 契约测试 `tests/sentinel_app_tests.cpp`.
- 数值来源由 `ec::sentinel::app::Origin` 显式标注:
  - `user_confirmed`: 用户明确确认的装配事实, 不冒充仪器实测;
  - `measured`: 有实际测量依据的配置;
  - `reference_converted`: 由旧仓库已运行参数按其单位/反馈源换算到新域;
  - `synthetic`: 仅供离线测试的合成夹具值, 永远不等于实车参数;
  - `unspecified` / `nullopt`: 尚未提供; 该域不取得执行资格.

配置类别由 `ConfigKind` 区分: `synthetic_fixture` 只允许离线测试用途, `real_deployment` 才允许部署用途. 两者混用 (部署配置里出现合成值或未标来源的已装配设备) 会被校验直接拒绝.

## 2. 配置项与单位

所有配置量为 SI 单位. 未注明的单位都应视为"尚未提供"。下表"设备/模式"是 Checklist 记录的候选映射, 不是实物核对结论.

| 域 | 设备/模式 (候选) | 关键配置项 (单位) | 代码字段 | 当前来源 | 尚缺依据 |
|---|---|---|---|---|---|
| `chassis_lf/rf/lb/rb` | M3508 + C620 电流 (CAN2, ID1–4) | bus/id、`rotor_per_axis`、`direction`、`current_limit_a` (A)、`output_limit_raw`、`max_rotor_speed_rad_s` (rad/s)、`max_axis_velocity_rad_s` (rad/s)、`feedback_ttl` (ms)、速度环增益、轮几何 `x_m/y_m/roll_dir_rad/radius_m/gain` | `DjiSlot` + `WheelGeometryConfig` | 夹具仅 `synthetic_config()` | H05 / C05 |
| `main_yaw` | GM6020 电流 (CAN1, ID6) | 同上, 另需位置环增益与关节 `zero_offset_rad/min_rad/max_rad` (rad) | `DjiSlot` + `JointGeometryConfig` | 夹具仅 `synthetic_config()` | H05 / G06 |
| `fire_yaw` | GM6020 电流 (CAN1, ID4) | 同上 | `DjiSlot` + `JointGeometryConfig` | 夹具仅 `synthetic_config()` | H05 / G06 / G07 |

| `friction_left/right` | M3508 + C620 (CAN2, ID5/6) | 同上 (无位置环) | `DjiSlot` | 夹具仅 `synthetic_config()` | S06 |
| `trigger` | M2006 + C610 (CAN2, ID7) | 同上 (协议满量程不同) | `DjiSlot` | 夹具仅 `synthetic_config()` | S06 |

`max_axis_velocity_rad_s` 是轴侧目标量程, 同时是速度环的拒绝边界与底盘 twist 同比例缩放的基准；它不是从协议满量程或旧 `reduce_rate` 推得的。底盘缩放取四轮中的最小上限, 全轮共用一个系数, 不独立夹单轮。

轮向符号只在一个位置生效: `DjiSlot.direction`（设备/电气符号）与 `WheelGeometryConfig.gain`（额外机构符号）都默认 `+1`; 同一反向只能在一处表达, 否则两次取反会静默相消.

时序 (`TimingConfig`): `control_dt_s`、`target_ttl`、`remote_ttl`、`imu_ttl`、`host_link_ttl`、`max_dt_s`. 旧任务延时 (2/5/1/2 ms) 只是代码值, 不是实测周期, 未作为配置缺省填入. `imu_ttl` 保留为设备在线观察时限, 不代替重构质量界; 惯性有效性实际由 `PerceptionTiming` 判定, `max_dt_s` 暂保留为命令预测步长上限. DJI 控制步长改由各组 `runtime.*.max_step_us` 给出, IMU 积分上限改由独立 `perception.max_gyro_step_us` 给出, 不因控制 max_dt 改变而重建惯性参考.

本地操纵映射 (`RemoteMappingConfig`, 由 `robots/sentinel/app/sentinel_remote.*` 持有) 是独立配置, 不并入设备配置: `stick_deadzone`、底盘 `chassis_vx/vy/wz` 上限 (m/s, m/s, rad/s)、角度层 `yaw/pitch_rate_max_rad_s`、`friction_rad_s`、`trigger_rad_s` 以及 ch4 三层判读 (`mid`/`upper`/`lower`/`hysteresis`, 原始值). 旧仓库的 `channel × 6`、小陀螺 80、135° 变换都不可换算为上述单位 (C02/C03), 因此不填默认值; 离线夹具只是显式测试值.

**ch4 依据:** 官方 C 板示例 (`9.remote_control_dma`) 解析 `ch[4] = sbus_buf[16] | (sbus_buf[17] << 8)` 后与 ch0–ch3 同样减 1024, 示例本身标注 `//NULL`, 即该字段未被文档化. 因此本仓库只按该依据解码原始值, 不套用 ch0–ch3 的 ±660 归一化, 中位/方向/量程留给实测; 官方示例把 byte5 bit5:4 注释为 left、bit7:6 为 right, 与本仓库命名相反, 在实物核对前不翻转已运行的接管操作.

外部约束 (`AuxState`, 由调用方每周期注入): `launch_permit_valid`/`launch_permit`/`launch_sampled_at`/`launch_ttl` 组成发射许可 (缺失或过期一律不当作许可), `power_limited`/`heat_limited` 只是可注入观测. 本版只对发射许可做门禁 (A11), 功率/热量阈值依据仍缺, 不据此新增限制.

### 2.1 后续运行接口 (N0)

`sentinel_runtime.hpp` 明确 `YawFrame` 的 joint/local_inertial/odom, 不与控制模式或权限状态合并.
`MicroTick`/`MicroLifetime` 与协议毫秒 Tick 类型分离; 32 位微秒比较窗口小于半回绕周期.
`GroupTiming` 表达 period/phase/output_ttl/max_step, `GroupClock` 跳过积压周期并报告真实 dt.
`RuntimeTiming` 的 GM 1 ms、CAN2/DM 2 ms 是软件候选; 最大步长/输出年龄同为待验证软件策略,
不是实车能力. `PerceptionTiming` 独立声明 gyro/joint 年龄、外推与积分上限, 未提供保持空值,
不再把设备在线 TTL 或控制 max_dt 当惯性质量保证. N1 已接入各组调度及独立 IMU 积分上限;
三维重构使用下述独立模型与质量参数. 部署未提供惯性积分策略时不发布有效惯性反馈.
历史 `synthetic_config()` 显式保留各组 1 ms 同频便于既有原生夹具, 多速率用例显式选择 `RuntimeTiming{}`;
不得把夹具同频配置当部署默认.

### 2.2 主平台旋转模型与采样质量

`SentinelConfig::serial` 缺省为 null, `serial_origin` 标记其来源; 未标定部署不会用 synthetic 补齐.
模型缺项只使主平台惯性反馈不可用, 不阻塞独立底盘/发射机构. 给出的模型含非法旋转、轴或合成部署来源时拒绝该配置.

- `fire_axis/pitch_axis/main_axis/forward`: V 系带符号单位向量. V=S0 是计算系定义, `forward` 仍须实际确认.
- `install`: 原始芯片量→S 日志/计算系的正交旋转; `gyro_bias_sensor`: 旋转前扣一次的三轴静态偏置.
  N2 原始拟合直接使用芯片 S, 此时 install 的 identity 是坐标定义, 不再把同一安装量叠加一次.
- `fire_reference/pitch_reference`: 标定姿态在当前机械关节坐标中的角度. 参数事务改零位时同步加 `旧零位−新零位`, 保持同一物理标定姿态并清该轴历史; 改安装/传动不属于此等价平移, 仍需重新标定.
- `position_lag_us/velocity_lag_us`: fire/pitch 独立时移, 正号表示 gyro(t) 对应 encoder(t-lag).
  固定 16 点历史允许 ±10 ms 配置范围; 超过历史覆盖或插值跨过外推上界时不可用, 不向过去猜角度.
- `min_projection_squared/min_heading_gain`: 前方向水平投影与主轴作用增益的数学退化界;
  `accel_norm_error_mps2`: 重力观测比力模长质量界. synthetic 数值只是软件夹具, 不是本车精度/噪声验收线.

姿态传播与新 accel 校正分开, accel 有效性不刷新 gyro 年龄, 旧 accel 不被反复融合.
超过短外推界即报告 stale; 只有超独立积分上限后的真正姿态重建才推局部参考代次并使主 yaw 旧目标失效.
短缺样/普通质量下降不推代次, odom 对齐不成为本地反馈初始化前置条件.
主平台重构按 `R_WV=R_WS*(E_f*E_p)^T`, 角速度扣除下游运动后由前向投影求方向/速率, 不是末端 Euler yaw/gyro.z.
时间误差字段保留 gyro 的采样估计界, CAN 没有源时刻时保持未知, 不将接收年龄宣称为精确物理相位.

`sentinel_replay.py` 从 N2 标定候选与 `.sraw` 生成有标签输入, 原生 `ec_sentinel_replay` 调用同一 `SentinelPerception`.
候选不会自动写进 MCU; 真实配置回填仍需确认来源和适用工况, 回放通过不是实车稳向结论.

### 2.3 主 yaw 闭环与参考系

类型化目标/执行结果显式区分 `joint`、`local_inertial`、`odom`. DT7 捕获/积分的是 MCU 局部惯性方向;
机械维护与 G07 使用关节角, 不依赖 IMU/Jetson 对齐. odom 目标先减已建立的对齐偏移再解算.
线协议 v3 已携带参考系并区分请求/采用/测量标签, 旧 v2 没有该标签, 不兼容新布局.

主 yaw 只有一个 `DjiAxis` 串级控制器/编组所有者. 惯性模式先按当前三维姿态求可达机械分支 `q*`,
以 `g*(q*−q)` 形成方向外环误差 (`g=d heading/d main_joint`), PID 的测量和 D 项来自连续惯性方向.
外环输出除以 g 得到等效轴速目标, 惯性 heading_rate 同样除以 g 后进速度内环, 不用编码器相对速率替代.
内环目标仍受已配置轴速量程限制, 电流归一化/电气方向由既有轴/设备路径各换算一次.
机械角负责参考、分支与限位; 到边界后朝界外的电流为零, 不借其它机构补偿.

外环使用 `direction_period_us/direction_max_step_us` (候选 2/10 ms), 内环随 GM 组 (候选 1 ms).
非到期周期保持外环输出而不清积分; 真无效 dt 走原拒绝路径. 模式换反馈时清同一控制器的历史,
不存在两套控制器同时写主轴. 增益热调读回来自该实际外环/内环, 不是影子配置.

重构失效只按 G07 保留原意图期限内的机械保持, 没有原意图或编码器也无效则不生成保持.
本地装配在继续刷新底盘等目标时显式保留该原租约, 不误撤销也不续期; 外部快照的缺域撤销规则不变.
恢复需新的有效意图; 本地用本周期的新姿态与新操纵生成目标, 不再因上一帧降级标记额外拒绝一周期.
真正惯性参考重建只作废惯性意图/降级保持, 不取消未改变机械坐标的维护目标.

### 2.4 测量轮速里程计与独立机构配置

四轮的轴侧速度来自实际 CAN 解码样本, 以 `OmniWheelModel` 的同一几何矩阵构建最小二乘逆.
列归一化后检查满秩, 非满秩/不全/超各轮 TTL 不产生有效 twist. 使用四轮最新有效测量,
不假装异步采样完全同步; 轮间时刻差单独上报, 不依赖 IMU 的时序配置.
最老样本水位线推进时按真实微秒间隔积分, 检查两端覆盖; 缺口计数并断开积分区间, 不跨缺口补积分.
残差以轮轴 rad/s 表达, 是不一致指标而非打滑判定或新门禁. 累计 pose、当前有效性、历史是否有缺口分开报告.

命令预测仍单独标记 `command_prediction`, 仅底盘有采用 twist 且四轮实际具备执行资格时推进,
不得拿它代替反馈 odom. 没有几何/速度反馈的底盘不会阻塞云台与发射机构.

独立试验仍保留真实安装槽: 地址/协议冲突不能构造拥有者; 最小换算缺失使相应 DJI 命令组只发显式零,
但其它组可运行. device 已齐、控制参数或关节几何缺失时, 该轴零输出而同组其它可用轴保持运行.
不期望运行且从未见到的未配置机构不伪造失联; 真正已见后失联/故障的 A09 仍有效.
无 DM 量程只可 disable, 不创建伪造设备反馈/使能. 这不是通过隐藏已装设备来测试.

`robots/sentinel/host/mechanism_fixture.hpp` 是此缺项场景的纯合成模板, 不入固件.
最小工具按 MCU 返回的参数作用域保存分机构候选, 不从 ID 猜机构, 不保存不存在的 PID 为零.
真实部署仍需上述来源与物理核对; 软件选机构不代表其它机构已经物理隔离.

## 3. 旧有效参数的换算依据

### 3.1 DJI 速度环

旧仓库速度环增益的量纲是 **raw 电流编码 / (转子 deg/s)**, 输出限幅同样是 raw 编码 (`app/gimbal/gimbal.hpp`、`app/chassis/chassis.hpp` 等). 换算到新域需要三步:

```text
反馈:  转子 rad/s = 旧 deg/s × π/180
轴侧:  rad/s(轴) = 转子 rad/s / rotor_per_axis × direction
增益:  Kp_A_per_rad_s = Kp_old × N × (180/π) × (A_full / raw_full)      N = rotor_per_axis
       Kp_norm        = Kp_A_per_rad_s / current_limit_a        (轴侧电流上限, A)
限幅:  output_limit_norm = 旧 raw 限幅 × (A_full / raw_full) / current_limit_a
```

**N 不能漏乘.** 旧增益的分母是**转子** deg/s, 而新控制环的误差量是**轴侧** rad/s:
轴侧角速度 = 转子角速度 / N, 因此把"每 (转子 deg/s) 的电流"改写成"每 (轴侧 rad/s) 的电流"
必须乘以 N = `rotor_per_axis`. 已核对的 GM6020 例子 (N=1) 恰好不暴露这个差别, 轮/
摩擦轮/拨弹不能照抄那条缺 N 的通式. `Ki`/`Kd` 还需另外核对旧代码的积分时间常数与微分/
滤波定义, 不能机械套用同一条公式.

`A_full / raw_full` 由设备协议决定 (`ec::drivers::dji_current_amp_full_scale` / `dji_protocol`):

| 模式 | 满量程电流 A | raw 满量程 |
|---|---|---|
| C620 (M3508) | 20 | 16384 |
| C610 (M2006) | 10 | 10000 |
| GM6020 电流 | 3 | 16384 |

已核对的例子 (Checklist R03、`docs/modules/control/速度控制链.md`): 旧 yaw1 速度环 `Kp = 73` 换算为
`73 × (180/π) × (3/16384) ≈ 0.7659 A/(rad/s)`; 旧输出限幅 `3000 raw ≈ 0.5493 A`.
做数值回放时必须连旧限幅一起换算, 不能只改 Kp.

#### 有效代码配置与连续时间换算

已核对 `references/Sentinel/modules/pid/PIDController.cpp`、`bsp/system/time.cpp` 与
`modules/motor/DJIMotor/DJIMotor.cpp`: 旧 `GetDelta` 返回整数毫秒, PID 除以 1000 后取至少 1 ms;
积分为 `Ki*error*dt`, 微分为 `Kd*Δerror/dt`. 因此不是需额外乘/除控制频率的离散 Ki/Kd.
速度环的 P/I/D 均按上述量纲比例换算, 但旧微分针对误差、新微分针对测量, 不能宣称阶跃瞬态等价.
电机 PID 实际由 `modules/motor/motor.cpp` 的 `osDelay(1)` 任务调用; 云台/底盘业务任务 2/5 ms
只改变目标刷新, 不等于其 PID 周期. 这些仍是代码周期, 不是旧现场实测 dt.

下表只取未注释的构造参数, 是**参考候选**, 不自动写入部署配置. 构造参数存在不证明该电机在实际分支执行: 旧`motor_yaw_`绑定CAN1 ID6, `motor_yaw2_`绑定ID4; 按当前实物分别对应fire/main, 不能按变量名直接标成主/从yaw. 此处纠正此前表格的机构标签, 不推定历史接线始终与当前一致. 当前正式APP维护台已按S5电流口径显示/输入DJI速度PID, 可使用表中SI数值, GUI会自动除以实际`current_limit_a`; **不要再手工除一次**. 直接协议/CLI、候选文件及固件`PidConfig`仍使用归一化数值. 同时核对旧电流/速度限幅, 先设电流上限再设速度PID; 更改电流上限会改变既有归一化增益的电流等效值.

速度PID单位分别是Kp: A/(rad/s)、Ki: A/rad、Kd: A/(rad/s²); 位置外环分别为1/s、1/s²、无量纲. 这些是反馈与输出单位的换算, **不是稳定性证明**, 也不把安装正负方向混入正值增益.

| 双摩擦轮, 用户已确认 N=1 | `2.5/0/0.01`, ±6000 raw | Kp=0.174853 A/(rad/s), Kd=0.000699411 A/(rad/s²), 旧 cap=7.324219 A |
| 拨弹, 完整传动 N 待确认 | `0.3/0/0`, ±8000 raw | Kp=0.017188734×N A/(rad/s), 旧 cap=8 A; N=36时Kp=0.618794, 仅原装减速箱/无外部传动假设成立时适用 |

位置外环 deg→rad 同时作用于输入和输出, 所以 GM 的 P/I/D 数值比例为 1, 速度限幅和积分输出限幅仍须乘 π/180.
旧速度反馈为 `0.1*old+0.9*new(deg/s)`; 新链没有继承这层软件滤波, 主 yaw 更改为 gyro/串联重构反馈.
旧启用的是积分限幅 (含饱和时积分冻结), 不是注释所称积分分离; 新 PID 为积分限幅加输出限幅. 旧`Deadband`还会在小误差内令输出归零, 不能只根据一组P/I/D声称完整行为等价.
这些滤波、微分、抗饱和及负载差异必须在独立机构实测时核对, 不按旧注释补旧实现.
**主 yaw 惯性环没有可直接宣称实测有效的增益**. 旧`GIMBAL_AND_CHASSIS`分支显式disable ID4, 其setRef已注释; ID4的构造参数更不能包装成已验证运行基线. 上表仅作带来源的候选, 不能拿SIL夹具参数或机构名称充当实车证据.

#### 当前四电机台架如何使用这些参考

- GM6020保留已人工通过的速度`0.06/1.0/0`、位置`7.5/0/0`、2.5A与五点编码器测速基线. 旧ID6的`0.765855/0/0`并非“更正确”的台架值, 该高增益此前在空载试验出现过振荡; 不为统一旧参数而回退. 本次修正来源标签不修改已人工通过的ID4台架参数, 也不把ID4旧未运行分支的另一组高增益自动应用.
- 当前M3508固件按N=19准备, 使用底盘换算P=2.657763而非直驱摩擦轮P=0.174853. 维护台内部域虽借用`friction_left`, 并不意味着N=1; 若实物传动不同须先确认传动量纲. M2006按N=36准备P=0.618794. 两颗速度I/D均为0, 初始电流上限分别7.324219A/8A. 这些是新电机待调参考, 不等于已通过实机验收.
- 主/从yaw旧位置P/I/D在deg与rad同步换算时数值不变, 但位置外环速度限幅、积分限幅及微分算法不能忽略. 当前APP对已装配位置轴支持三个位置增益的在线写入, “当前只使用P”不等于框架不支持I/D; 不将位置I/D错填进速度I/D.

### 3.2 DM MIT

DM 反馈与命令都在**设备输出轴**上以 rad、rad/s、N·m 表达, 不做旧代码的 `1.18 / 6.25 / 1.15` 伪编码变换.

- 物理 Kp ∈ [0, 500], Kd ∈ [0, 5]; 编码按满量程 4095 线性映射.
- 旧代码直接打包的 `Kp = 35` 是**编码量**, 对应物理值 `35/4095 × 500 ≈ 4.2735`, Kd编码为0, 对应物理Kd=0; 不能把35当物理Kp重新编码 (Checklist R04). MIT是位置/速度误差到力矩的PD, Kp单位N·m/rad, Kd单位N·m/(rad/s), 没有该指令层的Ki.
- 旧`gimbal.hpp`还配置了外部位置P=0.78, 但实际`ONLY_ANGLE`路径随后将PID输出按`/360*6.25+1.18`变为位置并在1.15截断. 这不是当前直接下发原生关节目标的同一结构, 不能把0.78另当新MIT Kp, 也不能宣称仅恢复4.2735/0就完整复现旧pitch控制.
- `PMAX/VMAX/TMAX` 是可配置映射范围, 不是型号固有常量; 未读到电调保存值前不得填默认值 (R06/H06).

### 3.2.1 旧云台方向与限位核查 (2026-09-26)

证据只取当前保存旧源码的可执行分支, 不将历史变量名/注释视为实物测量:

| 对象 | 代码事实 | 可复用与边界 |
|---|---|---|
| ID6 (`gimbal.hpp:39–49, 225–232`) | `reverse=true`, setRef=`cmd.yaw-70`; `DJIMotor.cpp:147–168`仅将参考取反, 内部反馈为原始累计编码角 | 正cmd对应原始角减小. 这是旧指令与编码器的相对符号, 不证明实物俯视顺/逆时针 |

模式覆盖不统一: 旧普通遥控分支施加上述cmd限幅; 小陀螺分支`robotcmd.hpp:285–291`更新目标但没有相同限幅, 键鼠pitch限幅在343–346行已注释, 视觉初始化分支另有同值截断. 因此不能把这些常量当作全模式通用机构边界. 旧遥控pitch初始化标志一开始为1, `if(!flag)`不执行, 也不能据`YAW_SET_INIT=1.18`宣称旧程序保证上电回机械零位.

结论: 已找到旧软件符号关系、特定模式目标区间和DM上限, 不再全部列为“无依据”; 但仍缺与当前安装/零位一致的fire/pitch两端工作区及实物正方向核对. 不需要为此重采整套IMU, 优先补最小方向/端点证据. 主yaw连续多圈以本轮用户确认及新的周期参考设计为准, 不套用旧ID6有界命令区间.

### 3.3 底盘 twist 与轴侧量

```text
轮轴侧目标 rad/s = ((v + ω × r_i) · d_i) / radius_i × gain_i      (omni_wheel_speeds)
同比例缩放系数     = min_i(轴侧上限_i) / max_i|轮轴侧目标_i|      (仅当 > 1 时缩放)
归一化输出          = 速度环输出 × current_limit_a / (协议满量程 A × output_limit_raw/协议 raw 上限)
协议 raw            = 归一化输出 × output_limit_raw
```

旧仓库的 `cmd.vx/vy` 无法确认单位 (C03), 因此这里不推导轮径/轮心/滚动方向, 也不把旧四轮指令当基准确认.

### 3.4 其它

- 旧 `reduce_rate` (M3508=19、M2006=36、GM6020=1) 只是电机侧减速比线索. 双摩擦轮已确认直接耦合 N=1, 不能乘底盘的 19; 拨盘完整传动仍需 S06 确认.
- 旧 `-70`、`1934`、`[-16,50]`、pitch `[-60,28]` 是标记核对线索, 不是新机构的零位/范围.
- 旧四轮 `cmd.vx/vy` 的物理单位无法仅凭代码确认 (C03), 因此不推导轮径/轮心/滚动方向.

### 4.1 回填影响 (哪些能直接填, 哪些会让旧证据失效)

回填动作本身不改代码路径, 但会改变"哪些结论还成立". 按影响分三类:

| 回填项 | 影响 | 必须重做的验证 |
|---|---|---|
| 设备 bus/id、`direction`、`rotor_per_axis`、`current_limit_a`、`output_limit_raw`、`max_axis_velocity_rad_s`、关节 `zero_offset_rad/min_rad/max_rad`、轮几何、`TimingConfig` | 纯数据, 只影响该域的执行资格与限幅 | 部署配置契约测试 (当前断言"无真实值 → 零装配槽/零执行资格") 的期望值需同步更新; 其余离线测试使用 `synthetic_config()`, 不受影响 |
| DM 已保存 `PMAX/VMAX/TMAX`、`CAN_ID/Master_ID`、`TIMEOUT` | 达妙 MIT 编解码的满量程映射与反馈量纲; 若与假设不同, 位置/速度/力矩的物理含义整体改变 | 达妙编解码与 O2/O7 闭环证据需用真实量程重跑 |
| IMU 安装轴向与时间质量 | 惯性反馈重构的输入变换 | 感知重构契约 (现基于合成安装/轴向/时间与原始回放) 需用真实轴向重跑; 主 yaw 降级路径判据也要复核 |
| ch4 中位/方向/量程、`RemoteMappingConfig` 各项、DT7 左右拨杆位域对应 | 本地操纵映射与接管判据的数值与命名 | `sentinel_app_remote_contracts` 与板级观测布局的期望值需按实物重跑 (布局本身不变) |
| 主 yaw 的 odom 对齐关系与参考代次来源 | 连续 odom 与上位机对齐语义 | 感知的 odom 对齐契约与协议 `align` 路径需重跑 |
| 功率/热量阈值、发射许可真实来源与时限 | 当前只上报、不据此限制; 填入即引入新行为 | 属于新行为, 需要新的行为契约与离线验证, 不能只填值 |
| 摩擦轮/拨盘传动比与每发角度 | 轴侧角速度语义成立的前提 | 摩擦/拨弹相关闭环证据需用真实传动重跑 |

回填**不**使以下证据失效: 框架层 (core/drivers/estimation/monitor) 契约、业务协议线格式与
会话语义、任务/CAN/内存静态预算、四个角色的镜像审计与链接核对. 这些与具体机械数值无关.

填表不是授权入口: 烧录、供电、动力测试与机构动作仍需单独明确授权; 配置齐备只表示该域
具备执行资格, 不等于已授权或已验证 (见 [实施与验收](实施与验收.md) 末节).

## 5. 使用方式

```cpp
// 离线测试: 接受合成夹具, 但夹具数值只用于验证配置边界与状态语义.
ec::sentinel::app::SentinelApp app{ec::sentinel::app::synthetic_config(),
    ec::sentinel::app::ConfigAudience::offline_test};

// 正式部署: 从"尚未配置"入口开始, 逐项补齐后按部署用途校验;
// 只要还有合成值/未标来源的已装配设备, startable() 为假.
auto config = ec::sentinel::app::real_config_placeholder();
// ... 按第 2 节填写 DjiSlot/DmSlot/几何/时序 ...
const auto report = ec::sentinel::app::validate(config,
    ec::sentinel::app::ConfigAudience::deployment);
```

未配置的域在状态快照里是 `DomainValidity::unavailable` + `Reason::not_configured`; 配置缺项是 `incomplete` + `incomplete_config`; 配置齐备但尚无反馈/参考是 `unknown` + `no_feedback` / `no_reference`. **配置齐备不等于取得执行资格或已有授权.**
