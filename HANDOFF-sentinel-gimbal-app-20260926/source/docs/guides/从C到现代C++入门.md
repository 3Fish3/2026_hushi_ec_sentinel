# 从 C 到受约束现代 C++

很多新队员初次接触本项目时会产生顾虑：“我只学过 C 语言，写过 STM32 单片机的 HAL 库，能看懂并参与这个工程吗？”
答案是：**完全可以！而且你会发现现代 C++ 写起来比纯 C 更加安全、惬意！**(^_^)b

在本项目中，我们使用 C++ 的核心目的不是为了玩弄复杂的语法黑魔法或构建深不见底的多层继承树，而是利用类型系统、对象生命周期与编译期约束，**让编译器拦截一部分类型与接口误用，并通过清晰的生命周期和边界检查降低运行期风险**。

> **特别声明：关于“受约束现代 C++”的含义**
> “零开销抽象”绝不等于代码天生没有开销或绝对不会出错。由于车载控制对实时性与确定性有极高要求，本项目强制遵循以下原则：
> - **实时控制路径严禁动态内存分配与异常机制**：在周期性控制回路、中断服务函数（ISR）与高频传输路径中，禁止使用 `new`、`malloc`、`std::vector`、`std::string` 或抛出异常。必须使用固定容量的数组、有界队列与预先分配好的对象。
> - **初始化阶段允许受约束的静态组装**：系统启动初始化阶段可以完成拓扑连接与参数传递。我们不能把这条约束绝对化成“整个 MCU 连一块堆内存都不存在”，但实时控制链路中必须零动态分配。

下面我们将传统 C 语言写法与本项目所采用的受约束现代 C++ 特性进行直观对比：

---

## 1. `std::optional<T>`: 显式表达“可能没有数据”

### 传统 C 的痛点
在纯 C 语言中，当一个函数可能无法计算出有效结果（例如 PID 输入了非法参数、或者传感器还没收到有效数据）时，通常有两种做法：
1. 返回一个“魔数”（例如 `0.0f` 或 `-999.0f`）。但这极易引起歧义：如果机器人的目标转速正好就是 `0.0f` 呢？
2. 返回一个错误码整数，并通过指针输出结果：`int pid_step(Pid* p, float target, float* out)`。这种方式极其繁琐，且调用方经常忘记检查返回值直接使用 `*out`。

### 现代 C++ 方案
`std::optional<T>` 优雅地解决了这个问题：它是一个值容器，内部包含“数据本身 `T`”以及一个“是否有值”的布尔标记。
- 它在自身存储空间内保存值，本身不额外分配堆内存；对象可位于栈、静态区或堆对象内，`T` 自身是否分配仍取决于其实现。大小受标记与对齐影响，不保证恰好为 `sizeof(T)+1`。
- 如果计算成功，它包含实际数值；如果失败或无数据，它处于“空值（`std::nullopt`）”状态。

```cpp
#include "ec/control/pid.hpp"
#include <iostream>

// 主机可运行示例: 演示 std::optional 的安全使用规范
// 注意: 此处 PID 参数仅用于教学演示，不代表实车物理参数
int main() {
    // 构造一个简单的比例 (P) 控制器
    // PidConfig 结构体字段按顺序为: {kp, ki, kd, integral_limit, output_min, output_max}
    ec::control::Pid pid{{
        1.0f,  // 比例增益 kp = 1.0
        0.0f,  // 积分增益 ki = 0.0
        0.0f,  // 微分增益 kd = 0.0
        0.0f,  // 积分限幅 = 0.0
        -1.0f, // 最小输出限幅 = -1.0
        1.0f   // 最大输出限幅 = 1.0
    }};

    // 调用 step(目标值, 测量值, 周期步长 dt_s)
    // 返回值类型为 std::optional<float>
    const auto result = pid.step(0.5f, 0.0f, 0.001f);

    // 1. 显式检查是否有值: 可以像指针一样直接放在 if 中判断
    if (!result) {
        // 如果输入了非法参数 (如 NaN、非正 dt 等)，PID 会返回空值而不是错误的数字
        return 1; // 失败退出
    }

    // 2. 确认有值后，使用 *result 解引用取出内部的 float 真实值
    //    误差 e = 0.5 - 0.0 = 0.5, P 输出 = kp * e = 0.5f
    if (*result == 0.5f) {
        return 0; // 预期成功
    }

    return 2;
}
```

> **安全避坑红线**：
> - 绝对不能对未经验证的 `optional` 直接解引用 `*result`，如果内部为空，其行为属于未定义行为（UB）。
> - 不要调用 `result.value()`，因为标准库在空值时会抛出 `std::bad_optional_access` 异常。关闭异常时的具体失败路径由标准库实现决定，不能将其当作可恢复的常规错误处理。请**一律使用 `if (result)` 检查，再通过 `*result` 取值**。

## 2. `std::span<T>`: 零开销、带长度的安全内存视图

### 传统 C 的痛点
在 C 语言处理通信数据包（如串口、CAN 接收缓冲区）时，函数原型通常写成：
```c
bool parse_frame(const uint8_t* buffer, size_t length);
```
指针和长度是完全分离的。一旦调用方传错了 `length`，或者忘记做越界检查，轻则读取脏数据，重则触发 HardFault 硬件异常。

### 现代 C++ 方案
`std::span<T>`（C++20）是将“连续内存的首地址指针”与“元素个数”捆绑在一起的轻量级视图对象：
- **零内存分配，零数据拷贝**：动态长度 `std::span` 通常保存指针与大小，固定长度形式可能有不同表示；具体大小依赖平台，不应硬编码为两个字长。
- 它不拥有内存，也不负责释放内存。

```cpp
#include <cstdint>
#include <span>

// 函数片段: 检查输入字节流的第一字节是否为帧头 0xAA
// 参数使用 std::span，调用方可以直接传入原生数组、std::array 等连续内存
bool has_valid_header(std::span<const std::uint8_t> bytes) {
    // 1. 先检查容器长度是否足够，防止越界访问
    if (bytes.empty()) {
        return false;
    }

    // 2. 在确认非空后，安全访问首字节
    return bytes[0] == 0xAA;
}
```

> **安全避坑红线**：
> - `std::span` 的 `operator[]` **不会自动为你检查越界**！访问下标前必须先通过 `.size()` 或 `.empty()` 验证长度。
> - `std::span` 只是借用视图，**绝不会延长底层缓冲区的生命周期**。切勿将一个局部栈数组包裹成 `std::span` 并持久化保存在全局对象中！

## 3. `std::array<T, N>`: 固定长度、绝不退化的现代数组

### 传统 C 的痛点
C 原生数组 `uint8_t buf[18]` 在作为函数参数传递时，会极其容易发生“数组隐式退化为裸指针”的现象，使得 `sizeof(buf)` 瞬间变成指针的大小（4 字节或 8 字节），原有的容量信息彻底丢失。

### 现代 C++ 方案
`std::array<T, N>` 是对固定大小内联数组的封装：
- 长度 `N` 是类型的一部分，编译期可知，永远不会意外退化为指针。
- 支持基于范围的 for 循环、成员比较操作符 `==`、值语义拷贝，且提供 `.size()`、`.data()` 等丰富成员函数。
- 元素连续存储在对象内部，容器本身不额外分配内存；对象可处于栈、静态区或堆中，元素自身是否分配需另看其类型。`operator[]` 也不自动检查越界。

```cpp
#include <array>
#include <cstdint>

// 明确定义容量为 18 字节的 DR16 遥控接收帧
using Dr16RawFrame = std::array<std::uint8_t, 18>;

void process_frame(const Dr16RawFrame& frame) {
    // frame.size() 严格等于 18，编译器强力保证入参绝不会被截断或错传
    static_cast<void>(frame);
}
```

## 4. RAII 机制与作用域锁: 告别“忘记开中断”的噩梦

### 传统 C 的痛点
在单片机中保护一段多任务或中断共享的临界区数据时，C 语言的做法往往是：
```c
uint32_t primask = __get_PRIMASK();
__disable_irq(); // 关中断
if (check_error()) {
    return -1;   // 惨剧发生：提前 return 忘记恢复 PRIMASK，中断永久关闭，整车卡死！
}
do_something();
__set_PRIMASK(primask); // 开中断
```

### 现代 C++ 方案 (RAII)
RAII（Resource Acquisition Is Initialization，资源获取即初始化）是 C++ 极其核心的编程范式：**将资源的获取绑定在对象的构造函数中，将资源的释放绑定在对象的析构函数中**。
因为 C++ 语言严格保证：当代码执行离开当前大括号 `{ ... }` 作用域时（无论是正常执行完、`return` 提前返回，还是 `break` 跳出），局部对象的析构函数**必定会被自动调用**！

```cpp
#include "ec/channel.hpp"
#include "ec/platform/host.hpp"

// 主机可运行示例: 演示 ScopedCritical 离开作用域自动解锁
int main() {
    ec::host::MutexCriticalSection lock;

    {
        // 1. 构造 guard 时自动加锁 (调用 lock.enter())
        ec::ScopedCritical guard(lock);

        // 2. 在受保护的临界区内做极短的有界数据读写
        //    即使在这里写 if (...) return 1; 离开时也会自动释放锁！
    } // 3. 离开大括号作用域，guard 析构函数自动执行，调用 lock.exit() 恢复锁状态

    // 再次加锁演示，验证前一次确实已经正确解锁
    ec::ScopedCritical guard2(lock);
    return 0; // 退出 main 时 guard2 自动析构解锁
}
```

> **安全设计提示**：
> RAII 在正常作用域退出时释放锁，但不能保证复位、HardFault 或进程强制终止时执行析构，也无法自动解决逻辑死锁。在临界区内只进行极短的有界内存复制，**严禁在持有非递归锁时调用可能访问同一把锁的函数**。

## 5. `enum class`: 强类型枚举，杜绝数字混淆

C 语言的传统 `enum` 是全局弱类型的，不同枚举的名字会发生冲突，而且枚举值会被无条件、隐式地转换为任意整数。在电机控制中，一不小心就会把 `CONTROL_MODE_SPEED` 的数值传给了 `TARGET_TYPE_ANGLE`。

本项目统一使用 `enum class`（强类型枚举）：
```cpp
#include <cstdint>

namespace ec {
// 强类型枚举: 来源标签
enum class CommandSource : std::uint8_t {
    none = 0,
    remote = 1,
    host = 2,
    maintenance = 3
};
}

// 使用时必须显式携带作用域
ec::CommandSource src = ec::CommandSource::host;

// 编译器将直接报错，拒绝隐式转换为 int:
// int id = src; // 编译错误！必须 static_cast<int>(src)
```
这样可以阻止不同枚举之间的隐式混用，但外部整数经显式转换仍可能成为非法枚举值，接收边界仍需校验。

## 6. Concepts (概念约束): 编译期拦截不合规类型

在传统 C/C++ 中，如果写一个通用容器，常常使用 `void*` 或者不受约束的模版。一旦类型传错，编译错误信息往往是长达几十行的深层模板展开，如同天书。

在 C++20 中，我们使用 **Concepts（概念）** 来精确声明模版参数必须具备的特征。例如，下面是 `include/ec/channel.hpp` 中约束的简化展示（实际还要求无异常的默认构造、拷贝构造与拷贝赋值）：
```cpp
#include <type_traits>

template <typename T>
concept ChannelValue = std::is_trivially_copyable_v<T> && (sizeof(T) <= 256);
```
这段代码的意思是：“要进入我们通信通道的数据类型 `T`，必须是**可平凡复制（Trivially Copyable）**的，且结构体大小**不得超过 256 字节**”。
例如带虚函数的非平凡类型会被该约束拒绝。但含裸指针的结构体仍可能通过检查：`struct PointerHolder { int* ptr; };` 可以满足此 concept。它不验证指针的所有权、生命周期或被指向内存的并发安全，这些仍由应用负责。

## 7. 现代 C++ 实用语法标签速查

| 语法 / 关键字 | 它的具体作用 | 嵌入式工程中的价值 |
|---|---|---|
| **`[[nodiscard]]`** | 建议编译器对被忽略的结果发出警告，具体诊断取决于工具链配置 | 提醒检查错误码，但不自动处理失败，也不保证调用者检查正确 |
| **`noexcept`** | 声明异常不向调用者传播；若异常逸出会终止程序 | 表达接口契约，不是编译器对函数内部不会失败的证明 |
| **`= default`** | 让编译器自动生成标准构造、析构或比较操作符（如 `operator==`） | 比手动手写 `memcmp` 更加类型安全，且自动处理内存对齐字节填充（Padding） |
| **`constexpr`** | 声明可以在编译期计算求值的常量或函数 | 满足常量求值条件时可提前计算；运行期参数调用仍可能在运行期执行 |
