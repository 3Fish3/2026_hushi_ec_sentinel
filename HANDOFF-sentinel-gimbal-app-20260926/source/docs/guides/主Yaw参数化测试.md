# 主 Yaw 参数化测试

固定入口：`robots/sentinel/host/sentinel_yaw_test.py`（相对 `source/`）。

该脚本用于已部署映射修复版固件的主 Yaw 有界位置试验。复用既有维护客户端、原始采集和 GUI 参数换算，不增加板端协议，不需要重新烧录。当前只支持主 Yaw，不用于 Pitch、底盘或发射机构。

默认仅打印试验计划，不打开串口、不启动 OpenOCD、不修改参数。指定 `--execute --safety-confirmed` 才连接硬件；该标记是操作者对本次现场条件的确认，不代表可以无人值守反复运行。

## 1. 前置条件

- Pitch 物理支撑稳妥，主 Yaw 在预期行程内没有碰撞风险，线束留足余量。
- 电机动力和反馈正常，人员及工具离开运动范围，物理断电急停随时可用。
- DT7 为左 `CL`、右顶部 `GPS`，允许维护模式。脚本拒绝接管已有控制权或执行目标。
- 关闭占用串口的维护 GUI 和其他采集程序；每条串口只允许一个拥有者。
- 使用交接包 `.venv/bin/python`；执行路径需要 `pyserial`，提示音使用 `paplay`。启用 `--swd` 时需要 OpenOCD 和 CMSIS-DAP（`c251:f001`）。
- 固件身份默认必须为 `app-gimbal-20261002-yawmap-fix`。后续部署新版本时，核验工件后显式传入 `--expected-build`，不盲目绕过身份检查。

维护接口是 C 板 UART2／USART1（921600 baud），原始采集和身份接口是 UART1／USART6（115200 baud）。USB-TTL 的 VCC 不连接 C 板电源。

## 2. 预览计划

先进入交接包根目录：

```bash
cd <PROJECT_ROOT>/HANDOFF-sentinel-gimbal-app-20260926
```

以下命令只预览正向 5°试验，不连接硬件：

```bash
.venv/bin/python source/robots/sentinel/host/sentinel_yaw_test.py \
  --direction positive --angle-deg 5 --ramp-rad-s 0.04 \
  --hold-s 0.4 --settle-s 0.6 --capture --swd
```

参数含义：以新读取的静止角为起点，先保持 0.4 s，再以目标角变化速度 0.04 rad/s 走到 +5°，最终目标保持 0.6 s。驱动阶段约 3.18 s，结束撤销目标，再只读观察 0.6 s。`--capture` 选择 UART1 原始短窗，`--swd` 选择不暂停 MCU 的 CAN 邮箱观察。

预览里的 `port: null` 仅表示尚未提供串口；实际执行必须提供两个串口路径。

## 3. 执行一次试验

以下命令会请求维护并驱动主 Yaw，必须先确认上述现场条件。本机串口使用稳定的 by-id 路径；更换适配器后先核验路径，不依赖易变化的 tty 编号。

```bash
.venv/bin/python source/robots/sentinel/host/sentinel_yaw_test.py \
  --port /dev/serial/by-id/usb-ARM_DAPLink_CMSIS-DAP_0700000100160043350000094e57354aa5a5a5a597969908-if01 \
  --observer-port /dev/serial/by-id/usb-1a86_USB_Serial-if00-port0 \
  --direction positive --angle-deg 5 --ramp-rad-s 0.04 \
  --hold-s 0.4 --settle-s 0.6 --capture --swd \
  --execute --safety-confirmed
```

不带 `--swd` 时不启动探针；不带 `--capture` 时不做原始短窗导出，但仍通过观测串口核验固件身份。

需要反向时，将 `--direction positive` 改为 `--direction negative`。每次运行重新读取起点，不继承上轮角度，也不直接指令绝对 0 rad。

## 4. 单变量 PID 对比

每轮最多改变一个参数。提供的速度环增益采用 GUI 的物理电流口径，脚本根据实际读回的电流上限换算成 MCU 原生值。

例如，在上一节执行命令中追加：

```text
--velocity-ki 0.8
```

若电流上限读回为 2.5 A，则写入 MCU 的 Ki 为 `0.8 / 2.5 = 0.32`。脚本记录原值、应用后读回，结束恢复原值并再次核验。也可单独选择：

- `--velocity-kp 0.08`：速度环 Kp，单位 A/(rad/s)。
- `--position-kp 7.5`：位置环 Kp，单位 1/s。

不传 PID 参数就只读、不修改增益。脚本不更改电流上限、输出上限、零位或参考系。

为防止继承此前误填的高增益，本工具拒绝：电流上限超过 2.5 A、GUI 速度 Kp 超过 0.12、GUI 速度 Ki 超过 2.0、位置 Kp 超过 15，或非零速度 D／位置 I／位置 D。单次候选增益还不能超过原值的两倍；原增益为零时，本工具不直接从零新增闭环增益。超出这些范围需要独立评审，不通过加大 CLI 数值绕过。

## 5. 可调参数与停止边界

| 参数 | 默认 | 允许范围／说明 |
|---|---:|---|
| `--direction` | positive | positive / negative |
| `--angle-deg` | 5 | 大于0、不超过10°；相对新读取的起点 |
| `--ramp-rad-s` | 0.04 | 大于0、不超过0.08 rad/s；目标变化速度 |
| `--hold-s` | 0.4 | 0.1..1 s，斜坡前保持 |
| `--settle-s` | 0.6 | 0.1..2 s，斜坡后保持 |
| `--post-s` | 0.6 | 0.1..2 s，撤销后观察 |
| `--sample-s` | 0.025 | 0.01..0.04 s，请求间的睡眠；实际采样周期还包含串口往返 |
| `--stop-speed` | 0.5 | 0.1..0.5 rad/s，只允许降低最大速度阈值 |
| `--margin-deg` | 1 | 0.1..1°，沿目标方向超过计划角度的允许余量；反方向超过1°停止 |
| `--capture-at-s` | 驱动结束前0.6 s | 相对原地保持开始的主机时间，短窗必须落在计划驱动时段内 |
| `--capture-ms` | 300 | 1..300 ms，缓存满可能提前冻结 |
| `--sound-file` | 系统 bell.oga | 提示音失败时不启动运动 |
| `--output` | source/.tmp/yaw-tests/下独立目录 | 用户指定时必须是尚不存在的新目录，拒绝覆盖 |

斜坡前保持、斜坡及斜坡后保持之和不超过 **5 s**。位置／速度反馈无效或超过20 ms、温度达到50°C、维护权限消失、配置／参考代次改变、非主 Yaw 执行、SWD 失败等情况均终止试验。

同步维护请求最多等待0.1 s，不自动重连或重试运动。请求超时不代表操作未执行，脚本仍尝试撤销和释放，并将结果未知记录为失败。

## 6. 输出与验收含义

每次执行创建一个新结果目录：

- `events.jsonl`：原参数、候选写入、恢复读回、目标、角度、速度、执行状态、设备 effort 和清理结果。
- `summary.json`：计划、起点、最终目标、位移、停止原因、参数恢复及维护释放状态。
- `control.ecraw`：启用 `--capture` 后保留的原始记录；必须配对主 Yaw 控制域4和 CAN1 `0x208`／流5。
- `swd.cfg`、`swd.log`：启用 `--swd` 后生成的固定只读配置和带主机时间戳的邮箱观察。
- `swd.go`、`swd.stop`：当次采样的启动／停止信号文件，不是重新编写的测试逻辑。

CLI 参数控制既有脚本；每轮仅生成结果数据和探针信号文件，不再临时改 Python 源码。

`completed=true` 只表示试验流程与清理完成，**不表示电机成功到达目标或 PID 调稳**。检查 `delta_deg`、角度序列、原始输出和采集内容后才能评价响应。

SWD 的邮箱 ID／载荷读取是非原子的，运行期间可能跨过邮箱更新。邮箱里看到非零 `0x1FE` 第四槽是本地外设提交证据，不等于主 Yaw 已接收，也不替代 CAN 线上抓包。待机的零值不能作为运动输出证据。

原始采集使用独立 UART1 线程，UART2 目标保活不被导出阻塞。导出设18 s全局边界（进行中的单次观测请求可能再耗约1.2 s）；目标先撤销、参数先恢复、维护先释放，再等待采集结束。由于串口/线程启动延迟，`--capture-at-s` 是主机触发计划，不是硬实时 MCU 触发。

撤销目标只去除主动驱动，不能保证立即刹停；线束张力、重力和惯性仍可能让机械运动。软件边界、清理 ACK 和控制超时不能替代物理急停。若报告出现 `cleanup_errors` 或未确认待机，操作者应立即使用物理急停，确认参数／权限状态后再决定后续操作。

不需要真实串口和探针：

```bash

```

实现完成时，22 项离线测试及所选6项采集／维护相关 CTest 通过。

2026-10-02 首次现场运行固定脚本：正向5°，斜坡0.04 rad/s，原地保持0.4 s、最终保持0.6 s，不修改PID，同时启用原始采集及只读SWD。提示音、流程清理与采集完成：目标撤销及维护释放ACK通过，最终待机、速度0，清理错误为空。结果目录为 `source/.tmp/yaw-tests/20261002-185356-4ce64ce4/`。
