# C 板接口与接线注意

**现场型号更正**: 用户随后确认采购标签为 USB2CANFD, 但实物丝印为 `USB2CAN / DM Tools / REV V3.0`. 应按实物 USB2CAN 核对工具与接口, 不将下文 USB2CANFD 手册的针序、终端默认值、SDK 或升级方法直接套用到这块实物. 当前没有达妙电机; 纯 CAN 通信测试不需要达妙电机参与.

接口外壳丝印、STM32 外设名、插座针序是不同的信息. **能插进去不代表线序正确; UART 要 TX→RX, CAN 则必须 H→H、L→L.** 本页维护接线事实与易混点, 当次测试结果仍记录在 [实施与验收](../../robots/sentinel/实施与验收.md).

## 1. 官方资料与适用范围

- RoboMaster Development Board Type C User Manual v1.0 (本地文件 `references/robomaster-type-c-user-manual-v1.0.pdf`, 不入版本控制), 2020.01, 用户提供的官方原件, 未改写内容. SHA256: `2f94ecd8558a065c90b56741047c2b5f3d363323e4973d27a0f526a9651603ef`.
  - 印刷页 10–11 / PDF 页 12–13: UART 电平、针序与外壳丝印映射.
  - 印刷页 11–12 / PDF 页 13–14: CAN 插座与针序.
  - 印刷页 13 / PDF 页 15: DBUS 反相电路与接针.
  - 印刷页 17–18 / PDF 页 19–20: MCU 引脚映射.
- 现场 USB2CAN 优先参考 [厂商 USB2CAN 专用仓库](https://gitee.com/kit-miao/usb-2-can), 本地 `references/usb-2-can/`, 固定于 `19255a02bd01fe17c58676a2862d15ce635d2ffc`. 厂商总目录 `.gitmodules` 将 USB2CAN 指向此仓库, 其中含 V3.0 外壳/模型、`通讯协议/USB 转CAN 帧格式.xlsx`、开源上位机与 `上位机/USB2CAN_2.0.0.3.exe`. 表格公开的是普通 USB2CAN 串口封装, 不能套用 USB2CANFD 的“协议不开放”结论. 已在现场 COM4 跑通普通 CAN 发帧, 实测范围见验收记录. 当前官方程序打开串口后不等待旧例程的握手回应; 不能把旧握手无返回视为模块不可用. 当前发送封装使用 CRC-8 (反射多项式 0x8c, 覆盖含零占位 CRC 的完整 30 B), 时间间隔单位为 0.1 ms, 不沿用旧说明中未经核实的假设.
- 官方 SDK 本地参考: `references/dm-device-sdk/` (通用 SDK, 源码入口 <https://gitee.com/kit-miao/dm-device-sdk>), `references/usb2canfd/` (原模块资料仓, 只稀疏检出根目录与 SDK, 源码入口 <https://github.com/dmBots/usb2canfd>). 两者是独立 Git 工作副本, 不作为固件依赖或自动构建输入, 不直接运行其中的电机控制示例. 旧版 SDK 对模块新固件有兼容限制, 使用前核对模块版本, 不为适配 SDK 自动升级固件.
- [达妙 USB 转 CANFD 模块使用说明书 V1.0](https://github.com/dmBots/usb2canfd/blob/main/达妙科技-USB转CANFD模块使用说明书V1.0.pdf), 2025.07.28, 第 3 页: 插座朝向、H/L 与终端开关; 第 6 页: CAN2.0 波特率配置.

已对照两份手册的实际接口图, 不只依赖 PDF 文本抽取顺序. 以下结论限于这些型号和图示版本, 不推广到所有大疆/达妙产品. 实物版本、卡扣方向或丝印不符时停止接线并重新核实.

## 2. 供电前提: SWD 连通不等于外设上电

- 用户现场确认: 本台架仅连接 SWD、没有外部供电时, DBUS 与 CAN 等部分外设不会上电. 能识别 MCU、烧录或读取 RAM, 不代表外部接口的电源轨已正常; SWD 本身也不是完整板卡供电方案.
- 进行 DBUS/CAN 验证前, 核实 C 板外部供电及相应外设电源. ST-Link 报告的目标参考电压不能证明 5V 外设供电存在, 也不能证明 CAN 收发器已经工作.
- 当前仅 C 板接电池与分电板, 低负载可能触发电池自动休眠. 测试中若目标失联、反馈突然消失或疑似休眠, **立即停止发帧/重试, 先请现场确认电池与电源状态**; 不盲目重刷、改波特率或将供电中断认作协议故障.
- 不擅自挂接电机或额外功率负载来阻止休眠, 不短接保护或改变电池设置. CAN 测试只针对用户确认接入的 C 板 CAN1 与 USB2CAN REV V3.0.

## 3. 串口丝印不是 STM32 外设编号

| C 板外壳 / 实体接口 | STM32 外设 | MCU 引脚 | 手册针序 | 当前观察固件 |
|---|---|---|---|---|
| 外壳 `UART1`, 3pin | **USART6** | TX=`PG14`, RX=`PG9` | 1=GND, 2=TXD, 3=RXD | 115200 8N1, 可选只读观测服务; **不是原样回显** |
| 外壳 `UART2`, 4pin | **USART1** | TX=`PA9`, RX=`PB7` | 1=RXD, 2=TXD, 3=GND, 4=5V | 115200 8N1 回显 |
| DBUS, PWM 排针第 8 组 | USART3 接收 | RX=`PC11`, 经板上反相电路 | A8=GND, B8=5V, C8=DBUS | DR16 接收, 不回显 |

针号按官方插座图定位, 不从线尾观察后直接套用左右顺序. DBUS 不是第三个可随意替代的普通 TTL 回显口.

### 电平与供电不要混为一谈

- 手册明确两路普通 UART 接口支持 **3.3 V / 5 V** 电平, 不能笼统写成“只支持 3.3 V”. 图中有 3.3 V 上拉, 也不能因此将板端 TX 宣称为固定输出 5 V.
- 仍须核实 USB-UART 模块的实际 TX 电平与 RX 门限; 有些模块的 3.3 V/5 V 跳帽只切换供电输出, 不切换信号电平. 不支持直接连接 RS232/RS485 电气信号, 这两类需要相应转换器.
- 3pin USART6 只有 GND/TX/RX, **没有 VCC 引脚**. 4pin USART1 的第 4 针是 5V, 不是 RX/TX. 不将 CH340 的 VCC 与已供电 C 板盲目并接.
- 普通 UART 的兼容说明不自动适用于所有 MCU GPIO, 也不取消 DBUS 的反相与接口要求.

### 台架端口与固件范围不一致, 不等于接线错误

用户确认 CH340 在 COM3, 正确连接 **3pin USART6 / 外壳 UART1**; 早期 `9519c7c-s1-hw-release` 固件仅初始化 USART1/USART3. 因而无回显、USART1 接收计数为 0 不能归为线缆、电平或 DMA 故障, 也不能反复要求把已经确认的 USART6 连接改成 USART1.

当前缺少适用的 4pin 转杜邦线, 用户决定 **USART1 与 CAN2 均暂不测试且不设阻塞**. 现已通过 CubeMX 加入 USART6, 使用有界 DMA 收发和只读观测协议; Python 入口见 [串口观测与应用接入](../../guides/串口观测与应用接入.md). 旧 `uart_probe.py` 的回显格式不适用于 USART6, 也不能把串口数据直接当电机命令. 历史未初始化记录不代表新镜像仍不可用, 实测范围见验收记录.

### DR16 先确认配对, 再判断解码

用户确认专用防呆线正确连接. 本台架曾出现 DT7 开机但 DR16 尚未配对 (接收器绿灯闪烁), USART3 的字节/IDLE/错误计数均为 0; 完成配对后绿灯常亮, 已实际收到有效遥控帧. 此实例说明“遥控器开机”和“接收器已建立链路”不能等同; 无字节时先核实配对与供电, 不直接改串口参数或断言线材错误. 指示灯描述是本台架的现场确认, 不推广到未知型号接收器.

## 4. USB2CANFD 手册与 C 板的 CAN 排列对比 (现场 V3.0 待核实)

以下相反排列结论只适用于已核对的 **USB2CANFD V1.0 手册**, 不证明现场 `USB2CAN REV V3.0` 的针序; 后者需按实物 H/L 丝印和对应资料确认. 用户已确认 CAN1 正确接线, 不据此要求再次换针.

**以手册所示设备插座口正视图、卡扣朝上为比较基准**:

| 接口 | 图示左侧 / Pin1 | 图示右侧 / Pin2 |
|---|---|---|
| C 板 CAN1, 2pin | CANL (Pin1) | CANH (Pin2) |
| 达妙 USB2CANFD, GH1.25 2P | H | L |

达妙图未给出针号, 上表第二行只表示该图的左右位置, 不擅自为其定义 Pin1/Pin2. 因而不能用“两头插头都能插入”推断普通两芯线可直接使用.

**正确的电气连接只有同名相连**:

- 达妙 **H → C 板 CAN1 Pin2 (CANH)**.
- 达妙 **L → C 板 CAN1 Pin1 (CANL)**.

这不是要求将 CANH 接到 CANL. 两端插座反排与线束是否已经交叉是两件事: 配套同面/异面线、转接线可能已经换序, 不能再凭颜色或外观盲目交换一次. 按插座 Pin1/丝印确定信号, 在线束两端都断开、相关设备断电时用万用表确认端到端导通, 再判断是否需要换针或专用转接线. 插头线尾视角与设备插座口视角会镜像, 不只记录“左接左”.

### CAN2 的 4pin 更不能当成 UART 4pin

C 板 CAN2 为 **Pin1=5V, Pin2=GND, Pin3=CANH, Pin4=CANL**. 与同板 USART1 的 4pin 定义也不同; 用达妙 2pin CAN 接入时, H 对 Pin3、L 对 Pin4, 不把 5V 接进 CAN 差分线. 参考地按双方接口与隔离设计核实, 不让信号地承担动力回流.

### 终端与软件模式

- 达妙模块内置 120 Ω 终端开关, 手册说明默认开启. 总线两端的终端应统一核对, 不因多接一个设备就再加一个终端. 在具备两只 120 Ω 并联且无其他影响的断电总线上, H/L 间约为 60 Ω, 不能将此简化判据替代线路检查.
- 与 STM32F407 / GM6020 联调使用 **CAN2.0、1 Mbps、标准数据帧**, 不启用 CAN FD/BRS. 适配器支持 CAN FD 不代表总线上其他设备也支持.
- 通用 CAN 页面与达妙电机专用调试页面不同; 不为观察 DJI 反馈而点击达妙电机使能、写参数或升级. USB2CAN 应按对应厂商串口封装/通用工具核对, USB2CANFD 则使用匹配工具/SDK; 二者均不能仅因出现 COM 口就当作 SLCAN.
- 观察固件不发送应用层控制帧, 但正常 CAN 模式仍可能自动 ACK. 本页只记录接线规则, 不代表 CAN 已实测通过或电机供电/运动已获授权.
