# 参数化全向轮运动学 (OmniDrive)

源码: [omni_kinematics.hpp](../../../include/ec/motion/omni_kinematics.hpp)、[omni_kinematics.cpp](../../../src/motion/omni_kinematics.cpp), 类型位于 `ec::motion`.
契约测试: `tests/input_imu_kinematics_tests.cpp` (正逆一致性、退化布局、量纲).

## 1. 解决什么问题

底盘收到的是机体坐标系下的平面运动 `PlanarTwist{vx, vy, wz}`, 轮子需要的是各自的轴侧角速度. 这一步换算与轮数、轮位、轮径、安装角和传动符号有关, 所以做成**参数化公式**: 135° 布局只是参数的一种取值, 不在公式里写死, 也不从轮数推断.

它**不负责**: 打滑建模、地面接触、功率分配、限幅, 以及轮位/安装角本身的测量. 几何参数来自机械资料与装机核对, 见 [Checklist C05](../../robots/sentinel/现有能力与待确认Checklist.md).

## 2. 单位与方向

| 量 | 单位 | 说明 |
|---|---|---|
| `PlanarTwist::vx_mps`、`vy_mps` | m/s | 机体坐标系线速度 |
| `PlanarTwist::wz_rad_s` | rad/s | 绕机体 +Z, 右手正 |
| `OmniWheel::x_m`、`y_m` | m | 轮心相对旋转中心的机体坐标 |
| `OmniWheel::roll_dir_rad` | rad | 轮子滚动方向在机体平面内的方向角, 绕 +Z 从 +X 起算 |
| `OmniWheel::radius_m` | m | 全向轮有效滚动半径 |
| `OmniWheel::gain` | `+1` / `-1` | 电机到该轮的方向与传动比符号 |
| 轮速输出 | rad/s | **轴侧**角速度, 与电机反馈同域; 不做减速比换算 |

正解是 `w_i = ((v + ω × r_i) · d_i) / radius_i × gain_i`; 逆解对 `w = J · twist` 做最小二乘 (`(JᵀJ)⁻¹Jᵀ`).

## 3. API

```text
omni_valid(drive)          // 半径、方向角、gain 等参数是否合法
omni_well_posed(drive)     // 三个自由度是否都能被独立观测 (布局非退化)
omni_wheel_speeds(drive, twist)      -> 各轮 rad/s, 参数非法时为空
omni_twist(drive, wheel_rad_s)       -> PlanarTwist, 布局退化时为空
omni_peak_wheel_speed(drive, twist)  -> 该 twist 需要的最大轮速绝对值, 供调用方自己缩放或限幅
```

`omni_twist` 是自检与回放工具: 同一组参数做正逆变换必须回到原值. 轮速互相矛盾 (物理上不可达的组合) 时它给出最小二乘意义下的最接近解, 不报错——调用方不能把逆解当成"实际车体速度测量".

## 4. 边界与常见错误

- 参数未配置或含非有限值时拒绝计算, 不返回"看起来合理"的零.
- 不做限幅: 是否缩放到轮速上限属于应用层决策, `omni_peak_wheel_speed()` 只提供所需信息.
- 不把电机原始 rpm 直接喂进来: 先用 [DJI 设备与分组执行](../drivers/DJI设备与分组执行.md) 换算到轴侧 rad/s.
- 轮位或半径写错时正逆变换仍然自洽, 但车体运动方向会错: 参数必须与机械资料核对, 不能只靠"跑起来看着对".
