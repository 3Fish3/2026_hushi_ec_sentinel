# 设备在线监视 (Device Watch)

源码: [device_watch.hpp](../../../include/ec/drivers/device_watch.hpp)，位于 `ec::drivers` 命名空间。对应契约测试: `tests/core_tests.cpp` 中的 `device_watch_contracts`。

## 1. 为什么必须按“总线编号 + CAN ID”双重索引？

在 RoboMaster 机器人上，我们通常会同时使用两条独立 CAN 总线（CAN1 和 CAN2）。
- 假设某机器人在 CAN1 和 CAN2 上各有一台反馈 ID 为 0x201 的电调；
- 它们属于不同总线，应作为两个节点记录。这里只举通用例子，当前哨兵实际映射以机器人 Checklist 为准。
如果设备监视器只记录 CAN ID，那么 CAN1 的 0x201 和 CAN2 的 0x201 就会在表中产生严重的冲突并相互覆盖！

**`DeviceWatch<Capacity>` 的双键索引防线**：
`DeviceWatch` 使用 **`(bus_id, can_id)`** 作为联合唯一键：
- 只有总线编号（`bus >= 1`）与标准 CAN 标识符（`id <= 0x7FF`）完全吻合，才会被视作同一个设备节点；
- 记录每个节点最近一次被总线成功观测到的单调时间戳 `last_seen`；
- 在纯静态、固定容量的连续内存中维护状态，实时路径**零动态内存分配**。

## 2. 职责纯粹性与安全认知

- **不负责协议内容合法性**：本组件只证明“在指定的 CAN 总线上刚刚收到了标有该 ID 的电信号报文”，**绝不等于该电机型号正确、帧内数据未被破坏、更不等于允许电机运动**！
- **单任务归属（无内部锁）**：为了实现极速更新，`DeviceWatch` 内部未设计加锁操作。在架构设计中，推荐由 CAN 帧消费任务独占更新与查询，或者在访问时由调用方施加外部互斥保护。

## 3. 主机可运行示例

下面的代码演示了设备节点的登记、心跳超时判定与在线设备数量遍历统计：

```cpp
#include "ec/drivers/device_watch.hpp"
#include <cstddef>
#include <iostream>

// 主机可运行示例: 演示 CAN 总线设备在线状态的打点、时效查询与槽位遍历
int main() {
    // 1. 创建固定容量为 16 个设备的在线监视器 (栈上分配，零堆开销)
    ec::drivers::DeviceWatch<16> devices;

    // 2. 模拟从 CAN2 总线接收到了 0x201 (1号电调) 报文，记录观测时间为 100 ms
    //    note(总线编号, 标准CAN_ID, 当前时间戳)
    if (!devices.note(2, 0x201, ec::Tick{100})) {
        return 1; // 登记打点失败
    }

    // 3. 在 105 ms 时刻查询设备是否在线 (设定离线超时 TTL 为 20 ms)
    //    时间差 = 105 - 100 = 5 ms < 20 ms，判定在线！
    if (!devices.online(2, 0x201, ec::Tick{105}, ec::Lifetime{20})) {
        return 2; // 应在线，若判定离线则异常
    }

    // 4. 模拟查询一个从未出现过的设备 (CAN1 上的 0x201)
    //    由于总线编号不同，监视器能精准区分并返回 false！
    if (devices.online(1, 0x201, ec::Tick{105}, ec::Lifetime{20})) {
        return 3; // 判定错误: CAN1 并无此设备
    }

    // 5. 遍历内部所有有效槽位，统计当前依然在线的活跃设备总数
    std::size_t active_count = 0;
    for (const auto& slot : devices.slots()) {
        // slot.used 标明该槽位已绑定设备; ec::fresh() 验证最后一次心跳是否在 TTL 内
        if (slot.used && ec::fresh(ec::Tick{105}, slot.last_seen, ec::Lifetime{20})) {
            ++active_count;
        }
    }

    if (active_count == 1) {
        return 0; // 契约验证通过！
    }

    return 4;
}
```

## 4. API 契约与容量淘汰策略

- **`note(bus, id, now)`**：
  - 更新或新插入一个设备条目。若 `bus == 0`、`id > 0x7FF` 或容量已满无空闲槽位，返回 `false`。
  - **静态容量防线**：若配置的容量满了（例如配置为 16 却有第 17 种不同 ID 涌入），新设备会被拒绝写入，同时用内部普通整数计数器记录丢弃事件（通过 `dropped_ids()` 读取），绝不会覆盖已有槽位。
- **`online(bus, id, now, ttl)`**：
  - 根据 [时间与时效](../core/时间与时效.md) 规则，判断该设备最近一次出现的时刻与 `now` 之间的流逝时间是否在 `ttl` 毫秒以内。
- **`get(bus, id)`**：
  - 返回设备记录结构体的副本（`std::optional<WatchedDevice>`），包含 `bus`、`id`、`last_seen`、`frames` 和 `used`。
- **`slots()`**：
  - 返回内部槽位数组的只读引用（`const std::array<WatchedDevice, Capacity>&`），用于遍历所有已注册设备。不能将该引用跨锁传递给其他并发线程。

容量支持 1–64 个节点，设备离线不会自动释放槽位。包括计数读取和 `slots()` 遍历在内的全部访问都须遵守单任务或外部同步约定；返回只读引用不等于获得一致性快照。
