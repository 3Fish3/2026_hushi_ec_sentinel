# 项目规范

- 新增或修改的手写代码注释使用简体中文; 技术符号、标识符、单位与协议名称保持原文.
- 第三方代码、厂商版权声明及自动生成代码不为统一注释语言而改写.
- 仓库根目录 `.venv/` 是可修改的项目级开发与测试环境. 代理可按当前任务需要自行添加、调整其中的依赖, 无需逐项确认; 同步维护 `requirements-dev.txt`, 不将虚拟环境文件纳入 Git. 此授权不包含全局安装、修改系统环境或关闭安全防护.
- 上位机、自动化测试辅助与后续复用工具优先采用 Python; 需要原生或桌面程序时可使用 MSVC/C#. 固件及核心 C++ 行为仍需相应的原生验证, 不用 Python 模型替代.
- 人工测试例程保持最小功能: 参数配置、目标下发、基本状态与参数回传. 未明确需要时不增加向导、验收打卡、多层确认或其他辅助流程.
- 禁止冗余软件兜底与防御性编程: 不为假设风险堆叠重复校验、额外限制、门禁或复杂恢复机制. 按已确认的实际需求与接口契约实现, 不把实车级流程强加给已有可靠物理急停的单电机台架; 不据此擅自删除已确认、已验收的行为.
- 控制参数优先参考并换算旧仓库中已实测可用的有效配置, 核对输入/输出单位、控制周期、反馈源、滤波和负载差异; 不照搬注释中的废弃参数或不同量纲的数值. 无适用依据时明确标为待调参数, 不以任意保守值冒充实测基线. 旧仓库仍仅作参数与能力参考, 不继承其实现或接口.
