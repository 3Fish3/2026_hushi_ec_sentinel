# 哨兵现有能力与待确认 Checklist

## 1. 用途与证据口径

本清单集中维护首个哨兵落地所需的现有能力、硬件/控制行为证据与待确认事项. 架构决策仍以 [架构设计](../../架构设计.md) 为准; 上位机协作字段的详细需求引用本地资料 `references/电控接口需求与联调建议.md` (不入版本控制), 不在此复制另一套协议字段表. 应用阶段首轮范围、冻结依赖与只读采集设计见 [应用首轮与契约冻结](应用首轮与契约冻结.md); 外部规划保持只读, 被采纳的硬件/行为结论在本清单原条目更新.

**用户已确认: 当前参考工作树就是正常运行版本, 整车整体运行没有严重问题; 已实际执行所有现有遥控器操作及上位机自动控制发弹, 新框架使用同一套硬件.** 启动、停止、遥控切换、失联和掉电无不良机械后果也是已确认的运行经验, 具体边界见 A07/A12. 这些是有效的已有运行证据. 本清单不把机器人当作从未运行的系统, 也不要求为了证明已有正常能力重新执行整套实车试验. 应优先复用操作经验、已知配置、已有记录和可运行固件基线.

证据标签:

- **[运行经验]**: 用户/实际操作者确认的运行事实; 不自动扩展为每种模式、全部故障或具体性能的验证结果.
- **[代码]**: 当前参考工作树中有效语句、调用路径或参数. 不只依据注释、枚举、未调用函数或被注释分支判断能力.
- **[资料]**: 已有接口说明、CAD 引用或照片等. 保留来源边界, 文件名不等于实际装机型号.
- **[推导]**: 根据代码计算出的结果, 明确换算前提, 不等于实测量.
- **[待确认]**: 有针对性的缺口或版本差异, 不是已复现故障.

`[x]` 表示该条限定范围内的资料/结论已收集, **不表示该机构已通过新框架验收**. `[ ]` 表示需要补充证据或作出设计决定. 本清单不授权烧录、运动、关节扫动或发弹; 新增实机测试另行授权.

路径缩写: 下文 `app/`、`modules/`、`bsp/`、`Src/` 均相对 `references/Sentinel/`. 读取基线的 HEAD 为 `94dc426ec49662fdf040df31d7a8b57c1f725785`, 工作树有大量已修改和未跟踪文件; 该 HEAD 不是本次读取内容的完整快照.

## 4. 机构正常控制行为

### 4.1 底盘

- [x] **C01 [代码]** 四轮均为 MCU 速度闭环, 使用电机反馈; 应用调用 `OmniCalculate()` 而非被注释的麦轮解算. 有停止、无跟随、小陀螺、跟随云台、左右转动、变速旋转等分支. 来源: `app/chassis/chassis.hpp::ChassisTask/OmniCalculate`.
- [x] **C02 [代码]** 先将 `cmd.vx/vy` 固定旋转 135°, 再进行四轮混合. 小陀螺内部旋转量为 80, 跟随分支为 `0.002 × offset_angle × abs(offset_angle)`. 这些数值是旧内部量, 不能直接标为 rad/s.
- [x] **C03 [代码]** `app/app_def.hpp` 定义轴距/轮距 400/400、轮半径 60、云台偏移 0/0, 注释单位 mm. 当前全向轮混合公式没有使用轮半径, 因此不能仅凭这些宏将旧 `vx/vy` 确认为 m/s 或 mm/s.
- [x] **C04 [代码]** 遥控输入 `channel2/3 × 6` 进入 `vx/vy`; `CHASSIS_STOP` 对四轮调用 `disable()`. 来源: `RobotCMD::rcControlSet`, `ChassisTask`.
- [ ] **C05 / 电控与机械** 确认轮径、轮位、轮子滚动方向、轮心坐标、传动比及 135° 变换的物理来源; 有现成可信参数直接复用, 不需为了填表重新测量.
- [ ] **C06 / 电控与上位机 [行为/操纵映射已冻结, 配置与实现待闭合]** 2026-09-18 用户选择标准 `base_link` 下 `vx/vy/wz` (m/s、m/s、rad/s) + 本地基本遥控: 主动接管、停车、平移/旋转输入. 首版不纳入 MCU 本地跟随云台模式, Jetson 可显式生成对应目标; 不照搬旧 135° 变换和小陀螺常量. 正常到位/普通非旋转模式下摇杆回中采用持续零速度闭环, 不因速度归零而自动退出输出; 首版不增加独立 `StopMotion`. 自动到位减速由 Jetson 的速度目标表达, 零 twist 仍须保持新鲜, 不因零目标无限续期; 零速度闭环不承担地图位置保持, 位置修正归 Jetson. 撤权/失联/急停/故障不等同于正常零目标. 合法 twist 解算超过配置轮速上限时四轮目标同比例缩放, 回报采用 twist 和缩放状态; 保留平移/旋转比例, 不独立夹各轮目标.

  **本地操纵:** 首版不实现键鼠业务映射, 使用 DT7 摇杆/拨轮覆盖整车遥控调试. 已选左拨杆上=本地、中=待机/释放正常来源并允许维护申请、下=Jetson; 右拨杆下=人工整车停止、中=普通运行、上=本地底盘旋转操作. 本地主 yaw 使用 MCU 局部惯性参考, 不要求 Jetson odom 对齐, 不冒称 odom; 惯性反馈失效沿用 G07 降级.

  **ch4 三层 Shift:** 正负侧及阈值待核对. 左杆前后/左右始终给底盘 vx/vy, 普通运行档 wz=0, 其余映射如下:

  | ch4 层 | 右X | 右Y |
  |---|---|---|
  | 中位: 主云台 | 主 yaw 方向目标增量 | pitch 角度目标增量 |
  | 一侧: fire yaw | fire yaw 相对角目标增量 | pitch 角度目标增量 |
  | 另一侧: 发射机构 | 摩擦轮开关 | 正向连续拨弹 / 中位取消 / 人工反转 |

  **来源边界:** 已有遥控运行经验继续保留, 不把比赛策略迁回 MCU. 本地遥控不依赖 Jetson 在线; 遥控与 Jetson 通过拨杆显式选择来源, 切换作废旧来源目标, 摇杆回中不自动交还控制权. Jetson 已取得控制且会话/目标有效时, 遥控失联不撤销该自主执行; 原由遥控控制时失联停止本地执行, 不自动转给 Jetson. 遥控失联不解除已生效的人工停止态.

### 9.2 DJI 协议结论

- [x] **R01 [官方协议+代码]** GM6020 的电压控制和电流控制使用不同标识符与指令量纲. 电流模式要求固件 `v1.0.11.2` 或以上, 并通过 RoboMaster Assistant `v2.7` 或以上启用电流环开关. 发送电流模式 ID 不等于自动改变电调保存的模式. 当前工作树使用 `0x1FE/0x2FE`, 与已有正常运行经验共同支持保留此电流控制路径; 具体装机版本号/开关截图仍归 H06, 不因新框架重构要求已验证的旧装机电机升级. **新增用户约定**: 本次新购 GM6020 先通过 RmAssistant 更新支持电流环的固件并启用该开关, 后续开发默认使用内置电流环 (`gm6020_current`), 不自动退回电压模式. 当前只有这一颗电机可供单测; 用户已确认其固件升级完成、电流环启用、ID1 (`0x205`) 且接入 CAN1. 真实反馈已读到, 见实施与验收 S5; 尚未直接读取该电机固件版本或开关回执, 不凭相同反馈 ID 推断控制模式.

| 设备/控制模式 | 控制 ID 分组 | 原始指令范围 | 官方控制量含义 | 反馈 ID |
|---|---|---|---|---|
| GM6020 电压 | `0x1FF` (ID1–4), `0x2FF` (ID5–7) | ±25000 | 电压控制编码, 不直接写成 ±25000 V | `0x204+ID` |
| GM6020 电流 | `0x1FE` (ID1–4), `0x2FE` (ID5–7) | ±16384 | 对应 ±3 A 转矩电流指令 | `0x204+ID` |

这些是指令满量程, 不是整车安全电流、长期允许负载或电机额定电流; 也不能未经官方反馈定义直接复用为全部反馈电流的比例. GM6020 英文版 0x2FE 表的电机编号列与中文分组存在不一致, 此处按中文表的 ID5–7 及现有驱动分组记录, 不照搬抽取表格的错列.

- [x] **R02 [官方协议+代码]** CAN 下的 C620/C610 给电流, GM6020 当前模式也给电流; 旧应用中的角度/速度环由 MCU 完成, 不因厂商支持 PWM 位置/速度模式就称当前 CAN 链路使用原生位置/速度指令. C610 反馈 DATA[6]/DATA[7] 为 Null, 不能把旧通用 DJI 解码读取的 DATA[6] 作为有效 M2006 温度反馈. 新版应按设备区分字段有效性.
- [x] **R03 [官方比例推导]** 当前限幅在正确模式下可解释为: yaw1 的原始 3000 约对应 0.5493 A 指令, C620 的 6000 约对应 7.3242 A 指令, C610 的 8000 对应 8 A 指令. 只是旧输出限幅的量纲核对, 不代表实测电流或重新建议安全阈值. M2006 官方产品页确认标准 P36 减速比 36:1; 是否存在额外传动仍归 S06/C05.

### 9.3 达妙协议结论

- [x] **R04 [官方协议+代码]** 两份 J4310 手册均给出 MIT 的 16 位位置和 12 位速度/Kp/Kd/力矩编码; Kp 物理范围 [0,500], Kd [0,5]. 按满量程 4095 换算, 旧函数直接打包的 Kp 编码 35 对应 `35/4095×500 ≈ 4.2735`, Kd 编码 0 对应 0. 因而重构若把旧字面值 35 当成物理 Kp 再编码, 将显著改变控制行为. 应显式区分物理参数与原始编码, 不静默改变已有增益.
- [x] **R05 [官方协议+代码]** MIT 控制 ID 为配置 CAN_ID; 位置速度模式为 `0x100+CAN_ID` (两个小端 float, rad 与 rad/s); 速度模式为 `0x200+CAN_ID` (小端 float, rad/s). 反馈用独立配置的 Master_ID, 默认 0. 当前 TX=1、RX=0 与 MIT/默认反馈地址契约相符, 不构成收发 ID 必须相等或 RX=0 必然非法的问题. `ONLY_ANGLE` 是旧 MCU 自定义控制分支, 不是达妙另一种线上协议; 当前仍发 MIT 帧.
- [x] **R06 [官方协议]** PMAX/VMAX/TMAX 是可配置的映射范围, 不是型号名称能唯一决定的硬件极限或额定能力. 当前 12.5/30/10 是已运行源码参数, 但手册不能证明电调实际保存值. 较新手册可通过参数读命令与寄存器 0x15/0x16/0x17 查询映射量程, 另有模式 0x0A、超时 0x09、固件 0x0E 等; 仅记录能力, 未授权/执行读写操作, 老固件兼容性待 H06. 双编码器与 10:1 减速比在已查 J4310-2EC 资料中有依据, 但实物完整后缀/版本及额外机械传动未确认, 不重复对已经表示输出侧的角度盲目乘除 10.
- [x] **R07 [官方指引与运行经验并存]** 早期与新版达妙手册均提醒 MIT 位置控制不应将 Kd 设为 0, 而现有已运行路径的 Kd 编码确为 0. 保留这项差异, 既不据此否定已有正常运行经验, 也不把该值不加分析推广为通用默认. 后续控制链改变或调参时纳入针对性验证, 本轮不修改旧代码、电调参数或要求升级.
- [ ] **R08 / 电控** 结合 H06 的实物/已有参数资料确定适用手册版本与字段支持; 新旧手册都支持的基本 MIT 契约可先设计, 新增模式、运行时读参、自动使能/故障恢复能力不因最新版文档存在就默认纳入首版. 对 MIT 编解码与原始/物理参数边界做离线对照测试, 不以实际发运动指令验证协议格式.

- [x] **R09 [官方手册核对, 2026-09-18]** 已读取用户指定的 `DM_J4310_2EC_V1.1_Manual_V1.2_EN_20260908.pdf`, SHA256 `7107b810f2573a82712556030d8e74eec8162cc4835aa19ffcac8c43a223d886`. 第 13 页确认状态反馈为问询式, 收帧 ID 低 8 位匹配、高 3 位忽略; 该段不保证任意匹配载荷无控制副作用. 第 17 页独立定义参数读: STD `0x7FF`, 四字节 `CANID_L CANID_H 0x33 RID`; Master_ID 上返回八字节 `CANID_L CANID_H 0x33 RID Data[4]`, Data 为小端 float/uint32. 第 20–21 页给出寄存器表, `0x50 p_m` 为转子推导的输出轴角、`0x51 xout` 为输出轴编码器角, 均为只读 float/rad. 另核对达妙官方 `motor-control-routine@ae6c1031056908d3d8059f003bd015a9d6b21894` 的 `read_motor_data` 与 `read_motor_ctrl_fbdata`, 分别确认 DLC=4 的参数读及 `CANID_L CANID_H CC 00` 状态查询. 首轮已实现这两种限定读取, 不发送 enable/disable/MIT/置零/参数写入; 无响应不自动回退控制帧. 装机版本支持仍归 H06/R08, 手册未明确参数读取是否刷新通信超时, 不用此工具验证失联停机时延. 使用及边界见 [只读采集与人工标定](../../guides/哨兵只读采集与人工标定.md).
