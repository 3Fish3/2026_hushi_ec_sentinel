# DJI 电机协议编解码

源码: [dji.hpp](../../../include/ec/drivers/dji.hpp)、[dji.cpp](../../../src/drivers/dji.cpp)，函数位于 `ec::drivers` 命名空间。对应契约测试: `tests/core_tests.cpp` 中的 `dji_contracts`。

## 1. 为什么需要独立的编解码模块？

大疆 RoboMaster 官方电机（如 M3508 配 C620 电调、M2006 配 C610 电调、GM6020 云台电机）是通过 CAN 总线与主控板通信的。
- 电机发回给单片机的是 8 字节的原始 CAN 报文，里面挤压着高低字节拼接的转速、机械角度、电流与温度。
- 控制器需要的是具备物理意义的标准国际单位（如角速度 `rad/s`、机械角 `rad`）。
- 反过来，控制器计算出的控制量也必须按照大疆官方协议打包为对应的 CAN 报文。

**模块设计边界**：
本模块是**纯粹的协议编解码器**。它不持有硬件 CAN 句柄、不主动调用总线发送函数、不累计多圈角度、不换算机械减速比，也不替你决定超温或堵转时的保护动作。

需要轴侧换算、显式位置参考或同组发送时, 使用上层的 [DJI 设备与分组执行](DJI设备与分组执行.md), 不把这些职责塞回字节编解码函数。

## 2. 报文分组与控制标识符契约

大疆电调为了节省 CAN 总线带宽，设计了**“4 个电机合并在同一帧 CAN 报文下发”**的协议格式：

| 模式枚举 (`DjiMode`) | 电调与电机型号 | 控制报文 组 1 (ID 1~4) | 控制报文 组 2 (ID 5~8) | 电机反馈报文标识符 (ID 1~8) |
|---|---|---|---|---|
| **`c620_current`** | M3508 电机 + C620 电调 | `0x200` | `0x1FF` | `0x201 ~ 0x208` |
| **`c610_current`** | M2006 电机 + C610 电调 | `0x200` | `0x1FF` | `0x201 ~ 0x208` |
| **`gm6020_current`** | GM6020 电流控制模式 | `0x1FE` | `0x2FE` (仅 ID 5~7) | `0x205 ~ 0x20B` |
| **`gm6020_voltage`** | GM6020 电压控制模式 | `0x1FF` | `0x2FF` (仅 ID 5~7) | `0x205 ~ 0x20B` |

> **关键规则警示**：
> 1. **严禁各电机独立发送！必须由总线拥有者统一合并槽位**：
>    如果 1 号电机发送 `{1000, 0, 0, 0}` 到 `0x200`，紧接着 2 号电机也发送 `{0, -500, 0, 0}` 到 `0x200`，后发的一帧会直接把 1 号电机的控制量清零覆盖！必须在应用层将 1~4 号电机的控制量组装到一个 4 元素数组中，统一调用一次 `encode_dji()` 生成完整帧后再发送。
> 2. **GM6020 组 2 约束**：GM6020 组 2 仅支持 ID 5~7，第 4 个槽位（对应 ID 8）必须为 0。

## 3. 主机可运行示例

下面的代码演示了下发控制量的编码，以及底层反馈报文的解码与物理单位还原：

```cpp
#include "ec/drivers/dji.hpp"
#include <iostream>

// 主机可运行示例: 演示 DJI 电机协议的控制指令编码与反馈报文解码
int main() {
    // 1. 控制量编码 (encode_dji):
    //    参数说明:
    //    - DjiMode::c620_current: 选用 C620 电流控制协议
    //    - group = 1: 控制第 1 组电机 (对应 CAN 报文 ID 为 0x200，包含 ID 1~4)
    //    - 控制槽位: {ID1=1000, ID2=-500, ID3=0, ID4=0} (电调原始协议电流数值)
    const auto tx_frame = ec::drivers::encode_dji(
        ec::drivers::DjiMode::c620_current,
        1,
        {1000, -500, 0, 0}
    );

    // 检查编码是否成功 (非法 group 或槽位超限会返回 std::nullopt)
    if (!tx_frame) {
        return 1;
    }

    // 验证编码结果: 组 1 的 C620 报文 ID 必须是 0x200，长度必须是 8 字节
    if (tx_frame->id != 0x200 || tx_frame->size != 8) {
        return 2;
    }

    // 2. 模拟从 CAN 总线接收到一帧 1 号电机的真实反馈报文:
    //    0x201 对应 1 号电调反馈，载荷 8 字节 (此处用空数据帧做测试)
    const ec::transport::CanFrame rx_frame{0x201, 8, {}};

    // 3. 反馈解码 (decode_dji):
    const auto feedback = ec::drivers::decode_dji(
        ec::drivers::DjiMode::c620_current,
        rx_frame
    );

    if (!feedback) {
        return 3; // 解码失败
    }

    // 4. 验证解码得到的物理量:
    //    - feedback->device_id: 自动根据 0x201 识别出是 1 号电机
    //    - feedback->rotor_angle_rad: 转子单圈机械角 (0 ~ 2π)
    //    - feedback->rotor_speed_rad_s: 已转换为国际标准单位 rad/s 的转子角速度
    //    - feedback->effort_raw: 原始转矩/电流读数
    if (feedback->device_id == 1 && feedback->effort_raw == 0) {
        return 0; // 编解码契约验证全部通过！
    }

    return 4;
}
```

## 4. 解码字段与物理单位换算

- **`rotor_angle_rad`**：转子单圈机械角度，范围严格落在 `[0, 2π)` 弧度内。电机编码器原始刻度为 8192（13 位分辨率），解析器已自动完成浮点弧度换算。
- **`rotor_speed_rad_s`**：转子实际旋转角速度，已由原始 RPM 换算为国际标准单位 `rad/s`（换算公式：$\text{rad/s} = \text{RPM} \times \frac{2\pi}{60}$）。**注意：这是电机转子本身的转速，尚未乘以外部机械减速比！**
- **`temperature_c`**：电机温度（摄氏度 `°C`）。对于 C610 电调，协议中该字节为保留位，返回无温度（`std::nullopt`）。

## 5. 常见调用失误与排查

1. **凭感觉猜测反馈 ID 属于哪种电机**：
   - C620 与 C610 的反馈报文 ID 范围完全一致（均为 `0x201 ~ 0x208`）。系统必须根据明确的底盘/云台接线拓扑配置 `DjiMode`，不能靠“碰运气”看哪个函数解析成功来判断。
2. **直接拿反馈角度当云台关节角度**：
   - 电机反馈的是转子单圈绝对角度，断电重新上电后无法得知跨越了多少圈，且转子与输出轴之间通常有减速比（如 3508 自带 19:1 减速箱）。必须在应用层结合零位校准与圈数累加器使用。
