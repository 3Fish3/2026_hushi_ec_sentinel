# 哨兵只读采集与人工标定

`sentinel_capture` 用于装机映射、原始编码器/位置与时序取证, **不是运动 APP, 也不是停车工具**. 只读表示不驱动、不改设置, 不表示 CAN 完全静默. 范围与尚待冻结项见 [应用首轮与契约冻结](../robots/sentinel/应用首轮与契约冻结.md), 实际验收见 [实施与验收](../robots/sentinel/实施与验收.md).

## 1. 能读什么

- 九 DJI 候选槽: 四轮、两 yaw、两摩擦轮、拨弹. 显示原始单圈 encoder、转子 rad/RPM、effort_raw、适用型号的温度. C610 温度始终无值.
- DM CAN1 / CAN_ID=1 / Master_ID=0: 普通状态的 p16/v12/t12、状态与温度; `p_m` (0x50) 和 `xout` (0x51) 的 float/rad 位置; 量程/模式/版本等白名单寄存器.
- DR16 通道、拨杆、键鼠; BMI088 原始 acc/gyro/temp, 加热关闭.
- 逐候选 ID 的接收计数、间隔 min/max/sum/count、数据年龄, 以及 FIFO overrun、软件队列丢弃/高水位、服务耗时和串口诊断. 未映射帧保留总数和最后 bus/ID, 不冒充全 ID 分析仪.

**不要求外设齐全.** 空电机总线、只有一颗 GM6020、未接 DR16/DM 都不会阻塞其它页; IMU 初始化失败也只记录自身错误. 候选接线表位于 `robots/sentinel/capture/capture.hpp`. 型号不靠 ID 自动推断, 不使用猜测的传动比/输出限值构造运动设备. 原始单圈值不等于关节标定: `joint_rad` 和 `cumulative_rotor_rad` 保持 null. 低频 PC 快照不能保证跨圈解包, 请用机械标记和有限小幅人工转动采集.

### DM 查询依据及边界

本地资料 `DM_J4310_2EC_V1.1_Manual_V1.2_EN_20260908.pdf`, SHA256 `7107b810f2573a82712556030d8e74eec8162cc4835aa19ffcac8c43a223d886`, 第 13、17、20–21 页. 参数读取格式和 DLC 另与达妙官方 [dm_motor_drv.c](https://github.com/dmBots/motor-control-routine/blob/ae6c1031056908d3d8059f003bd015a9d6b21894/stm32%E4%BE%8B%E7%A8%8B/dm_ctrl(f4)%20v1.1%20%E8%A3%B8%E6%9C%BA/User/dm_motor_drv.c) 的 `read_motor_data` 交叉核对; 同文件 `read_motor_ctrl_fbdata` 定义固定状态查询. 未下载/执行厂商控制示例.

固件唯一 CAN TX 是 CAN1 上的 STD `0x7FF`, DLC=4:

| 用途 | 数据 |
|---|---|
| 参数读取 | `01 00 33 RID` |
| 普通状态读取 | `01 00 CC 00` |

RID 白名单: `07 08 09 0A 0E 14 15 16 17 24 50 51`. 包括 Master/命令 ID、TIMEOUT、CTRL_MODE、版本、Gr、PMAX/VMAX/TMAX 和两种位置. 写参数、保存、使能、失能、清错、置零和 MIT/其它运动帧均不提供; PC 不可修改 ID、RID 或透传 CAN.

- 默认顺序轮询 `p_m → xout → 状态 → 一个配置寄存器`, 两次发送尝试间隔至少 50 ms, 同时最多一个待答请求, 100 ms 未答即计超时并前进. 正常响应时位置/状态各约 5 Hz, 每个配置约 2 s 更新一次. 这不是高频控制反馈链.
- 参数响应按 Master ID、节点、0x33、RID 分流, 不误解为普通 MIT 状态. 收到 NaN/Inf 保留原始 bits, 物理值标无效.
- 手册未定义读取是否刷新通信超时计数; 本工具不用于验证电调失联停机时间. 设备寄存器没有请求序号/硬件采样时刻, 请求关联与 MCU 接收时间不是严格的电调采样时间或独立 ACK.
- 装机固件是否支持这组读取尚待实测. 无响应显示缺失/陈旧, 不能单凭它认定设备离线或型号错误, 不自动改协议、升级、使能或改参数.

## 2. 构建与角色检查

先按 [板级生成与构建](../boards/sentinel_f407/生成与构建.md) 设置本机 `$arm` 和 `$sdk`. 使用独立目录, 不覆盖 S1/S5 缓存:

```powershell
$ErrorActionPreference = 'Stop'
cmake -S . -B build/capture-arm-Release -G Ninja `
  '-DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake' `
  "-DARM_GNU_ROOT=$arm" "-DEC_STM32CUBE_F4_ROOT=$sdk" `
  -DEC_BUILD_SENTINEL_CAPTURE=ON -DEC_S5_GM6020_BENCH=OFF `
  -DCMAKE_BUILD_TYPE=Release -DEC_FIRMWARE_ID=read-v2-partial-release
if ($LASTEXITCODE -ne 0) { throw '采集配置失败' }
cmake --build build/capture-arm-Release --target sentinel_capture
if ($LASTEXITCODE -ne 0) { throw '采集构建/检查失败' }
```

产物为 `build/capture-arm-Release/boards/sentinel_f407/sentinel_capture.{elf,bin,hex,map}`. 构建自动运行 `check_capture.py`, 核对专用身份、向量、读取入口, 排除已列明的运动/PWM/S5/通用 CAN TX 门面等符号. **不是对所有可能硬件副作用的形式化证明**. 参数/状态查询白名单另有原生行为测试. 默认 `sentinel_s1` 的零 CAN TX 检查保持原样, 不拿 `--allow-gm6020-bench` 检查本镜像.

采集角色与 S5 同开时 CMake 拒绝配置. 本镜像不调用 APP 控制/提交钩子, 不装配正式运动设备. 默认 S1 不链接采集实现.

## 3. 打开面板与记录

烧录、上电接线和人工转动按单独授权执行. 操作前应无其它控制器/厂商程序驱动机构, 设备处于已停止状态, 按实际负载支撑 pitch. **本 APP 不会发送 disable 帮忙停车.** CAN 保持正常模式并 ACK; 接收与反馈需要相应外部供电.

PC 沿用 CH340 → C 板 USART6 (外壳 UART1), 115200/8N1, 不并接 VCC. 接线详见 [接口与接线注意](../boards/sentinel_f407/接口与接线注意.md). 不扫描端口、不抢占其它程序持有的串口.

```powershell
New-Item -ItemType Directory -Force build/capture-logs | Out-Null
./.venv/Scripts/python.exe boards/sentinel_f407/tools/sentinel_capture.py `
  --port COM3 --log build/capture-logs/run-001.jsonl `
  --elf build/capture-arm-Release/boards/sentinel_f407/sentinel_capture.elf `
  --hardware '本次机械与接线版本'
```

使用既有 `requirements-dev.txt` 的 pyserial 和 Python 自带 tkinter, 无新增依赖. ELF 哈希来自指定文件, 不是在线读取 Flash 后的固件匹配证明; 面板先核对独立采集协议身份.

- 表中点选一行优先读取对应页, 可切回“全车轮询”或“遥控/IMU 优先”. `--hz` 为总请求速率 1–15 Hz (默认 10), 不是每电机帧率. 全车十页默认约 1 s 更新一遍.
- 电机值来自独立 MCU 样本; 保留最后一次值和不断增长的年龄, 不把旧值刷成新采样. `ONLINE` / `LOST` 由 MCU 快照中的样本年龄判定; PC 低频轮询导致的页面老化显示 `ONLINE / SNAPSHOT_OLD`, 不误报电机失联. 历史值不能当作当前有效反馈.
- 从未收到反馈显示 `NO_FEEDBACK`, 收到过而超时显示 `LOST`, 内容非法显示 `INVALID`; DM 参数从未回复显示 `NO_REPLY`, 不猜它是没接还是不支持. IMU 未能初始化显示 `INIT_FAILED`. 个别项缺失不停止其它项读取.
- 底部 DR16/IMU 分两行等宽显示, 最多每秒刷新5次, gyro 保留4位小数; `snapshot` 状态来自 MCU, `age` 单独表示数据年龄, 不用 SNAPSHOT_OLD 后缀反复撑开文本. 不改变串口轮询、日志精度或 MCU 时效判定.
- DM 状态行与 p_m/xout 行是不同查询的样本. 两者不能当作严格同时采样, PMAX 也不能用于反复缩放已经为输出轴 rad 的 p_m/xout.
- 放到机械标记后保持姿态, 输入“机械标记”和“独立量角/单位/备注”, 点击“记录标记”. 工具等待对应页新回复后写日志; 标签含请求时刻、返回时刻、页面序号、原始样本和 `valid_at_mark`. 不写 MCU/电调零位. 未选行时默认记录第一电机页, 标定其它轴应先选中对应行.
- 暂停/恢复记录仅控制 PC 文件写入, 不停止 MCU 查询. 不记录期间的物理变化不会凭空补齐, 恢复事件会留在文件中. 文件用新建模式, 拒绝覆盖.
- 单次请求 500 ms 未答即报告 MCU 链路 `NO_RESPONSE` (尚未连通) 或 `LOST` (此前连通过), 保留最后数据并继续在同一个已打开串口发只读查询; 恢复回复后报告 `ONLINE`, JSONL 保存状态迁移. 不自动重新打开串口或复位设备. 串口句柄错误或协议不匹配仍停止并显示具体原因.
- `capture protocol mismatch` 会列出实际/预期 schema 与长度. 必须使用同一版 Python 和 `sentinel_capture.bin`; 早期 schema=1 的 184 B 汇总页不是当前镜像, 不能通过缺设备解释或猜布局兼容. 不要误烧同目录的 `sentinel_s1.bin`.
- 观察到 MCU 毫秒时钟倒退时清页面缓存并记录新分段; 当前没有硬件随机 boot ID, 不能声称识别了所有短复位或短断电.

无界面限定记录与离线导出:

```powershell
./.venv/Scripts/python.exe boards/sentinel_f407/tools/sentinel_capture.py `
  --port COM3 --headless --seconds 30 --log build/capture-logs/run-002.jsonl
./.venv/Scripts/python.exe boards/sentinel_f407/tools/sentinel_capture.py `
  --export build/capture-logs/run-002.jsonl --csv build/capture-logs/run-002.csv
```

JSONL 是原始记录主入口, 包含 schema、机械标签、可选 ELF 哈希、PC 时刻、MCU 时刻、页面和采集质量; CSV 为电机/寄存器、人工标签和链路状态迁移的派生表, 不代替 JSONL 中的诊断与完整标记快照. 未标定/缺失写 null, 不写假健康零值. 采纳的数值/来源/适用版本回填 Checklist, 原始日志不默认提交, 清理 build 前保留有用证据.

## 4. 时序、资源与协议口径

- 采集角色先完成含等待的 IMU 初始化, 再启用 CAN 接收, 避免快任务尚未启动时就堆积电机反馈. 接收 ISR 打点并投递容量 128 的有界队列. 独立任务每 1 ms 最多处理 128 帧并执行查询调度; 优先级高于原 10 ms 串口任务, 独占有界 IMU 采样 (每个 SPI 事务截止 100 µs), 不做格式化或文件 I/O. 默认 S1 的队列/周期不变.
- `received_ms` 是 MCU 接收时刻. `cycles` 是 ISR 读取 DWT CYCCNT, 仅相邻间隔 <1 s 才纳入间隔统计, 用模 2^32 差处理一次回绕. 周期时钟 168 MHz, 不能拿它当无限时长或跨机时钟; >=1 s 的空窗不纳入 sum/min/max, 应结合计数/年龄/日志识别断流.
- 统计 min/max/mean 来自 MCU 全部接收事件, 与 PC 请求频率分离. `mean_us = sum_cycles / intervals / 168`, intervals=0 时无均值. 实际到达率不等于电调配置发送率, 无运动 TX 的负载不代表正式整车负载.
- FIFO overrun 是硬件错误事件数, 不是丢失帧精确数量. 软件队列 overflow、未知映射、非法协议分开计数; 累计量不清零, 本轮取首末差. 上电初始化阶段亦可能有接收损失, 不为美化结果清掉它.
- BMI088 在 1 ms 快任务独立读取 gyro FIFO / accel DRDY / 低频温度. gyro FIFO 最多读 4 帧并选择最新帧, 其余帧显式计入降采样; 时间估计误差与 overrun 独立记录. 没有宣称硬同步或精确 DRDY 时刻. 运行时队列峰值、栈余量/耗时仍需实机验证.
- USART6 复用 `UartFrame` CRC/转义: 请求 `0x30`, 载荷 1 B 页号; 响应 `0xB0`. 应用 schema=3, 页头 `u8 schema/page/count/reserved + u32 now_ms`, 全部小端. 页 0 为身份/诊断 (192 B); 页 1–5 各两个电机 (112 B); 页 6 为遥控/IMU (101 B, 含 ch4); 页 7–9 各四个参数 (88 B). 页不是原子整车快照. 具体字段顺序以 `capture.cpp`、`board_capture.cpp` 和 Python 解码器为准, 主机测试有独立字节对照.
- 快照回复间隔至少 50 ms, 单周期只保留最后请求, UART 忙时计丢弃而不积压旧回复. 任意其它消息不会取得电机执行权限.

软件结果只覆盖限定接收/查询/日志路径, 不包含动力稳定性、机械范围、软限位、零位标定正确性或实际无运动验收.

## 5. 高频原始短窗与离线标定

入口为 `robots/sentinel/host/sentinel_raw.py`, 与已有面板互斥占有同一 USART6. 现有面板和 JSONL 继续负责人工标记/部分设备观测; 动态标定必须用新增 `.sraw` 原始文件, 不用 UI 刷新率或 PC 收包时间拟合. `sentinel_capture` 和正式 `sentinel_app` 均有相同的轻量记录器; capture 不链接控制器/执行器发送路径.

### 5.1 有限采集, 冻结后再导出

- 固定 512×64 B 记录存储, 满或达到请求时长即冻结, 不覆盖旧记录. `state=full` 表示实际窗口被容量截短, 不能用请求时长假定采到了完整工况. 不同短窗之间是空白, 不能连成连续轨迹.
- `stationary`: gyro 最多 1000 Hz, accel 200 Hz, 温度随独立新样本. `rotation`: gyro 500 Hz, accel 100 Hz, main/fire/pitch 原始 CAN 各最多 500 Hz. 这些是软件选流上限, 真实数量/间隔看源序号. 默认 200 ms 窗口可容纳该组合; 无需提高现有 UART 波特率.
- rotation 活跃窗口中, DM 暂停慢速参数轮询, 仅每 2 ms 尝试一次既有白名单 `0x7FF/DLC4/01 00 CC 00` 状态查询. 不等待旧响应、不叠加 MIT/enable/disable; 窗口结束后恢复原查询方式. 500 Hz 查询获得真实新反馈的能力仍须实测.
- `control`: 正式 APP 上选择一颗 DJI 域 (0..5, 7..9), 记录请求/采用值、关节角/速度、归一化电流输出、真实 dt、量程触及和发送结果. pitch 原生 MIT 不用此 DJI 电流轨迹布局; 其原始状态由 rotation 记录. 轨迹只观察既有 APP 执行, 不在此入口下发目标. `state_bits` 的 bit25..26/27..28 分别是请求/采用参考系 (0=joint, 1=local_inertial, 2=odom); Python/CSV 解码为 `requested_frame/adopted_frame`. 关节反馈仍是机械角/速度, 不因惯性目标标签改变测量坐标.
- 序号/微秒时间是源采集信息; CAN 为接收时间, 误差未知用 null. gyro 的 FIFO 时刻为估计, accel 为读取时刻及 ODR 误差界. 同一旧温度/accel 不被 gyro 续期. 断包、接收队列丢帧及 FIFO 覆盖可见; 正常显式选流不冒充丢包.
- 输出仍走 115200/8N1 的限速观测服务: 每页 3 条, 载荷 224 B, 最坏转义 466 B (约 40.5 ms), PC 间隔至少 65 ms. 一窗 512 条约 11 s 导出, 此间不采新窗. 不承诺连续全量 1 kHz.

授权实物采集后才执行下例; `COMx` 不自动扫描:

```powershell
.venv/Scripts/python.exe robots/sentinel/host/sentinel_raw.py capture --port COMx --profile rotation --duration-ms 200 --metadata build/capture-metadata.json --output build/fire-train-01.sraw
.venv/Scripts/python.exe robots/sentinel/host/sentinel_raw.py export build/fire-train-01.sraw --output build/fire-train-01.csv
```

元数据 JSON 保留 `firmware` (建议 ELF SHA256)、`configuration` (配置身份)、机械标记/视频入口、`moving_axis` (`main/fire/pitch`)、`parent_fixed_confirmed`、`stationary_confirmed`. 软件另从观测端读取实际 `device_identity.build_id/uptime_ms`, 记录 IMU 设置/单位/时基/短窗身份. build_id 不是二进制哈希; 未提供的物理身份保持 null. 同 run 的开始/读取重传不清窗口, 不更改任何执行目标.

### 5.2 拟合输入与可辨识性

入口 `robots/sentinel/host/sentinel_calibrate.py manifest.json --output calibration.json`. 安装 `requirements-dev.txt` 到项目 `.venv/`, 不全局安装. manifest 使用下列字段 (数值必须由适用配置/试验给出, 不抄占位数字):

| 字段 | 含义 |
|---|---|
| `stationary` | 静止 `.sraw` 文件名列表, 日志须有静止确认标签; 多个温度阶段独立保存 |
| `quality_limits` | `stationary_std_rad_s`, `scale_tolerance`, `min_rate_std_rad_s`, `axis_rms_rad_s`, `holdout_rms_rad_s`, `fixed_rate_rad_s`, `fixed_position_rad`; 是本次拟合判据, 不是预设本车精度 |
| `reference_joint_rad` | `main/fire/pitch` 的可重复标定姿态, 不擅设开机即零 |
| `joints` | 三轴各自 `origin`, `rotor_per_axis`, `direction`, `zero_offset_rad`; DJI 另需 `max_rotor_speed_rad_s` 防多圈误解, 以及下述首帧机械参考; pitch 另需已读回的 `node`, `pmax_rad`, `vmax_rad_s` |
| `axes` | 按 pitch→fire→main 分别给 `train`, `holdout` 文件列表、`lag_bound_s`, `lag_step_s`, `fixed_relative_angles_rad` (`fire/pitch`); 训练下游处于参考姿态, 留出可取不同固定姿态 |
| `forward_V` | 实际主平台前方向, 未确认用 null; 不从相机/板边猜 |

DJI 每个短窗必须独立确定首帧机械分支, `unwrap` 不能恢复它. 在 `joints.main.reference` / `joints.fire.reference` 给出带来源的合法机械区间, 结构为 `{"origin":"measured","min_rad":...,"max_rad":...}` (数值单位 rad). 来源只接受 `measured/user_confirmed/reference_converted/synthetic`, 最后一类仅用于离线夹具. 范围必须来自当前零偏与传动约定, 不是转子原始角范围.

也可在该 `.sraw` 的用户元数据中提供 `joint_reference.main` / `joint_reference.fire`, 结构相同, 表示**该窗首个关节样本**的已知姿态区间, 应包含人工定位和编码量化误差. 两处都提供时取交集, 窗口锚点不能越过已知机械范围. 按 `direction * rotor_angle / rotor_per_axis - zero_offset_rad + k * 2π/rotor_per_axis` 枚举等价分支; 缺参考、多解或无解均拒绝, 不强制首帧归零、不猜圈数. 选中首分支后再延续窗内展开. `reference_joint_rad` 仍是拟合姿态, **不是各窗口的首帧锚点**.

标定与原生回放共用这条换算; 旧 manifest/候选若没有首帧参考, 必须补充真实依据或对应窗口元数据后使用. 原始记录格式不变, 不因补参考改写原始 CAN 字节.

先静止三轴均值/方差/分窗均值/温度范围, 再由原始 gyro 与已换算编码角局部差分拟合带符号轴向. 原生速度字段单独拟合时移, 不沿用位置延迟. 正 lag 的定义固定为 `gyro(t) = axis * encoder_rate(t - lag) + bias`. 恒速可辨方向但不能独自辨时间偏移; 时移超边界、单位/比例不符、非被测轴串动或缺少单轴标签均拒绝. 平行 yaw 依赖真实分轴标签, 不让优化器猜运动归属.

V 在参考姿态定义为 S0; 非零下游姿态先经 `Exp(a_f*q_f) Exp(a_p*q_p)` 换回同一坐标比较. 留出日志不得参与拟合, 保存各来源残差和 SHA256. 输出始终为 `offline_candidate`, `deployment_ready=false`, 不自动写电调或 MCU 配置. 温漂模型、完整 accel 内参/杆臂保持 null; 可选六位置测试只针对易拆小组件, 不翻整车. 单轴留出通过也不代表组合工况、长期漂移或实车闭环已通过.

### 5.3 同一路径原生回放

构建 `ec_sentinel_replay` 后, 可将 `.sraw` 和标定候选送进真正的 `SentinelPerception` (不是 Python 姿态模型):

```powershell
.venv/Scripts/python.exe robots/sentinel/host/sentinel_replay.py calibration.json held.sraw --native build/sentinel-app-host/Release/ec_sentinel_replay.exe --output build/replayed.csv --min-projection-squared 0.01 --min-heading-gain 0.02 --accel-norm-error-mps2 0.8
```

命令中的三个质量阈值只是合成回放示例, 不作为本车已测参数. 前方向为 null 时明确拒绝生成 heading.
回放将 CAN 由 N2 量纲转换器还原为关节样本, 按 MCU 到达时刻合并独立 gyro/acc/关节流; 不把未来样本提前使用.
原生使用同样的短历史、独立时移、安装/静态偏置、EKF 传播/新 accel 校正、指数积串联重构与连续 heading.
CSV 报告有效性、源年龄及局部代次; 记录不足不能仅因程序正常退出称为有效重构.
原生用例另以独立 double 正向矩阵/数值微分检验 float 反解, 并覆盖真实原始采样输入链的非单位安装、动态比力、下游组合运动和回绕.

离线互操作入口: `ec_capture_tests --raw-golden` 输出原生字节, Python 保存 `.sraw`, `ec_capture_tests --raw-replay <file>` 走同一原生解码. `sentinel_raw_calibration_contracts` 含独立合成轴/零偏/时移及错单位、平行轴标签混淆、父级串动负例.
