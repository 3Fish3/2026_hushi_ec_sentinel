# 串口观测与应用接入

这条链路解决一个具体问题: 不停住 MCU, 在电脑上看遥控器、IMU 和通信状态. 它是 **S1–S4 台架只读工具**, 不是整车控制协议, 不提供电机使能、模式切换或目标写入.

## 1. 先用起来

### 接口与固件

- CH340 接 C 板 **外壳 UART1 的 3pin / 内部 USART6**: TX PG14、RX PG9, PC 与板端 TX/RX 交叉并共地. 具体针号看 [接口与接线注意](../boards/sentinel_f407/接口与接线注意.md).
- 115200、8N1、无流控. 不并接 CH340 VCC. DR16 和 CAN 还需要正确外部供电; SWD 能读 MCU 不等于这些外设有电.
- 固件需包含 USART6 观察服务. 按 [板级生成与构建](../boards/sentinel_f407/生成与构建.md) 构建, `EC_S1_UART6_MONITOR=ON` (默认). 旧版 USART1 字节回显镜像不会理解此协议.
- 该开关关闭时不启动 USART6 观测 DMA/响应服务; CubeMX 仍初始化 USART6 引脚与外设. 它不是后续整机监控开关的完整实现.

### 项目级 Python 环境

在仓库根目录使用 PowerShell 7. 环境安装与工具前置见 [环境部署](../getting-started/环境部署.md). 无需全局安装 Python 包, 也无需激活脚本或修改执行策略:

```powershell
python -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
./.venv/Scripts/python.exe boards/sentinel_f407/tools/board_monitor.py --port COM3
```

已存在可用 `.venv` 时跳过创建. `.venv/` 是可修改的开发/测试环境, 增加依赖时同步清单, 环境本身不入 Git. 上位机不依赖原生测试 EXE 或达妙 SDK.

记录 30 秒, 同时保留逐帧 JSONL:

```powershell
New-Item -ItemType Directory -Force build | Out-Null
./.venv/Scripts/python.exe boards/sentinel_f407/tools/board_monitor.py `
  --port COM3 --seconds 30 --hz 10 --log build/monitor-run.jsonl
```

日志拒绝覆盖已有文件. `host_bad_frames` 记录 PC 接收端拒帧数, 与 MCU 上报的 `bad_frames` 分开解释. `--headless` 改为逐行 JSON 输出, 便于自动核对. 默认 5 Hz, 可选 1–10 Hz; `Ctrl+C` 退出并关闭端口. 端口被其他工具占用时先关闭那个工具, 不抢占或强杀它.

### 面板怎么看

- `LIVE` 表示最近收到匹配请求序号的合法响应, 不等于所有设备在线.
- DR16 显示四个原始通道整数、左右拨杆枚举、帧计数、数据年龄. 原始轴值范围 `-660..660`, 需要归一化时用 `dr16_axis()`, 不直接当成 `[-1,1]`.
- IMU 显示 `m/s²`、`rad/s`、温度及加热标志; 初次验收仍不启用加热. 这些不是融合姿态或校准结果.
- CAN 显示接收/丢弃/忽略计数及最后 ID. 最后 ID 是历史记录, 不是“该电机当前有效反馈”; 当前 `rx_dropped` 还包含设备表拒绝, 不全是物理丢帧.
- 传输超过 0.5 s 无新响应, 面板隐藏旧测量值并标记 `STALE`. DR16/IMU 还分别根据 MCU 时间戳与有效标志判断新鲜度. JSONL 保存原始历史值以及 `valid`, 使用日志时同样不能忽略有效性.
- 连续三次响应超时或串口异常即退出, 不自动重连或无限发请求. 先确认供电/固件再重开; 面板不能防止电池休眠.
- 退出码 0 只表示结束时链路仍有新鲜响应, 不代表 S1–S4 全部通过, 也不代表获得执行授权.

## 2. 一条请求如何穿过框架

```text
PC encode_frame(0x01, sequence)
  → USART6 环形 DMA
  → UartDmaPort.read(): 有界字节块 + generation
  → UartFrameDecoder.push(): 完整校验后的消息
  → board_monitor: 只接受空载荷快照请求, 限频
  → 复制一致的只读观测字段, 编码响应
  → UartDmaPort.try_send(): 自有缓冲 DMA TX
  → PC 校验序号/CRC, 解码并标记时效
```

这比原来的“收多少字节就回显多少字节”多了 **分帧、消息分发和应用数据编码**. 串口一次 `read()` 不是一个包; 发送返回 `accepted` 也只是 DMA 已启动, 不是 PC 已收到.

源码入口:

| 职责 | 文件 |
|---|---|
| 通用帧编码、增量解码 | [uart_frame.hpp](../../include/ec/transport/uart_frame.hpp) |
| STM32 有界 DMA 字节端口 | [uart_dma.hpp](../../platform/stm32f407/include/ec/platform/uart_dma.hpp) |
| 当前应用分发与快照采集 | [board_monitor.cpp](../../boards/sentinel_f407/src/board_monitor.cpp) |
| 板级观测载荷字段 | [board_monitor_protocol.hpp](../../boards/sentinel_f407/include/board_monitor_protocol.hpp) |
| Python 编解码、面板与日志 | [board_monitor.py](../../boards/sentinel_f407/tools/board_monitor.py) |

### 分帧 v1

线上形式为 `7E + 转义后的原始帧 + 7E`. 原始帧包含:

| 字段 | 编码 |
|---|---|
| 版本 | u8, 当前 1 |
| 消息类型 | u8; `0x01` 请求, `0x81` 响应 |
| 请求序号 | u16 小端, 响应原样带回, 回绕允许; 不是身份认证或跨重启会话号 |
| 载荷长度 | u16 小端, 最大 256 B |
| 载荷 | 请求为空; 观测响应固定 250 B |
| CRC | CRC-16/CCITT-FALSE, 多项式 0x1021、初值 0xFFFF、非反射、无最终 XOR; 覆盖版本至载荷, CRC 本身按小端附加 |

原始帧中的 `7E`、`7D` 编为 `7D` 后跟原值 XOR `20`. CRC 在转义前计算, 首尾界符不参与 CRC. 超长、坏 CRC、未知帧版本被丢弃, 下一个界符可重新建立边界. 不依赖 UART IDLE 判断协议包完整性.

观测载荷依次为: 10 个 u32 板状态字段、32 B 固件标签、DR16、IMU、CAN、4 个 UART3 错误计数、14 个 USART6/协议诊断字段. 全部小端, 浮点为 IEEE-754 binary32, 不传输结构体填充或指针; 标签最多 32 B, 不能替代 ELF 哈希. 精确字段顺序以上表中的 C++ 编码器与 Python 解码器为准, [跨语言测试](../../tests/board_monitor_tests.py) 核对同一向量. 修改布局应同步版本/兼容判定与测试, 不默默让新旧面板互相误解.

### 执行和并发约束

- USART6 由一个任务端口对象独占; UART6 与 RX/TX DMA ISR 同一抢占优先级. IRQ 只公布 RX 游标、释放完成的 TX 缓冲或标记恢复, 不解析应用消息.
- RX 512 B; S1–S4 每个 10 ms 任务周期最多处理 512 B (S5 专用任务为 1 ms), 分 64 B 短临界区复制. DMA 覆盖或重启使 `generation` 改变, 消费者据此清理半帧.
- CPU 屏蔽中断不会停止 DMA, 仍必须及时复制且不能漏掉整圈 HT/TC. 封装不是无限吞吐或无条件无损的保证.
- TX 单帧自有缓冲, 忙时整段拒绝, 不积压旧回复. 错误时在任务中终止 UART/DMA 再重启, 不在 ISR 里等待. 恢复会丢弃未完成帧, PC 靠 CRC/序号和下一次请求恢复.
- 每周期仅保留最后一个请求, 回复间隔至少 50 ms (最多 20 Hz, 为 PC 的 1–10 Hz 留出调度余量). 超出预算的请求计入丢弃, 不能把这个策略照搬到离散动作命令.
- 采样字段复制在短临界区内, CRC 与 HAL 发送在外. 各传感器保留自己的采样时间, 一致复制不等于传感器同时采样. 周期/栈开销仍须按实际任务负载验证.

## 3. 运行中监控: 分页记录与 SWD 只读读取

### 分页记录 (0x02 / 0x82)

除了上面的固定快照, USART6 还可以请求 **分页记录**: 请求载荷是 2 字节小端起始序号, 响应载荷是
一页记录 (`ec::monitor` 的显式小端编码, 最多 8 条, 每条 24 字节). 记录表达
"谁、何时采到什么、是否有效、为什么被拒", 不设计万能字段字典:

- `kind`: `device` / `axis` / `source` / `period` / `environment`;
- `validity`: `unknown` / `valid` / `stale` / `invalid` / `unavailable` — **未实现的传感来源是 `unknown`,
  未安装的设备是 `unavailable`, 都不填健康零值**;
- `mode` 与 `enabled` 是两个独立字段, 不合并成单一状态枚举;
- `sampled_at` 是这条记录自己的采样时刻, `published_at` 是写入发布区的时刻;
- 每条记录都带自己的采样时间, 所以**分页不是原子全车快照**; 判断撕裂看头部的发布代次 (`generation`).

这条入口与 SWD 读的是同一张表, 因此串口与调试器给出同一逻辑状态. 关闭 `EC_MONITOR_REGISTRY`
后既没有每周期发布开销, 也没有分页响应 (请求只计丢弃).

```powershell
./.venv/Scripts/python.exe boards/sentinel_f407/tools/monitor_swd.py `
  --elf build/framework-arm-Release-s5-OFF/boards/sentinel_f407/sentinel_s1.elf `
  --ocd-host 127.0.0.1 --ocd-port 4444 --json
```

### SWD 只读读取的运行中 RAM

`boards/sentinel_f407/tools/monitor_swd.py` 直接读运行中 RAM, **不停核、不写、不设目标**:

- 用 ELF 符号 `g_ec_monitor_desc` 定位 40 字节固定描述符, 并校验
  `magic` / `layout` / `record_size` / `capacity`, 再比对描述符里的构建标识字符串与 ELF 自身的
  `g_ec_s1_build_id`, 防止读到的描述符不属于当前固件;
- 读记录表前后各读一次发布代次: 一致才采信, 不一致则有限重试后标 `consistent: false`, 不通过停核"补救";
- 传输层只允许发出 `read_memory`; 出现 `halt`/`resume`/`write_memory` 立即视为错误;
- 连接中断、描述符版本不符、构建标识不符都直接报错退出, 不重试到死.

已在本机核对的 OpenOCD 契约 (xPack OpenOCD 0.12.0+dev):

- 内存命令名按 OpenOCD 官方参数顺序 `read_memory <address> <width> <count>` (width 取 8/16/32/64, count 是元素个数); 本工具固定 width=8, 因此 count 就是字节数; 单次上限 64K 个元素, 地址+数量不得回绕;
- `tcl port` 必须在 `init` 之前配置; 本机离线会话里 tcl 端口接受连接但不返回数据,
  因此首版 transport 使用已实测可用的 **telnet 端口** (默认 4444) 行协议;
- **真机 SWD 连机效果尚未验证**: 离线自检只用假内存与假服务端
  (`--self-test`, 覆盖只读命令白名单、撕裂检测、版本/构建不符、断流), 不能代替实机验证.

## 4. 改成机器人应用时, 改哪里

新增机器人控制消息时, 应在 **应用分发层** 定义目标语义、单位、设备映射、有效期与拒绝条件. 连续目标进入 Mailbox, 离散动作进入有界事件队列, 再由本地仲裁、授权、限位与保护决定是否执行. 不能让串口回调直接操作电机, 也不能把 CRC 或 `remote.online` 当作授权.

新设备/模式的完整接入应覆盖: 参数与轴侧单位 → 驱动反馈 → 控制与安全契约 → 应用消息 → 状态反馈 → 台架测试. 默认只读分支刻意没有这些写命令; 未知命令仅计数并忽略. 独立启用的 [S5 GM6020 台架](GM6020单电机测试.md) 已提供三种模式的配置与状态回传, 但不代表整车组装已经完成. 正式整车协议仍见 Checklist I05/I06, 不能因已有观测帧就视为冻结.

## 5. 有限无运动回归工具

仅在授权台架上使用:

```powershell
./.venv/Scripts/python.exe boards/sentinel_f407/tools/monitor_probe.py --port COM3
# 下列选项额外产生有限请求突发和一次 30 ms Break, 会故意触发串口错误恢复
./.venv/Scripts/python.exe boards/sentinel_f407/tools/monitor_probe.py `
  --port COM3 --burst-requests 200 --break-line
```

检查 CRC/超长帧拒绝、未知命令忽略、分段请求、限频和错误后恢复. 不自动扫描端口, 任一必要检查失败即停, 不自动复位/重试. 不能对未确认用途的串口运行, 也不能替代接线和供电检查.

## 6. 串口与 SWD 的后续边界

本文对应 USART6 板级只读观察入口; S5 控制面板另见上面的单电机指南. 整机可启用监控、串口/SWD 可选后端的需求统一记录在 [Checklist I11](../robots/sentinel/现有能力与待确认Checklist.md). 现有 `g_ec_io`/`g_ec_s1` 的停核读取不是运行中一致快照; 记录表用发布代次给出"可读/可能撕裂"的明确信号, 仍然不靠每次暂停 MCU 来冒充无侵入实时监控. 任务/周期/容量与带宽预算见 [资源与并发预算](../boards/sentinel_f407/资源与并发预算.md).
