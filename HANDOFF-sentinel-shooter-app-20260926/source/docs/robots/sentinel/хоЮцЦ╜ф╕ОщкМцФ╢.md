# 板级实施与人工验收

## 1. 用途与边界

本文是后续板级开发顺序、人工操作与阶段验收记录的单一入口. 架构契约见 [架构设计](../../架构设计.md), 硬件事实和待决策参数见 [Checklist](现有能力与待确认Checklist.md), 构建与生成命令见 [板级构建](../../boards/sentinel_f407/生成与构建.md), 正式 APP 的协议与操作端接口见 [正式APP接入说明](正式APP接入说明.md), 配置项与缺项见 [应用配置与换算基线](应用配置与换算基线.md), 任务/CAN/内存预算见 [资源与并发预算](../../boards/sentinel_f407/资源与并发预算.md). 不在这里重新定义机械参数或上位机协议.

正式 APP 的**离线验收结论、交付物清单与配置回填影响**集中在本页末节 [哨兵正式 APP 离线验收与移交](#哨兵正式-app-离线验收与移交-o0o8); 该节只汇总结论与入口, 实现与协议细节仍在各自文档.

当前已有核心库、主机测试和覆盖 S1–S4 的非运动板级固件. **提供 ELF/HEX/BIN, 不是整车控制固件; 已开展首次烧录与基础观察, 尚未完成 S1–S4 验收**, 实测范围见 §2.2. S1–S4 的具体入口见下文; 已增加独立启用的 S5 GM6020 单电机台架, 人工结果见 S5 小节, S6 仍为后续操作规程. 文档不代表后续硬件操作自动获授权. 实机验收从 S1 起按依赖进行, 不用离线结果抵扣实机步骤.

原则:

- 按依赖逐组件接入. S1–S4 连续完成实现与必要离线检查, 不逐阶段等待人工验收; S4 软件交付完成后统一安排 S1–S4 实机验收, 再推进需要这些实机证据的运动验收. 软件完成不等于实机通过.
- 实机测试不替代协议边界、过期、授权和数值计算的离线测试; 编译与主机测试也不替代中断、DMA、总线时序和真实输出的验证.
- 旧系统正常运行与已有安全经验继续采纳, 不重复要求证明旧固件. 本文验证的是新实现及其与旧行为的必要差异.
- 每阶段的最小测试入口与正式机器人任务分开选择, 尽量复用正式驱动/通道代码, 不另写一套无法代表正式实现的测试驱动.
- S1–S4 的后续软件开发可基于前置离线检查推进, 未验证的板上行为仍明确标为待验收. 集中实机验收按依赖顺序执行, 前置失败时停止依赖该结果的后续硬件步骤; 无关组件的有效证据保留. 阶段通过不授权额外运动或发弹.
- MCU、执行器供电、运动和发弹授权分别明确; 烧录不默认授权使能电机. 未知安全参数保持未配置, 不用演示值上机.

## 2. 开发路线与停点

| 阶段 | 软件交付 | 人工停点 | 依赖 |
|---|---|---|---|
| S1 板级基础 | 正式板级生成工程、启动/链接、时钟、RTOS、基础日志与复位诊断 | 可烧录、可复位、能持续观察周期任务, 不请求执行器输出 | 当前核心 |
| S2 UART | 单端口收发、DMA 缓冲所有权、分段交付、错误/溢出诊断及测试端工具 | 回环/对端传输与异常恢复通过 | S1; 日志端口与被测端口分离 |
| S3 CAN 与反馈 | CAN 收发、过滤/分发、时间戳、设备在线状态, 对应电机反馈解码 | 逐个确认设备 ID、反馈和离线行为, 不下发运动请求 | S1, 对应协议离线测试 |
| S4 遥控与 MCU IMU | 遥控解码/离线判据、板载 BMI088 采样/时间/姿态有效性, IMU 温控受限接入 | 只观察输入与状态, 不由遥控直接驱动机构 | S1; 遥控依赖 S2 |
| S5 单电机与单机构 | 对应电机控制编码、限幅、明确使能/撤销路径、反馈闭环与试验超时 | 一次一个电机/机构, 逐步验证方向、量纲、停止及恢复 | S3; 采用的控制反馈须先验证 |
| S6 整车与上位机 | 正式任务组装、统一仲裁、机构保护、新协议与状态回传 | 先无输出联调, 再分机构运动, 最后明确授权的整车/发射验收 | 相关 S2–S5 与行为/协议决策 |

S2/S3 可按实际设备可用性调整先后; S4 两项也可分别验收. S5 不要求等待无关机构完成, 例如不能因双 yaw 稳向反馈缺口阻止底盘单轮验证.

**已有部分台架资产, 实机验证已从 S1 开始**, 当前证据与剩余步骤见 §2.2. 离线开发与实机验收分别推进, 不因一次烧录成功而将 S1–S4 整体标为通过, 也不同时接通所有组件. S5 单电机运动验收仍需对应反馈等前置实机证据及独立授权.

主 yaw 稳向、双轴协同和新传感器方案仍受 Checklist G07 约束; 不能用相对编码器控制通过冒充惯性稳向通过.

### 2.1 无硬件阶段的软件在环验证 (SIL)

SIL 是主机可执行程序, 不依赖 Renode/QEMU、真实串口、CAN 适配器或 MCU. 使用手动推进的虚拟毫秒时钟, 不依赖 Windows 线程睡眠来模拟控制周期. `ec_sil_tests` 由普通主机测试构建生成, 不加入板级固件.

**复用的正式代码**:

- `VelocityLoop`: 组合 `ExecutionGate`、PID、命令/反馈时效与输入检查, 提供同轴 rad/s 目标/反馈到归一化执行量的计算; 无动态分配, 无 HAL/RTOS 依赖. 授权或计算失效时撤销代次并清除 PID 状态, 返回无输出, 不替机构选择停止动作.
- `CommandMailbox` / `Snapshot`、DJI 编解码、UART DMA 字节管线、DR16 边界分帧与 BMI088 解析.
- `DjiDevice` / `DjiTxGroup`: 显式设备配置、轴侧速度与位置参考、归一化输出转换及四槽合并. 原单电机夹具和新增四电机同组场景均复用正式组件, 契约见 [DJI 设备与分组执行](../../modules/drivers/DJI设备与分组执行.md).
- 主机示例与 SIL 都使用同一个 `VelocityLoop` 和 DJI 设备执行组件, 不维护模拟专用控制器. 这些组件尚未接入真实电机输出任务.

**模拟边界**:

- PC 命令源通过进程内类型接口投递目标、读取状态, 没有冻结新上位机线协议、字节布局或握手. 授权来自夹具模拟的本地自检与明确许可, 不是来自网络中的 `Grant`.
- 虚拟 CAN 链路有固定容量和可注入的延迟、丢包、busy/error. 原有单个虚构 C620 ID1 场景及四个同组 C620 场景采用一阶转子模型, 反馈经过正式 DJI 解码与设备换算再参与控制. 模型的增益、时间常数、原始量映射、看门狗、PID/TTL 参数均为测试数据, 不可当作装机参数.
- 无输出时发送零电流是这个独立虚拟台架明确选择的动作, 不代表实车已定义制动/保持/失能. 测试结果不证明真实机构停止距离、保护时延、稳定性或功率/热量约束.
- UART 测试注入 DMA 游标、HT/TC/IDLE 和错误恢复事件; IMU 测试投递合成 SPI 响应与失效样本. 它们不执行 STM32 寄存器副作用、实际 HAL 中断或真实 SPI 事务, 不代替板级胶合代码、RTOS 调度与电气验证.
- CAN 打点仍是本地接收时间. 无源端时间戳时, 持续滞后但不断到达的反馈不能仅凭 TTL 判定为旧测量. 发送端 `accepted` 也不证明对端已应用命令; SIL 包含“accepted 后丢包且电机未应用”的限制用例, 不把它误报为已被固件检测.
- 执行器掉电场景覆盖持续时间足以触发反馈超时的情况. 小于超时且无启动标识的短暂重启尚不能可靠识别; 检测/恢复契约与真实电调设置仍需闭合. MCU 重启身份、新协议、防重放、全车仲裁、双 yaw 反馈及各机构安全动作仍按 Checklist 协商, 本轮不以模拟值替代决策.

**运行方法** (仓库根目录; 首次安装与配置见 [第一次构建与运行](../../getting-started/第一次构建与运行.md)):

```powershell
cmake --build build/host
ctest --test-dir build/host --output-on-failure
# 仅运行软件在环:
ctest --test-dir build/host -R sil_contracts --output-on-failure
# 可选轨迹导出, 必须使用不存在的新文件名:
./build/host/ec_sil_tests.exe --csv build/host/sil-trace.csv
```

Release 对应 `build/host-release`. CSV 使用排他创建, 已存在则报错而非覆盖. 每个场景有独立虚拟时间轴; CSV 包含目标、模型真实转速、解码反馈及其新鲜度、控制计算输出及其有效性、`VelocityStatus` 和 `SendResult` 的枚举数值. `output_valid` 只表示计算有输出, 不表示 CAN 已送达或电机已执行; 状态数值是调试数据, 不是长期线协议. 无反馈时占位数值必须结合 `feedback_fresh=0` 阅读. UART/IMU 回放结果通过终端断言输出, 不伪造动力学曲线.

**自动判定覆盖**: 正负目标跟踪与饱和、输入非有限/超界、命令/反馈在到期瞬间失效、旧授权拒绝、本地撤销、遥控失联不自动授权上位机、重新自检/授权后恢复、电调掉电而 MCU 不重启、CAN 延迟/坏帧/队列满/TX 失败、32 位时间回绕及过长控制步长、UART 分块/游标重启/溢出与 DR16 重同步、IMU 响应格式与样本陈旧. 检查在 Debug 和 Release 均启用. 新增四电机同组场景还验证方向/传动比换算、跨圈位置跟踪、独立槽位控制, 以及单槽撤销后整组拒发并不会立即清除电调旧输出的限制. 该场景仅通过终端断言报告, 不加入现有单电机 CSV. 混合 C610/C620 与 GM6020 分组的协议边界由核心契约测试覆盖, 不声称已经具有这些电机的真实动力学模型. 这些均为离线证据, 不填写 S1–S6 实机通过记录.

**后续按小批次推进, 不自动执行**:

1. **补齐 S1 与 UART 基线**: 当前 CH340 接在尚未初始化的 3pin USART6. 先按 [接口与接线注意](../../boards/sentinel_f407/接口与接线注意.md) 确认丝印与针序, 决定改接已配置的 4pin USART1, 或另行实现 USART6; 本次未改线/改固件. 官方手册说明两路普通 UART 支持 3.3 V/5 V 电平, 仍需核对 CH340 TX 电平与 RX 门限, 不向已供电板并接 VCC. 匹配端口后从小包回显开始, 再使用现有 `uart_probe.py` 验证持续传输与恢复. 复位键/掉电重启另由现场操作后检查诊断.
2. **DR16 与 BMI088**: DR16 通过 C 板对应 DBUS 接口与既有电路连接, 不将反相 DBUS 当成普通 TTL 串口. 只观察各通道、拨杆、离线及重连; BMI088 检查板体各方向的加速度/角速度响应, 加热仍关闭. 不由遥控直接驱动电机.
3. **无电机 CAN 台架**: 达妙模块接 C 板, 选择 CAN2.0 / 1 Mbps / 标准数据帧, 不用 CAN FD/BRS. 两品牌该 2pin 接口的 H/L 排列不同, 先按上述接线说明确认线束是否已换序, 始终 H→H、L→L, 并核实参考地方案和终端电阻. 从低频、有限数量测试帧开始, 分别验证 CAN1/CAN2 接收及在线过期. 正常模式控制器可能自动 ACK, “不发控制帧”不等于电气静默.
4. **GM6020 仅反馈**: 获得独立供电许可并固定电机后, 先确认实际 ID、模式与输出禁用条件, 仅采集反馈. 现观察映射仅对 CAN1 `0x208/0x20a` 按 GM6020 解码; 其他 ID 只计在线, 不能把未解码当作电机无反馈. 不为了迁就映射而擅自修改电机持久参数.
5. **单电机运动**: 在前置反馈通过、限幅/超时/停止与独立断电方案确定后, 单独授权并提供专用台架组装. 当前观察固件不具备运动输出入口; 电池与分电板不能替代限流、保险及独立动力切断措施.

最初参照的 USB2CANFD 手册与现场型号不一致, 不能将其终端默认值、针序或 SDK 结论直接套用于实物. 现场 USB2CAN 已按下节跑通 1 Mbps 通用 CAN 接收, 无需为此另购通用 CAN 模块. 接线规则与资料入口统一见 [接口与接线注意](../../boards/sentinel_f407/接口与接线注意.md).

### 2.3 CAN1 台架与工具选择 (2026-09-17)

**后续现场更正**: 采购标签写 USB2CANFD, 但用户确认实物为 `USB2CAN / DM Tools / REV V3.0`, 且没有可用达妙电机. 前述 USB2CANFD SDK 选型与手册对该实物的适用性未成立; SDK 枚举为 0 不能用来断言适配器损坏或电池休眠. 后续改为核对 USB2CAN 的 CDC 串口工具/协议与版本, 不刷 FD 固件或替换现有串口驱动. | UART 错误恢复 | 30 ms Break 产生 1 次 FE、1 次 RX 重启, 随后的合法请求成功; Debug 与 Release 均通过该场景, 不等于覆盖所有 DMA 硬件故障 |
| Release 30 s 并发 | 配置请求 10 Hz, 实收 244 快照; DR16 有效帧增加 2135, IMU 持续有效; 并发 CAN1 注入 5000 帧全部收到, 无新增丢弃, 最大周期 10 ms、跳周期/故障 0, 栈最低余量 346 words |
| Debug 观测 | 5 s 内 23 快照, 最大周期 10 ms、跳周期/故障 0, 栈最低余量 228 words; 不是最坏实时负载证明 |
| 软件复位与 PC 连续观察 | 25 s 窗口共 112 快照, 明确看到 MCU 时间回到起点; 复位期间 1 次响应超时, 随后恢复, 最后 DR16/IMU 有效, 无固件故障 |
| 端口关闭后重开 | 同一 COM3 被多个有限测试串行打开/关闭后仍可查询; 不代表物理拔插已验收 |

结束时恢复并保留 Release `5aa113e-u6-observe`, 软件复位运行, 串口及调试服务关闭, 现场电源未由软件切断. 人工后续可直接运行面板, 集中完成遥控通道/拨杆动作、遥控器关开、IMU 轴向、按键与真正掉电重启. **USART1/CAN2 不设阻塞, S1–S4 不因面板已可用而整体关闭**. 整机串口/SWD 监控仍为 Checklist I11 的后续需求.

## 4. 人工通用操作顺序

1. 核对本次固件、目标板和测试模式, 确认只启用当前组件. 检查电源与接线, 未测试执行器按现场已确认方案隔离; 不依赖一个软件标志保证所有外设不动作.
2. 确认已经得到对应烧录/供电/运动授权. 涉及发射链时确保无弹, 实弹另行单独许可; 无弹不等于摩擦轮或拨盘没有机械风险.
3. 按本阶段提供的准确操作烧录并校验, 复位后先检查身份、启动模式和错误状态. 身份或模式不符就停止, 不继续尝试运动.
4. 打开日志/测试工具, 先记录空闲状态, 再一次只改变一个输入. 比较预期结果, 保存必要的日志、截图或测量记录.
5. 只执行本阶段列出的异常场景. 断开数据链路、停止发帧、设备掉电是不同测试, 不能相互替代. 不短接带电总线或随机拔插大电流电源模拟故障.
6. 结束时撤销授权与目标, 按明确动作确认机构停止或失能后再处理接线/供电. 记录通过、失败、未测和限制, 由用户确认验收结论.

出现异常运动、方向/反馈矛盾、连续复位、通信洪泛或日志中断导致状态不可判断时, 停止增加输入, 按预先确认的停止/断电方案处理; 保留证据后排查, 不靠重复复位强行继续.

## 5. 分阶段人工操作说明

### S1. 板级基础

**开发准备**: 明确板级时钟与 HAL 时基、RTOS tick、日志出口; 提供一个不初始化运动业务的入口. 输出固件身份、复位原因、心跳时间、任务超期和栈余量等可获取诊断. 栈/堆配置不照搬旧工程作为已验收预算.

**人工操作**:

1. 按供电图隔离执行器, 连接调试器与诊断通道, 烧录 S1 固件并复位.
2. 核对启动身份、测试模式、配置与复位原因; 观察心跳计数和周期时间持续增长.
3. 按交付说明观察指定时长, 检查是否有复位、HardFault、任务停滞或超期增长.
4. 在不连接运动输出的前提下分别进行软件复位、复位键复位和获授权的主控重新上电, 核对诊断及重新初始化行为.
5. 对要求精确的时钟/周期, 使用独立测量手段或已校准时间参考核对; MCU 用自己的错误时钟打印“周期正确”不能独立证明频率正确.

**通过标准**: 能可靠启动/复位, 身份正确, 无非预期输出或异常复位, 周期与资源余量满足本阶段预先给出的判据. 仅看到 LED 闪烁不构成完整通过.

#### S1 已实现入口与配置

- 板级入口: `boards/sentinel_f407/cubemx/sentinel_s1/sentinel_s1.ioc`; 实际 CubeMX 6.18.1, STM32CubeF4 1.28.3 / HAL 1.8.5 / FreeRTOS 10.3.1. SDK 外置, 包身份校验见 `boards/sentinel_f407/sdk.cmake`; 不修改本机 SDK 或旧参考工程.
- MCU: STM32F407IGH6, 1 MB Flash、128 KB 普通 SRAM + 64 KB CCM; S1 不使用 CCM. HSE=12 MHz, PLL M/N/P/Q=6/168/2/7, SYSCLK/HCLK=168 MHz, APB1=42 MHz, APB2=84 MHz. HSE/PLL 输入已显式保存, 不能在 Clock 警告下继续当作有效配置.
- HAL 时基为 TIM14 1 kHz, RTOS SysTick 为 1 kHz; 一个普通优先级 S1 任务按 10 ms 绝对周期运行. 这是诊断配置, 不是后续机构控制频率.
- RTOS heap_4=16 KB, S1 任务栈=2048 字节, MSP 预留=4096 字节. 任务对象在调度前分配, 诊断循环不分配. 栈溢出/分配失败/断言及核心故障接入 RAM 诊断. IWDG 未启用, 故障停留供调试, 不自动重启.
- 当前合并观察固件还初始化下述 S2–S4 的 UART/CAN/SPI 路径, 不再是仅 SWD/时钟入口. PF6 保持 GPIO 低电平关闭 IMU 加热, PA4/PB0 初始化为高电平, SPI 采样时按事务控制片选. 不启动 USB、PWM 或运动业务. 软件输出限制不替代现场执行器供电隔离.
- 诊断为固定 RAM 的 `g_ec_s1` 与 16 项覆盖式事件环, 无串口日志依赖. 复位/掉电不保留记录; 当前协议不是运行中多字段一致快照, 用调试器停核读取.

#### S1 集中人工验收时的具体命令

**以下仅在硬件就位且获得烧录/主控供电授权时执行; 按 S1 起依次验收, 不因离线测试通过而跳过.** 先隔离执行器, 保证无弹; 按实际板卡调试接口图核对 SWDIO=PA13、SWCLK=PA14、GND、参考电压与复位连接. 这里给出支持 `dapdirect_swd` 的 ST-Link 示例, 不假设现场探针一定为 ST-Link; 若为 J-Link 或其他探针, 应先明确匹配配置, 不盲试驱动或自动升级探针固件. 不修改 Option Bytes、读保护或执行整片擦除命令.

1. 完成上面的构建/产物审计, 记录版本与哈希. 检查供电和目标身份后烧录、校验并复位:

```powershell

if ($LASTEXITCODE -ne 0) { throw 'Programming or verification failed; stop here' }
```

该命令会改写固件所覆盖的 Flash 扇区, 包括旧程序的相关扇区; 需要保留旧固件时先准备已确认的可恢复镜像. 不将文档基线提交当作旧整车固件备份.

4. 预期与记录:
   - `magic=0x45435331`, `abi=1`, 身份标签与构建一致, `stage=6` 且 `fault=0`.
   - 记录 `sysclk_hz/hclk_hz/pclk1_hz/pclk2_hz` 为 168M/168M/42M/84M, `hal_version=0x01080500`, `rtos_hz=1000`, `period_ms=10`. 这些是寄存器/配置计算值, 不是对晶振精度的独立测量.
   - 连续无调试干扰运行时 `cycles` 约每秒增加 100, 预期 `skipped_periods=0`; 记录 `max_elapsed_ms`, 不将本轮诊断统计等同于控制 WCET. 不符合时保留日志调查, 不直接调大容限.
   - 运行超过一秒后 `stack_free_words>0`, `heap_free_bytes` 与 `heap_min_free_bytes` 在初始化后应稳定; 栈余量单位是 4 字节 word. 这只是当前负载余量, 不证明未来整车预算.

5. 停核会干扰时基和调度统计. 若要复查连续运行时序, 重新复位后再做一段完整观察, 不把停核前后计数直接拼接. 复位键、主控重新上电等用例按上文 S1 步骤分别执行并记录复位标志; 结束后停止调试并按现场方案断电.

#### S2–S4 已实现入口与配置

同一 `sentinel_s1` 固件现已包含 S1–S4 非运动路径, 构建命令与 S1 相同. 额外诊断在 `g_ec_io` (`magic=0x45434f49`, `abi=2`); CAN 转速字段为 `last_speed_rad_s` (`float`, 电机侧 rad/s). 不启动 PWM/USB, 不链接电机命令编码或 `HalCanTx`. IMU 加热保持 GPIO 关闭.

| 组件 | 引脚与配置 | 软件行为 |
|---|---|
| USART1 上位机字节流 | PA9 TX / PB7 RX, 115200 8N1, RX DMA circular 512 B, TX DMA 512 B | 回显收到的字节; 每 10 ms 最多搬运 512 B, 每个临界区最多复制 64 B; TX 背压时保留 RX 数据, 溢出丢弃未读并计数. 该波特率取自现有运行 `usart.c`, 不是未冻结的最终上位机协议 |
| USART3 DR16 | PC10 TX / PC11 RX, 100000 9E1, RX DMA circular 64 B | 以真实 IDLE 标记 DR16 帧间隔, 仅解码边界间恰好 18 B 的帧; 启动/接收错误后首个 IDLE 只用于同步. 100 ms 无新帧则 `online=0`. 不驱动机构 |
| CAN1 / CAN2 | PD0/PD1, PB5/PB6, 1 Mbps, 全 ID 滤到 FIFO0 | 只接收. 记录时间戳、在线计数; CAN1 0x208/0x20A 按 GM6020 电流模式、CAN2 0x201–0x206 按 C620、0x207 按 C610 解码, 其他 ID 仅统计在线. C610 温度无效. 不下发 0x200/0x1FF/0x1FE 等控制帧. DM 不主动查询 |
| SPI1 BMI088 | PB3 SCK / PB4 MISO / PA7 MOSI, mode 3, 5.25 MHz (APB2 /16, 不超过 BMI088 的 10 MHz 上限); CS=PA4/PB0 | 读取加速度/陀螺/温度并换算 SI. ±6 g / ±2000 °/s 与现有运行配置一致, 无零偏标定. 通信失败不复位整板 |

### S2. UART 收发与 DMA

**开发准备**: 提供独立端口测试模式与对端工具, 输出序号、字节计数、校验结果、缓冲溢出和 UART/DMA 错误. 测试载荷不是最终上位机协议; 串口驱动只保证字节流及错误报告, 不假设一次 DMA 回调等于一帧. 同时给出引脚、电平、波特率/字长/校验/停止位和缓冲容量.

**人工操作**:

1. 断电核对接线与 TTL 电平, 选用交叉 TX/RX + 共地的对端或明确指定的本地回环. 不接入 RS-232 电压, 不同时连接两个发送器到同一 RX.
2. 烧录并打开独立诊断通道, 发送带序号的已知二进制数据, 覆盖 `00`、`FF` 等非文本字节, 核对完整内容与计数.
3. 按工具提供的用例依次执行短包、缓冲边界前后长度、拆分发送、连续多段和连续无空闲数据. 核对字节顺序、完整性, 不能仅测串口助手手打文本.
4. 在预定容量内双向持续收发, 再按明确用例超过缓冲预算, 观察是否报告溢出及采用既定丢弃/恢复行为. 超载后不能把旧数据当新数据交付.
5. 分别停止对端发送与按说明断开数据连接, 再恢复正常数据, 检查错误恢复和有效时间戳. 不让“串口收到新字节”自动使能机器人.

**通过标准**: 预算内无非预期丢失/重复/乱序; 超载和异常可观察、可恢复, 不越界或阻塞实时任务. 本地回环只证明本地路径, 正式 Jetson 链路仍需实线验证.

### S3. CAN 与电机反馈

**开发准备**: 提供只接收/诊断入口, 不发送电机使能或运动帧. 明确总线速率、过滤器、设备 ID、解码模式和时间戳来源; 按设备区分反馈字段有效性. DM 若需要主动查询才反馈, 查询命令和影响须先核实, 不能隐式夹带使能.

**人工操作**:

1. 断电核对 CANH/CANL、参考地与终端配置, 初次只接一个已知设备或已确认的总线分支; 电机供电按授权范围进行.
2. 观察原始 CAN ID、DLC、数据、接收时间、设备状态与解码值; 与已有设备设置对照后, 再接下一个设备排查 ID 冲突.
3. 如果设备和现场允许安全手动转动, 在明确条件下缓慢改变位置, 对照角度/速度方向与原始编码值; 不强行转动带电闭环轴或有机械约束的机构. 无法手动验证的项目留到 S5.
4. 通过停止测试对端发送或获授权的设备掉电, 观察反馈超过指定时间后变为无效/离线; 数值保留用于诊断时必须明确标为陈旧.
5. 恢复设备, 检查重新识别和新反馈. 对 MCU 不掉电、执行器重上电的情况, 不能自动恢复旧运动许可.

**通过标准**: ID 映射、帧解码、字段有效性与新鲜度正确, 无非预期控制发送. C610 温度必须标为不提供; 未确认的 DM 量程不能冒充有效物理量. “未下发运动”不保证电调上电自身一定无动作, 供电前仍需确认其启动行为和现场安全条件.

### S4. 遥控与 MCU IMU, 分别验收

**遥控操作**:

1. 只启用输入显示, 执行每个摇杆、拨杆及计划保留的按键操作, 对照原始值、归一化值与模式请求.
2. 观察中位/端点、无效帧与输入稳定性; 关闭遥控发送端验证离线判据, 恢复后检查旧操作是否被清理.
3. 检查模式选择只是仲裁输入, 不直接调用电机输出; 遥控掉线不构成上位机自主授权.

**IMU 操作**:

1. 先检查传感器身份、通信错误和带时间戳的加速度/角速度/温度原始数据, 再观察姿态有效性.
2. 按交付说明静置初始化, 检查零偏/有效状态, 不以未经标定的姿态作为已就绪反馈.
3. 在不牵动带电机构的安全条件下按已标注轴缓慢改变传感器姿态, 核对轴向、符号和时间顺序; 可利用已有可信标定, 不要求无理由重做全部标定.
4. 通过已实现的测试入口停止样本投递, 检查陈旧状态和恢复. 若做软件注入, 记录为注入验证, 不冒充真实 SPI 断线测试.
5. IMU 加热单独确认启用, 先核对温度有效性、输出上限与失效切断, 再观察稳定性; 不把旧温控常数直接视作新实现已验证参数.

**通过标准**: 遥控输入/离线语义正确; IMU 数据、时间与有效性符合已定义判据. 末端 MCU IMU 的采样通过不代表它可以直接作为主 yaw 稳向反馈, 主 yaw 反馈缺口不在本阶段自动闭合.

  保存设置、轮几何 —— 不改变代码路径; 但部署配置契约测试的期望值需同步更新 (它当前断言
  "无真实值 → 零装配槽").
- **回填后必须重跑对应离线证据**: IMU 安装轴向与时间质量 (感知重构)、ch4 中位/方向/量程
  (本地操纵映射)、DM 保存量程 (达妙 MIT 编解码量纲) —— 这些数值进入换算, 旧夹具结论不再适用.
- **回填不使下列证据失效**: 框架层 (core/drivers/estimation/monitor) 契约、协议线格式、
  任务/CAN/内存静态预算、角色审计与镜像检查.
- **填表不是授权**: 任何烧录、供电、动力测试与机构动作仍需单独明确授权; 配置齐备只表示
  该域具备执行资格, 不等于已授权或已验证.
