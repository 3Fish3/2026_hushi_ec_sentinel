# 监控注册表 (ec::monitor::Registry)

源码: [registry.hpp](../../../include/ec/monitor/registry.hpp)、[registry.cpp](../../../src/monitor/registry.cpp); 板级装配在 `boards/sentinel_f407/src/board_registry.cpp`.
契约测试: `tests/monitor_tests.cpp`; 只读后端: `boards/sentinel_f407/tools/monitor_swd.py`; 使用说明见 [串口观测与应用接入](../../guides/串口观测与应用接入.md).

## 1. 解决什么问题

整机状态对象通常远大于 256 字节, 不能整块塞进通道; 而"谁在线、目标是多少、为什么被拒绝"这类信息又必须能从**串口和 SWD 两个后端**看到同一份逻辑状态. 本模块提供一张固定容量、定长记录的静态表:

- 每周期由板级任务更新, 单写者;
- 串口按页请求 (显式小端 wire 编码), SWD 直接读运行中 RAM;
- 关闭编译开关后既没有表也没有每周期发布开销.

它**不负责**: 控制决策、日志持久化、历史回放、为所有兵种设计万能字段字典. 也不声称分页是原子全车快照.

## 2. 记录内容

| 字段 | 含义 |
|---|---|
| `kind` | `device` / `axis` / `source` / `period` / `environment` |
| `id` | 该类别内的序号, 由注册方约定 |
| `validity` | `unknown` / `valid` / `stale` / `invalid` / `unavailable` |
| `mode` / `enabled` | **两个独立字段**: 控制模式与执行状态不合并 |
| `reject` | 拒绝原因枚举 (`no_grant`、`stale_feedback`、`target_stale` …) |
| `sampled_at` / `published_at` | 该记录自己的采样时刻与写入发布区的时刻 |
| `target` / `measurement` | 目标与测量; 没有来源时写 NaN |

未实现的传感来源是 `unknown`, 未安装的设备是 `unavailable`, 数值用 NaN: **不用健康零值冒充"一切正常"**.

## 3. 分页、代次与并发

- 一页最多 8 条记录, 每条 24 字节, 载荷 = 24 + 24×条数 (满页 216 字节), 在单帧预算内.
- 写入与发布分离: 写者 (`find()`/`records()`) 改的是**暂存视图**, 读者 (`read_page()`/`records() const`/`published_records()`/SWD 描述符地址) 在 `end_update()` 之前一直看到上一份已提交视图. `end_update()` 把暂存**整体**复制到发布区 (容量固定 48×24 B, 不依赖"哪些槽被 find 过"), 然后推进代次.
- 发布代次协议: 复制**前**代次 +1 变**奇数**(发布中), 复制完成后 +1 变**偶数**(可读). 读者只接受"两次读取相同且为偶数"; 两次读取都落在复制窗口内时会读到同一个奇数, 因此不会被误认为一致快照 —— 只比较"代次是否相同"做不到这一点. **时钟与已用条数也在括号内更新**: 它们与记录同属一份快照, 在括号外先写时钟会让读者在偶数代次下读到"新时钟 + 旧记录". `flags` 是描述符里的静态属性(监控已启用), 不是发布状态快照.
- 头部带 `generation`: 读者先读代次、读记录、再读代次, 不一致就重试 (有限次) 并标记撕裂. 代次在复制之后推进, 所以相等才代表这一份是完整发布; 代次变化本身不是"数据错", 也不保证跨重启唯一.
- 每条记录保留自己的采样时刻, 所以**同一页里的记录不来自同一瞬间**; 需要"同一次采样"的语义时要看 `sampled_at`.
- 跨任务读取走 `copy_snapshot(lock, ...)` 提供的正式临界区, 不用 `volatile` 掩盖 data race.

## 4. 只读后端与容量

- 串口: USART6 观测协议的分页请求/响应 (`0x02`/`0x82`), 每周期只保留最后一个请求, 不阻塞控制.
- SWD: 描述符 `g_ec_monitor_desc` (40 字节定长, 含 magic/版本/记录尺寸/容量/各字段地址) 供调试器定位; 描述符里的 `records_address` 指向发布视图. 读取方先校验描述符, 再按"读代次 → 读记录 → 读代次"的顺序核对, 只发 `read_memory` (`read_memory <address> <width> <count>`, 本工具固定 width=8), 不 halt/不写. 响应解析要求先去掉命令回显与 IAC 协商, 且必须以提示符结束; 缺提示符、错误行、字节数不符都算失败, 不回退到"尽量解析".
- 容量: 48 条记录, 认领满返回空而不动态扩容; 关闭 `EC_MONITOR_REGISTRY` 后 Release 配置约省 1.8 KB Flash / 1.2 KB RAM (实测值见 [资源与并发预算](../../boards/sentinel_f407/资源与并发预算.md)).

## 5. 常见错误

- 把 `validity == unknown` 当成"设备正常": 它表示**该来源还没有实现**.
- 用 `published_at` 判断数据新鲜度: 那是写入时刻, 新鲜度要用 `sampled_at` 与对应 TTL.
- 把分页当成一致性快照: 页内各记录时刻不同, 代次只保证"没读到半更新".
- 在中断里更新记录表: 它不是为 ISR 设计的, 只允许每周期任务写.
