# STM32F407 平台适配 (STM32F407 Platform)

源码: [stm32f407.hpp](../../platform/stm32f407/include/ec/platform/stm32f407.hpp)、[adapter.cpp](../../platform/stm32f407/src/adapter.cpp)，位于 `ec::stm32f407` 命名空间。
本层是通用核心库与 ST 官方 HAL 库 / FreeRTOS 之间的“桥梁”，负责把通用接口映射到底层真实的 ARM 汇编与驱动调用上。

---

## 1. 硬件中断临界区策略 `IrqCriticalSection`

在单核 Cortex-M4（STM32F407）芯片上，多个 FreeRTOS 任务以及各种外设中断服务函数（ISR）可能会并发访问同一个通道。此时通用的互斥锁（Mutex）无法在中断里使用，必须使用硬件级的屏蔽中断策略：

- **保存与恢复现场**：
  - `enter()`：读取 ARM 核心的 `PRIMASK` 寄存器保存当前中断状态，执行关中断指令（`__disable_irq()`），并插入内存屏障（`__DMB()`）；
  - `exit(saved)`：执行内存屏障，再将 `saved` 状态写回 `PRIMASK` 寄存器。
- **为什么必须“恢复原掩码”而不是盲目开中断（`__enable_irq()`）？**
  如果当前代码本身已经处在某一个中断服务函数中、或者处于上一层外层临界区内，如果内层代码退出时盲目执行开中断，就会提前放开中断嵌套，彻底破坏外层的同步保护！因此必须严格遵循“进门保存、出门恢复”原则。
- **作用边界**：
  仅适用于单核 Cortex-M4 的任务与普通外设中断。它**不屏蔽 NMI（不可屏蔽中断）与 HardFault（硬件硬故障中断）**，且**关中断绝对不会停止硬件 DMA 的后台内存搬运**！临界区内部只允许执行极短的有界内存拷贝，严禁在临界区内调用 RTOS、HAL 或用户回调，包括延时和打印；持续时间仍需测量，不能只按关中断指令耗时估计。

---

## 2. 单调毫秒时钟 `now()`

`ec::stm32f407::now()` 函数将 ST 官方 HAL 库的 `HAL_GetTick()` 封装为核心层的强类型单调毫秒 `Tick`：
- 要求系统必须拥有一个持续自增的 1 kHz 时基（通常由 SysTick 或专用硬件定时器提供）；
- 严禁在时基未初始化或处于低功耗休眠停止状态下读取时间。

---

## 3. 周期性精确等待 `PeriodicWait`

在电控控制任务中，控制算法（如 1 kHz 速度环）必须以严格的固定周期被唤醒：
- `PeriodicWait` 在控制任务初始化时构造，传入 **FreeRTOS 的原生 tick 周期数**（注意：必须确保 FreeRTOS 的 `configTICK_RATE_HZ` 与你的周期预期一致）；
- 每次在循环末尾调用 `wait_next()`：内部结合了 [周期规划](../modules/core/周期规划.md) 算法与 FreeRTOS 的 `vTaskDelayUntil()`，彻底消除累积相位漂移；
- 若发生严重调度超时，`wait_next()` 会自动报告跳过的周期数，不补跑堆积的过期周期。非法周期或超出半回绕观察范围返回空值，调用方必须处理；禁止在 ISR 中调用，调度抖动仍需实测。

---

## 4. CAN 硬件发送适配器 `HalCanTx`

当启用了 STM32 HAL CAN 驱动时，`HalCanTx` 实现了通用的 `ec::transport::CanTx` 发送接口：
- 构造时借用板级初始化的 `CAN_HandleTypeDef&` 句柄；
- 发送时检查硬件发送邮箱：若 3 个硬件邮箱均被占用，立即返回 `SendResult::busy`，绝不在当前执行流中死循环轮询；若有空闲邮箱，调用 `HAL_CAN_AddTxMessage` 将报文写入硬件寄存器并返回 `accepted`；
- **单发送任务独占纪律**：同一个 `HalCanTx` 实例只能由一个专属的通信任务调用，禁止多任务并发向同一个硬件 CAN 句柄下发报文。

---

`accepted` 仅表示接口已接受报文，不代表电调收到或执行；该适配器不提供完整的 Bus-Off 监测与恢复状态机。

---

## 5. 短窗口测时 `CycleTimer`

- 基于 Cortex-M 的 DWT 周期计数器，`elapsed_us()` 给出同一窗口内的短时间差，用于周期最差耗时统计。
- **DWT 计数器会回绕** (168 MHz 下约 25.6 s)，因此只能做短窗口时间差，不是跨机同步时钟，也不能拿它代替系统 `now()`。
- 计数未启用或不可用时 `elapsed_us()` 返回空值，调用方必须处理，不能当成 0 微秒。
- 具体预算与实测缺口见 [资源与并发预算](../boards/sentinel_f407/资源与并发预算.md)。

## 6. 高级入口：独立交叉编译平台适配静态库

> **初学者提示**：
> 新队员若要编译完整的 C 板固件，请直接参考 [板级生成与构建](../boards/sentinel_f407/生成与构建.md)，无需阅读本节。
> 本节仅供开发底层适配层、单独验证静态库语法与编译期约束的高级开发者参考。

在 PowerShell 7 终端、仓库根目录执行以下命令，可以在不生成完整 ELF 固件的前提下，单独交叉编译出 `libec_stm32f407.a` 静态库：

```powershell
# 遇到未捕获错误立即停止
$ErrorActionPreference = 'Stop'

# 1. 填入实际路径: $cube 需含 Drivers/、Middlewares/ 及 Inc/ 下的
#    stm32f4xx_hal_conf.h、FreeRTOSConfig.h；官方 SDK 本身不提供板级配置。
#    配置头不在 Inc/ 时另传 -DEC_BOARD_CONFIG_DIR=实际配置目录。
#    其他必要头文件目录可用 EC_SDK_EXTRA_INCLUDE_DIRS 补充。
#    本节不会替你创建外部工程，也不使用固件构建的 SDK 锁定检查。
$arm = 'C:/Tools/arm-gnu-toolchain-14.2.rel1' # 替换为你实际的工具链根目录
$cube = 'C:/SDK/external-cube-project'       # 包含 STM32CubeF4 头文件依赖的工程目录

# 2. 生成基于 Ninja 的交叉编译构建配置
#    -DCMAKE_TOOLCHAIN_FILE : 引入交叉编译工具链定义文件
#    -DEC_BUILD_STM32F407=ON: 启用 STM32F407 适配静态库的构建
#    -DEC_CUBE_PROJECT      : 传入底层 HAL/CMSIS/FreeRTOS 头文件检索根目录
cmake -S . -B build/f407 -G Ninja `
  -DCMAKE_BUILD_TYPE=Debug `
  "-DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake" `
  "-DARM_GNU_ROOT=$arm" `
  -DEC_BUILD_STM32F407=ON `
  "-DEC_CUBE_PROJECT=$cube"
if ($LASTEXITCODE -ne 0) { throw 'CMake 配置生成失败' }

# 3. 编译静态库目标
cmake --build build/f407
if ($LASTEXITCODE -ne 0) { throw '平台适配库交叉编译失败' }
```
