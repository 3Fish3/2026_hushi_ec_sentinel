# 会话、控制权与执行上下文

源码: [authority.hpp](../../../include/ec/control/authority.hpp)、[execution_context.hpp](../../../include/ec/control/execution_context.hpp)、[session.hpp](../../../include/ec/session.hpp); 底层 token 见 [授权门](授权门.md).
契约测试: `tests/session_tests.cpp`; 端到端主机示例: [host_link_example.cpp](../../../examples/host_link_example.cpp)、[host_app_example.cpp](../../../examples/host_app_example.cpp).

## 1. 三个层次, 不要混成一个"模式"

| 组件 | 回答的问题 | 不回答 |
|---|---|---|
| `session::SessionTracker` | 对端是谁、链路还活着吗、这条意图是新的吗 | 谁有权控制、机构该怎么停 |
| `control::ControlAuthority` | 本周期谁可以下发目标 (遥控 / 上位机 / 无人) | 协议解析、机构动作 |
| `control::ExecutionContext` | 这一次执行请求是否放行, 不放行时该做什么动作 | 目标值本身、总线编码 |

三者都不构成完整整车安全状态机: 机构停止动作、故障传播范围和恢复条件仍要按机构逐项定义, 见 [Checklist A08/A09](../../robots/sentinel/现有能力与待确认Checklist.md).

## 2. 会话: 身份、链路与意图

`SessionId{source, boot, session}` 由对端声明, 本地只核对: `source` 是对端身份, `boot` 是**每次启动唯一**的 nonce (否则重启后旧会话的序号与幂等记录会误判), `session` 是显式重建时递增的会话号.

- `begin()` 只在"还没有会话 / 身份变了 / 同一身份但会话号更大"时接受; 同一身份、相同或更小会话号一律拒绝, 旧会话的帧不能重置序号窗口.
- `heartbeat()` 只刷新链路存活 (`link_ttl`), **不影响任何意图期限**.
- `accept_intent()` 返回 `accepted` / `duplicate` / `stale` / `expired` / `no_session` / `not_ready`. 意图有效期在首次接收时按本地时钟与外层 TTL 固定, **重传不会延长它**; 判据全部用本地 `Tick`, 不做跨机时钟同步, 也不信任对端时间戳.

## 3. 控制权: 只有边沿才能取得授权

`ControlAuthority::update(Inputs)` 每周期调用一次, 返回本周期允许的来源或空 (空表示必须撤销所有轴). 规则:

- 遥控在线本身不等于接管, 必须有明确接管动作 (`remote_takeover`);
- 遥控接管优先于上位机, 即使上位机同时请求;
- 遥控掉线只撤销授权, **绝不自动把控制权交给上位机**;
- 撤销后上位机必须重新提出请求 (请求边沿); 持续保持的旧请求电平不能重新获得授权;
- 上位机还需要有效会话与本地显式授权 (`host_authorized`), 链路存活本身不等于授权.

`token()` 给出当前执行 token, `gate()` 暴露底层授权门供执行路径核对; 两者都建立在同一个 `ExecutionGate` 上, 不引入第二套故障状态机.

## 4. 执行上下文: 一处判断, 明确结论

```text
ExecutionRequest{ token, locally_ready, target_fresh, link_alive }
ExecutionContext{ gate, policy }.evaluate(request)
  -> { execute, reason, stop }
```

`reason` 区分 `not_ready` / `no_grant` / `link_stale` / `target_stale`. 不放行时给出 `policy` 里配置的 `StopAction`: `hold_position` / `zero_output` / `disable_output` / `unspecified`.

**`unspecified` 表示上层还没有配置策略, 必须报告而不是静默归零.** "无输出"不等于"已经停下": 减速、保持、零输出或失能由机构装配层显式选择, 框架不提供默认动作, 也不自行把某个机构归零.

## 5. 所有权与常见错误

- 单任务拥有, 每周期调用一次; 不在中断里调用, 不跨任务共享.
- 把 `link_alive` 当授权: 链路活着只说明"能收帧", 不等于"允许执行".
- 用持续电平代替请求边沿: 撤销后旧请求不能恢复授权, 必须重新给出请求动作.
- 期望框架自己选停机动作: 不会; `policy_missing` / `unspecified` 必须由应用层补齐.

## 会话身份变化与序号事务 (修复后口径)

- **身份代次 `epoch()`**: 会话层在"接受新的会话身份"(换来源 / 换启动实例 / 同一对端更高会话号)
  或本地 `reset()` 时递增。`begin()` 对**身份不同**的请求默认**拒绝**, 只有本地明确进入重建流程
  (`begin(id, now, allow_identity_change = true)`) 才接受; 旧身份之后不能夺回会话。
- **授权随身份失效**: 控制权组件接收 `Inputs::host_session_epoch`; 代次变化的那一周期按
  "上位机未请求"处理 —— 旧目标与旧 token 立即失效, 新会话必须重新产生请求边沿才能重新取得控制权
  (同周期遥控接管仍然生效)。接入层同时在代次变化时清空邮箱与事件队列。
- **目标自带授权身份**: 关节/执行路径使用"目标被接受时"的授权, 不在执行时换发当前 token;
  事件队列元素同样携带动作 ID + 发出时授权 + 期限, 消费时重新核对。
- **序号事务**: `check_intent()` 只判定, `commit_intent()` 才提交。接入层按
  **判定 → 入队 → 提交** 的顺序执行, 因此队列满时不会消耗序号, 上位机重试同一序号仍然可入队。
- **代次语义边界**: `ExecutionGate` 只承诺**启动内**撤销(每次 arm/invalidate 使旧 token 失效,
  耗尽不回绕); 本地 token 从不跨重启保存, 线协议也不携带本地 generation, 跨重启身份由会话层
  (`SessionId.boot`) 与本地显式重建流程负责, 不用随机初值伪装跨重启隔离。
