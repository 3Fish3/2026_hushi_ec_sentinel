# Sentinel F407 板级说明 (RoboMaster C 板)

当前哨兵下位机目标硬件为 **RoboMaster 开发板 C 型**（主控芯片 STM32F407IGH6），源码位于 `boards/sentinel_f407/`。
本文档详细说明当前板级固件的外设资源映射、非运动安全观察机制与 RAM 在线诊断区。

接线前先读 [接口与接线注意](接口与接线注意.md): 外壳 `UART1` 实际对应 USART6, `UART2` 对应 USART1; 达妙 USB2CANFD 手册与 C 板 CAN1 的 2pin H/L 排列不同, 但现场实物已更正为 USB2CAN REV V3.0, 不能直接套用 FD 型号资料. 官方 C 板 PDF 为本地资料, 不入版本控制; 文件名与校验和见该页.

任务/周期/优先级与 Flash/RAM/队列预算见 [资源与并发预算](资源与并发预算.md); 该页同时记录装配层入口与"默认镜像没有执行器发送路径"的静态边界。

## 1. 当前外设资源配置与用途

下表为工程当前的硬件外设与引脚映射基线。在连接实机物理线缆时，务必对照硬件版本、线序接口与工作电平（3.3V / 5V / 24V），禁止凭主观臆测接线：

| 外设接口 | 芯片物理引脚 | 当前配置与工作模式 |
|---|---|---|
| **USART1** | TX: `PA9`, RX: `PB7` | 115200 8N1；配置 512 字节环形 DMA 接收缓冲区；用于上位机通信测试回显（TX 使用有界缓冲队列） |
| **USART3** | TX: `PC10`, RX: `PC11` | DR16 遥控接收；100000 8E1（CubeMX 配置 9 位字长含偶校验）；配置 64 字节环形 DMA 接收缓冲区 |
| **USART6** | TX: `PG14`, RX: `PG9` | 外壳 UART1 的 3pin; 115200 8N1, 512 B 环形 DMA RX、单帧有界 DMA TX; 可选只读观测服务, 不是回显或电机控制口 |
| **CAN1** | RX: `PD0`, TX: `PD1` | 1 Mbps 波特率；当前处于非运动只读观察模式，接收电机与传感器报文 |
| **CAN2** | RX: `PB5`, TX: `PB6` | 1 Mbps 波特率；当前处于非运动只读观察模式，接收电机与传感器报文 |
| **SPI1** | SCK: `PB3`, MISO: `PB4`, MOSI: `PA7` | Mode 3，挂载在 APB2（84 MHz），采用 16 分频配置为 **5.25 MHz**（符合 BMI088 手册要求的 10 MHz 上限） |
| **BMI088 片选** | ACC CS: `PA4`, GYRO CS: `PB0` | 由板级软件严格串行管理加速度计与陀螺仪的独立片选拉低/拉高与 SPI 事务 |

> **安全与非运动状态认知**：
> 当前 S1~S4 阶段的板级固件为 **“非运动观察固件 (Non-Actuating Observation Image)”**：
> - 固件内部完全未链接任何电机控制帧下发逻辑，未初始化电机 PWM，未开启 USB，板载 IMU 恒温加热电阻默认关闭；
> - ⚠️ **但这绝对不能当作“插电后物理上 100% 绝不会动”的免责护身符！** 在实机连线上电前，仍必须严格遵循操作规程：**按具体阶段核定供电与执行器隔离方案**，经核准授权后方可执行上电观察。主控基础检查先隔离执行器；真实电调反馈验收则需要相应供电及机械安全措施，不能统一要求全部电调断电后仍有反馈。

## 2. 全局 RAM 在线诊断结构体 `g_ec_io`

在没有接电机、也不能随便打印日志淹没串口的观察阶段，开发者如何得知串口、CAN 总线和陀螺仪到底有没有在正常收发数据呢？
答案就是：**全局静态 RAM 诊断区 `g_ec_io`**！

固件在全局 SRAM 中预留了一块固定的结构体 `g_ec_io`（类型为 `EcBoardIo`，当前魔数为 `0x45434F49`，ABI 版本为 2，源码见 [board_io.h](../../../boards/sentinel_f407/include/board_io.h)）：

| 诊断结构体子字段 | 包含的关键观察指标 |
|---|---|
| **`usart1`, `usart3`** | 累计接收字节数、发送字节数、溢出被丢弃字节数、硬件错误（Framing/Overrun/Noise）与 IDLE 帧空闲中断发生次数 |
| **`can`** | CAN 报文接收总量、最后捕获到的标准 ID 与所属总线编号、在线设备总数、最后解析出的转速 `last_speed_rad_s`、温度及温度有效标志 `last_temp_valid` |
| **`remote`** | 遥控器 `ch0 ~ ch3` 原始整数数值（[-660, 660]）、`switch_left/switch_right` 拨杆状态、`mouse_x/y/z` 与 `mouse_left/right`、`keys` 按键位、最后一次有效帧的时间戳与在线状态 `online` |
| **`imu`** | BMI088 初始化状态机状态、采样成功计数、SPI 通信错误计数、解析出的最新三轴加速度、三轴角速度与芯片温度 |

USART6 面板不直接把 `g_ec_io` 内存结构体发送出去, 而是在任务中一致复制选定字段并显式编码; UART6 自身的计数也随响应给出, 不改变现有 `g_ec_io.abi=2`. 使用方式见 [串口观测与应用接入](../../guides/串口观测与应用接入.md).

### 如何在实机调试中读取诊断数据？
在连接 ST-Link 并通过 OpenOCD/GDB 挂载主控板后，可以在 GDB 命令行中将单片机内核暂停（Halt），然后直接执行：
```gdb
(gdb) p g_ec_io
```
GDB 将完整打印出所有外设的实时收发统计！
- 控制任务要**一致**的遥控/IMU 样本时不要读诊断区，用 `board_inputs.hpp` 的 typed 交接（`input_remote(now)` / `input_imu(now)`）：它带采样时刻与有效性，完整样本（含键鼠）由接收路径直接发布。
- **注意**：`g_ec_io` 是带 `volatile` 的诊断区，用于停核诊断，不是运行中的一致快照。各字段需结合时间与有效性阅读；`remote.online` 也不代表执行授权。停核会打断单片机的微秒级连续时序，重新恢复运行并进行连续性能测试时，建议复位重新开始。
