# 哨兵实车采集 · 简明操作

更新: 2026-09-25. 配合HANDOFF包使用, 旧包里的“先读我”以本文为准.

本次只做**基础运动采集和底盘/云台对齐时的零位记录**, 不做完整标定验收. 不调PID、不驱动电机、不写电调零点, 全程手动移动云台.

**要交回的内容: 一段静止、一次对齐记录、主yaw/发射yaw/pitch各一段主要运动.** 不要求精确转角、不要求其它关节完全不动、不要求每段回到同一个起点.

## 1. 先准备

- 结束旧控制, 先给电机断电. 刷固件不能代替停车, 只读固件也不会主动帮电机停车.
- 清除弹丸, 不操作摩擦轮和拨弹, 保留物理断电开关. 底盘停稳, 手动操作时不要让整车跟着转或滑动.
- C板牢固固定在**随pitch一起运动的末端结构**上, 不手持、不松动. 本轮中途不改安装; 拍一张固定近照, 备注是否换板或重装. 若装在其它位置, 先说明.
- **pitch需要防止自由坠落, 不需要全程保持某个精确角度.** 用手或现有可靠支撑承托即可; 转主yaw时不要把随动结构硬按在地面方向上. 一个人无法兼顾就找人协助, 不为凑数据勉强操作.
- 主yaw按本次提供的结构描述处理: **可360°转动, 无机械限位**, 不人为规定左右端点或必须对称往返. 仍注意线束不要缠绕、拉紧; 本次不需要连续多圈. fire和pitch按各自实际可动范围操作.
- 解压完整HANDOFF文件夹, 不在压缩包内运行, 不单独拷走exe. 已有只读采集固件和程序可以继续用.

## 2. 核对电机和接线

| C板总线 | 电机/位置 | 设备ID | 反馈ID |
|---|---|---|---|
| CAN1 | GM6020 主yaw | 4 | 0x208 |
| CAN1 | GM6020 发射yaw | 6 | 0x20A |
| CAN1 | 达妙 pitch | CAN_ID=1, Master_ID=0 | 0x000 |
| CAN2 | 左前/右前/左后/右后轮 | 1 / 2 / 3 / 4 | 0x201 / 0x202 / 0x203 / 0x204 |
| CAN2 | 左/右摩擦轮 | 5 / 6 | 0x205 / 0x206 |
| CAN2 | 拨弹 | 7 | 0x207 |

**旧0924包把两个yaw的名称标反了: 实际主yaw是ID4, 发射yaw是ID6. 按本表和手动运动认电机, 不改电机ID迁就旧标签.**

- CAN核对H/L, 保持原车正确的终端接线, 同总线不要有重复地址.
- USB串口接C板丝印 **UART1=USART6**, 不是UART2. TX接RX、RX接TX、GND共地; **不并接USB串口VCC**.
- 需要烧录时接ST-Link, 电脑只接一只. 串口与SWD可以同时连接, 录制时不要用调试器暂停MCU.
- 右摩擦轮故障本次不处理. 底盘/摩擦轮缺反馈写在备注里, 三轴和IMU齐全即可继续采云台.

## 3. 需要时烧录只读固件

**已经运行交接包的只读采集固件, 就跳过这一步.** 固件不明或仍是控制固件时才重刷. 电脑需有STM32CubeProgrammer和对应驱动; 采集程序不需要Python.

1. 电机电源保持断开. 在CubeProgrammer选择ST-LINK / SWD, 连接后确认STM32F405/407、1 MiB Flash; 不匹配就停止.
2. 先读取原Flash: 起始`0x08000000`, 长度`0x100000`, 另存备份, 不覆盖旧备份.
3. 下载并校验包内`firmware/sentinel_capture.hex`. **不全片擦除, 不改Option Bytes/读保护**, 只擦写镜像覆盖扇区. 0924包为扇区0–4, 换包时重新核对.
4. 校验成功后复位运行, 再正常给C板和电机供电. SWD连上不代表电机已经供电. 不刷S1、正式APP或台架S5.

## 4. 检查并记下对齐零位

1. 双击`启动采集.cmd`, 选择COM口, 波特率 **1,000,000**. 关闭其它占用串口的软件.
2. 点“1. 检查电机 / IMU”, 用“全车轮询”等10–15秒. 确认三轴在线、IMU更新、达妙参数有读回并刷新, 保存`mapping-*.jsonl`.
3. 分别轻动主yaw、发射yaw和pitch, 按CAN地址确认对应编码器变化. 不用精确测角, 不用每动一次就回零.

### 对齐只做一次, 不要求运动后再回到同一个R0

- 在底盘上指出“车头向前”, 在**主yaw平台本体**上指出一条朝前基准线, 拍照或贴箭头. 不拿当前枪口或C板方向反推车头.
- **主yaw零位记录:** 将主yaw平台基准线对准底盘前方. 在检查窗口选ID4对应行, 等页面刷新并短暂停稳, 填`主yaw对齐底盘前方, 人工对齐`后点“记录标记”.
- **发射yaw零位记录:** 将枪管的水平投影对准主yaw平台前方基准线. 选ID6对应行, 短暂停稳后填`发射yaw对齐主平台前方, 人工对齐`并记录. 不用“两个yaw相互抵消, 枪口看着朝前”替代这两个关系.
- **pitch:** 能方便托到枪管水平时, 选pitch行记录`枪管近水平, 目测`或实际测量方式. 不方便保持水平就记录当前承托姿态并写`pitch零位未确认`, 不强行摆水平, 不把任意姿态当作零位.

记录哪个轴, 只需在那一刻确认该轴的对齐关系; **不要求手工同时精确锁住三轴**. 如果漂动了就调整后重新标记该轴, 不把先后几次标记当成同一时刻的精密测量. 拍清对齐基准, 如实写“人工/目测”. 主yaw这次记录的是朝前方向, 不是限位, 也不是累计转了几圈.

完成后关闭检查窗口. 选“主yaw单轴运动”录约20秒, 备注`对齐记录`: 尽量让两个yaw处于上述对齐关系, pitch保持方便承托的姿态, 拍一张对应照片. 留下一小段可辨认的对齐停顿即可, **不要求20秒全程精确保持**; 若滑开, 备注大约何时对齐, 不能稳定对齐就如实说明. 不默认这个文件和之前的标记姿态完全相同.

这里的“零位记录”只是保存对齐时的原始读数, **不修改电调或MCU零点, 也不等于已经完成软件零位配置**.

## 5. 只采必要的几段

每段选菜单、时长、填简短备注, 点“2. 开始记录”, 等显示“正在记录”后再动. 检查窗口和录制不能同时占用串口.

| 内容 | 选择菜单 | 建议时长 | 怎么做 |
|---|---|---|---|
| 静止 | 静止 / 温漂 | 30–60秒 | 在方便稳定承托的任意姿态, 让整车和云台真正静止. 不要求朝前或pitch水平 |
| 主yaw主要运动 | 主yaw单轴运动 | 30–45秒 | 推动主yaw承载的上方总成, 平顺转动、停一下、换向. 幅度自行选, 不测指定角度, 不要求整圈或回起点 |
| 发射yaw主要运动 | 发射yaw单轴运动 | 30–45秒 | 主要拨动发射yaw左右转, 中间有启停和快慢变化. 不要求主yaw/pitch精确锁住 |
| pitch主要运动 | pitch单轴运动 | 30–45秒 | 承托着抬头、低头往返, 不自由下落. 不要求两个yaw保持指定角度 |

- 静止段可以在对齐前或运动前后方便时录. **静止不等于固定在指定角度**; 如果一直晃动就注明没有有效静止段, 不把晃动数据标成静止. 如果对齐时本来就能稳定不动30–60秒, 用运动菜单录下三轴和IMU, 可同时作为对齐与静止记录, 不必再录一份.
- 一次主要操作一个关节, 不是要求“纯单轴”. 其它关节自然漂动允许如实保留, 不必为了压住它们同时使劲; **也不要故意三个轴一起乱动**. 明显带动其它轴时写一句备注, 不写虚假的“其它轴已固定”.
- 前后方便时稍停几秒, 运动平顺、不猛甩、不撞fire/pitch的实际限位. main/fire向左指从上方看逆时针, pitch用“抬头/低头”描述; 备注先往哪边动即可.
- 三个运动菜单都会记录三轴电机和IMU, 菜单名称只是标签, 不会驱动电机. “静止 / 温漂”只录IMU, 电机条数为0正常; **对齐记录必须选运动菜单**.
- 不再安排指定30°/45°刻线、每轴两轮、两个额外pitch静止姿态、专门组合运动、结束回R0或结束温漂. 有真正缺失的数据再针对性补, 不先要求整套重录.

备注例子: `本次安装; 主yaw; 先左后右; pitch由人承托并有缓慢变化`. 重装C板后给本批起一个新名字, 不覆盖或混用旧安装记录.

## 6. 看结果, 交回文件

- 正常应显示“记录结束 · 传输完整”, 记录缺口、CRC错误和板端丢弃均为0. 运动/对齐项目应有IMU和三轴电机记录; 某轴为0先查供电、ID和接线.
- 异常文件也保留. 电池休眠或反馈消失时, 恢复供电后新开一段重录并备注, 不拼接断开的记录. **停止记录不等于停止电机.**
- 点“打开记录目录”, 交回**整个records文件夹**, 包括`.sraw`、同名`.summary.json`和`mapping-*.jsonl`, 再附对齐照片、C板安装照片、未确认的零位及异常说明. 本次烧录过则附原Flash备份.
- 不用导出CSV、现场拟合或调参数. 本批用于核对运动方向、形成安装关系候选及整理零位证据; **人工对齐有误差, 不宣称精密零位、比例/时延标定或闭环验收通过**.

开发端按三轴实际记录处理, 不把串动当成纯单轴、不把缺失的角度或零位补成0. 现有完整拟合程序还要求独立验证数据, 对齐记录也不会自动导入软件零位; 这批简化采集不保证直接跑完完整标定流程. 需要进一步确认时, 再明确缺哪一项、补哪一段.

技术细节另见[哨兵只读采集与人工标定](哨兵只读采集与人工标定.md), 现场不需要先读. 随旧HANDOFF包交接时附上本文即可, 不必为更新说明更换固件或exe.
