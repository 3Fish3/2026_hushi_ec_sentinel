# main 双串口记录

适用于联调 APP，不需要切换到 capture 固件。脚本仅查询、启动/导出记录窗口，不申请运动控制权、不发目标、不改参数、不操作 SWD。

## 当前接线

| 用途 | 探针序列号末尾 | 固定设备路径 | 波特率 |
|---|---|---|---:|
| APP业务口（板上丝印UART2 / USART1） | 384 | `/dev/serial/by-id/usb-Horco_Horco_CMSIS-DAP_332107148384-if02` | 921600 |
| APP观察口（板上丝印UART1 / USART6） | 353 | `/dev/serial/by-id/usb-Horco_Horco_CMSIS-DAP_332107148353-if02` | 115200 |
| SWD | 8308 | 不参与串口采集 | — |

以上是当前实测线缆对应关系，不是探针固有职责；换线后须重新核验，可用 `--business-port`、`--observe-port` 显式指定。

## 在 Jetson 上运行

先确认没有其他进程占用两路串口。在准备好遥控操作和停止手段后运行：

```bash
python3 ~/sentinel-host/sentinel_record_main_dual.py \
  --seconds 120 --raw-ms 500 --trigger-deg 5
```

按一次回车，等待连接检查和倒计时。看到“开始记录”后自由操作，不要求键盘标记或固定动作顺序。脚本不会驱动底盘；操作者自行控制运动，异常时先撤运动，必要时硬断电。

**Ctrl+C、录制到时和脚本报错都不会让机器人停车。**

## 记录内容

- `status.jsonl`：约10Hz完整status 0/1/2页、开始时参数快照与身份。
- `main-control-*.sraw`：main控制短窗，含目标、机械反馈、归一化控制输出、限流标志、步长和发送结果。
- `control-windows.jsonl`：每份短窗的触发误差、请求/保存时间、MCU窗口时间、条数，以及失败请求阶段。
- `summary.json`：成功/错误次数与触发条件满足的状态采样数。

默认目录为 `~/captures/main-dual-<UTC时间>/`，拒绝覆盖已有目录。

## 触发与覆盖边界

- 默认只在main处于有效的局部惯性位置控制，且同页采用目标与测量的绝对误差达到5°时触发。5°是采集触发策略，不是验收精度。
- 导出期间只保留最新触发，恢复到阈值内会清掉待触发；超过0.5秒的触发不会补抓。
- `--raw-ms 500` 请求500ms，但固件共用缓存仅512条，满后提前冻结。以文件中的实际MCU窗口时间为准，不能将请求时长当作实收时长。
- 请求开始前还存在业务状态采样和串口延迟，没有预触发回溯；不保证捕获误差的绝对峰值。
- 导出时不能同时开始另一个高频窗口。高频数据是间歇片段，不能声称整个120秒都记录了高频控制输出。
- `--trigger-deg 0` 可用于无条件间歇短窗通信自检，不是机器人运动模式。
- 若没有达到阈值，0份高频短窗可能是正常结果；查看 `trigger_condition_samples`。若已经触发但导出失败，日志会保留错误，不计作成功。
- 最后一个窗口可能在状态记录到时后继续导出；脚本会显示收尾进度。所有记录时间需按各自MCU时间关联，而不是按导出完成时刻关联。
