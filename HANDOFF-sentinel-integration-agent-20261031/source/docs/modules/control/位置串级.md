# 位置串级 (PositionLoop)

源码: [position_loop.hpp](../../../include/ec/control/position_loop.hpp)、[position_loop.cpp](../../../src/control/position_loop.cpp), 类型位于 `ec::control`.
契约测试: `tests/control_tests.cpp`; 角度工具见 [angle.hpp](../../../include/ec/control/angle.hpp).

## 1. 解决什么问题

位置控制不是一个单独的 PID: 外环把角度误差变成**速度目标**, 内环再把它变成执行量. 本组件复用正式 [速度控制链](速度控制链.md) 作为内环, 不复制 PID、时效与授权判断.

它**不负责**: 位置参考的建立、零位标定、机械限位、跨圈语义的业务选择. 参考由 [DJI 轴门面](../motion/DJI轴门面.md) / 设备层显式建立.

## 2. 角度误差的两种语义

| `ArcMode` | 误差 | 适用场景 |
|---|---|---|
| `continuous` | 最短弧 (`shortest_arc_error`), 允许跨圈 | 连续旋转的轴, 例如 yaw |
| `bounded` | 直接相减并限制在 ±π | 有机械范围的轴, 越界必须由上层阻止 |

选择哪种是**机构语义**, 不是实现细节: 同一个角度在两种语义下的目标方向可能相反. `wrap_to_pi()` / `shortest_arc_error()` 只做数学, 不判断机械范围.

## 3. 配置与输出

| 字段 | 含义 |
|---|---|
| `position_pid` | 角度误差(rad) → 速度目标(rad/s). 默认限幅须落在内环正的`max_target_rad_s`内; 若要不设软件速度限幅, 显式设`position_pid.limit_output=false`并令内环`max_target_rad_s=0` |
| `velocity` | 内环配置, 直接复用 `VelocityLoopConfig` |
| `arc` | 误差语义 |

`step()` 返回 `PositionResult{status, output, velocity_target, velocity_status}`:

- `output` 是归一化执行量, 必须由执行器适配换算 (不是 A 或 N·m);
- `velocity_target` 是外环产生的内环目标, 便于诊断"是外环还是内环拒绝了本周期";
- `inner_rejected` 表示内环拒绝 (反馈失效、目标过期等), 此时没有输出.

## 4. 复位与常见错误

- 重新建立位置参考后必须 `reset_controller()`: D 项作用于测量值, 参考跳变会经 D 项产生一次冲击; `reset()` 不是 bumpless transfer, 它只清控制器历史.
- 把 `bounded` 当成"自动限位": 它只限制误差计算方式, 越界目标仍然要由上层拒绝.
- 内环正的`max_target_rad_s`比外环输出限幅小: 构造时失败. 在线`set_inner_max_target(0)`会同时取消外环速度限幅, 正值则恢复匹配的外环边界, 不重置PID历史.
