# IMU 温控计算 (ThermalController)

源码: [thermal.hpp](../../../include/ec/control/thermal.hpp)、[thermal.cpp](../../../src/control/thermal.cpp), 类型位于 `ec::control`.
契约测试: `tests/control_tests.cpp` (关闭即输出 0、超时归零、占空比有界).

## 1. 解决什么问题

IMU 零偏随温度漂移, 加热电阻把陀螺仪稳在固定温度附近可以减小漂移. 本组件只做**温度 → 占空比**这一步计算: 输入温度与采集时刻, 输出 `[0, duty_limit]` 内的占空比, PWM 由平台层写到具体定时器.

它**不负责**: PWM 外设配置、温度传感器来源、加热使能策略、故障锁存. 默认**关闭**, 关闭或温度失效时输出 0, 不做任何"HAL 输出默认接通"的假设.

## 2. 配置与来源

| 字段 | 默认值 | 来源 |
|---|---|---|
| `target_c` | 40.0 | 旧配置 `RefTemp`, 不是实测最优温度 |
| `deadband_c` | 0.1 | 旧 PID `Deadband`, 误差在带内时不重算输出 |
| `kp` / `ki` / `kd` | 0.2 / 0.004 / 0.0 | 旧 `Kp 1000/°C`、`Ki 20` 按占空比尺度换算 |
| `duty_limit` | 0.4 | 旧 `MaxOutput 2000` / 旧 PWM `ARR=4999` |
| `integral_limit` | 0.06 | 旧 `IntegralLimit 300` 同尺度换算 |
| `temperature_ttl` | 500 ms | 温度样本有效期, 到期输出 0 |

换算前提是旧固件 TIM10 的 PWM 尺度 (`ARR=4999`, 预分频 167). **换到别的定时器或别的占空比基准时必须重新换算**, 否则同一组参数会得到完全不同的加热功率.

## 3. API 与状态

```text
set_enabled(true/false)          // 状态变化时清控制器历史
update(temp_c, temp_at, now, dt_s) -> duty
status()  // off / active / temperature_stale / invalid_input / invalid_dt
duty()    // 最近一次输出
```

温度超时、非法输入或非法 `dt_s` 时输出 0 并给出对应 `Status`, 不沿用上一次输出. 关闭期间积累的积分会在重新使能时被清掉, 避免一开就满功率.

## 4. 板级现状与边界

F407 板级当前**没有接线到 PWM**: `.ioc` 里没有对应通道, 默认镜像的静态审计也禁止出现 `HAL_TIM_PWM_*`. 因此本组件目前只有主机侧验证, 接通加热需要一次 CubeMX 配置与单独授权. 没有实测温度曲线, 不宣称稳态精度或超调指标.
