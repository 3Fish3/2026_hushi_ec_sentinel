# 固件刷写与上位机对应

本文是当前开发/台架电脑的工具入口, 不替代实车部署参数确认. 返回[文档总览](../README.md), 详细构建配置见[生成与构建](../boards/sentinel_f407/生成与构建.md).

## 1. 快速打开

双击仓库内`boards/sentinel_f407/tools/firmware_tool.cmd`, 或从仓库根目录运行:

```powershell
.venv/Scripts/python.exe boards/sentinel_f407/tools/firmware_tool.py
```

使用现有项目Python/Tkinter, 不新增GUI依赖. 工具调用本机CMake、Ninja、ARM GNU、STM32CubeF4和OpenOCD; 默认从PATH及已有构建缓存发现路径. 首次或换电脑时展开“工具路径”检查, 运行任务时保存到`build/firmware-tool/settings.json`. 仅烧录已有ELF不需要重新构建, 但仍需ARM的nm/objcopy及Python完成角色审计. USB探针枚举使用Windows PowerShell 7, 不更换驱动或全局安装工具.

**打开窗口、切换用途、检查固件、仅构建均不连接串口或SWD.** 只有明确点击烧录按钮才连接ST-Link, 工具不下发电机使能、运动目标或调参请求.

## 2. 选哪一个

| 用途 | 上位机 | 下位机固件 / 编译配置 | 串口 |
|---|---|---|---|
| 实车底盘离地/遥控调试 | `sentinel_console.py --mechanism chassis` | `sentinel_app`, `EC_APP_CHASSIS_COMMISSIONING=ON` | 丝印UART2 / USART1 / 921600 |
| 当前四电机人工台架 | `sentinel_console.py --mechanism bench` | `sentinel_app`, `EC_APP_FOUR_MOTOR_BENCH=ON` | 丝印UART2 / USART1 / 921600 |
| 单GM6020人工台架 | `sentinel_console.py --mechanism gimbal` | `sentinel_app`, `EC_APP_GM6020_BENCH=ON` | 丝印UART2 / USART1 / 921600 |
| 实车只读采集/标定 | `sentinel_capture_station.py` 或交接包`CaptureStation.exe` | `sentinel_capture`, 标签`capture-cap-stream-1m-v1` | 丝印UART1 / USART6 / 1000000 |
| 旧S5单GM波形调试 | `motor_bench_console.py` | **`sentinel_s1`文件名**, `EC_S5_GM6020_BENCH=ON` | 丝印UART1 / USART6 / 115200 |
| 正式APP实车软件入口 | `sentinel_console.py` 或Jetson业务链路 | `sentinel_app`, 两个bench选项均OFF | 丝印UART2 / USART1 / 921600 |
| 基础只读观测 | `board_monitor.py` | `sentinel_s1`, `EC_S5_GM6020_BENCH=OFF` | 丝印UART1 / USART6 / 115200 |

- **不要只看文件名**: 三种APP都叫`sentinel_app.elf/bin`, S1与S5都叫`sentinel_s1.elf/bin`, 能否驱动完全不同. 工具按所选角色审计ELF, 拒绝错角色和已废弃的ID7/旧单圈台架版本.
- 当前四电机全部CAN1: GM6020 ID4、M3508 ID2、M2006 ID3、J4310控制ID1/反馈ID0. M2006不能回到ID7, 否则0x1FF与GM电压指令冲突; M3508不能ID1, 避免反馈0x201命中达妙低8位控制ID. 界面接线说明对应本仓库当前配置, 不等于读取了实物电调参数.
- 实车APP当前仍是**零执行槽占位**, 没有因为台架通过就获得上车执行资格. 台架镜像也不能直接拿去驱动实车机构.
- 正式APP还有丝印UART1/USART6的115200只读观测口, 不是第二业务控制口. 同一UART2不能并接Jetson与PC两个发送端. 全部串口使用TX/RX交叉、共地, 不将模块VCC并接已供电C板.
- S5有电流/速度/位置与冻结波形; 正式维护台是APP目标/参数接口, 不能拿S5上位机连APP. capture允许DM白名单只读查询, 不是S1的零CAN发送角色.

## 3. 刷写步骤

1. 在原上位机撤销目标并断开控制会话, 保留现场物理电源硬切. 接SWD, 当前只连接一个ST-Link.
2. 选择用途. 窗口会显示默认ELF、对应上位机、串口和编号说明. 可以选择其它同角色ELF, 但仍必须通过审计; 不直接接受缺少角色信息的裸BIN.
3. **快速更新源码:** 点击“构建并烧录”. **使用已有产物:** 点击“烧录已有固件”. “仅构建”不会接触硬件, “检查固件”只验证文件. 七种用途分别使用独立构建目录, 不在一个目录混用角色.
4. 工具从所选ELF生成固定BIN快照、执行现有角色审计并显示SHA256/大小/扇区范围. 实际只写BIN到`0x08000000`, 不把ELF任意地址段直接交给硬件加载器.
5. 烧录前确认恰好一个ST-Link, 再由目标寄存器确认STM32F405/407 (低12位ID=0x413) 与1024KiB Flash. **只逐个擦除镜像覆盖的扇区**, 写入、校验, 成功后复位运行并退出OpenOCD. 不读Flash备份、不整片擦除、不改Option Bytes、不自动重试.
6. 日志显示成功后启动对应上位机并重新连接. GM台架重启后需人工重新建立本次位置参考; J4310保持原生位置语义, 不套用GM设零. 不会因烧录成功自动申请运动权限.

单次日志、所选镜像副本及SHA256信息在`build/firmware-tool/runs/`. 这里保存的是**构建文件副本**, 不是从板子读取的Flash备份. 窗口关闭前等待当前任务完成. 若写入/校验失败, 工具不宣称成功也不自动复位运行; 目标可能保持暂停, 请先按日志处理连接/供电/文件问题再手动重试. 不提供整片擦除或解保护按钮.
