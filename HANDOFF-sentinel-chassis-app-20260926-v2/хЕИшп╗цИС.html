四全向轮底盘调试 HANDOFF

本包用于离地逐轮调试 → 遥控底盘落地运动实测. 已包含可驱动的专用APP, 只开放四轮; 不开放云台、发射、Jetson或小陀螺. 几何以现车CAD为准, 传动比由用户确认为19:1. 不再要求重测尺寸或先做整轮只读采集.

1. 接线、ID与上电前准备

从车体上方看, A边(全向轮3/5之间)为车头. 包内看底盘轮位与ID.png.

实际轮位CAD实例人工设置电调反馈编号
左前LF全向轮-3CAN2 ID10x201
右前RF全向轮-5CAN2 ID20x202
左后LB全向轮-2CAN2 ID30x203
右后RB全向轮-4CAN2 ID40x204

• 四轮M3508/C620接CAN2, 共用0x200命令组. 同总线保留摩擦左ID5、摩擦右ID6、拨弹ID7, 不重复编号. 不套用裸四电机台架CAN1编号.

• DT7接收机接C板DBUS. PC串口接丝印UART2 / USART1, 921600, TX/RX交叉、共地, 不并接VCC, 不与Jetson并联TX. SWD接ST-Link.

• 检查紧固、CAN与供电, 可靠支架撑起四轮, 物理电源硬切可用. pitch在本版本失能, 有重力下落风险的机构须先物理支撑.

• 固件会给其它DJI已知地址显式零电流, 对pitch发失能/状态查询. 这不是其它机构的调试资格或承重保持.

• 烧录前断动力, 遥控右拨杆下位, 两摇杆回中. 完成离地检查前不要把车放地运行.

2. 安装脚本与刷写

只提供原始Python脚本与依赖, 无EXE. 建议解压到短路径(例如E:/chassis), 避免Windows工具链重建时遇到路径长度限制. 在解压目录执行:

`powershell

python -m venv .venv

.venv/Scripts/python.exe -m pip install -r requirements.txt

.venv/Scripts/python.exe source/boards/sentinel_f407/tools/firmware_tool.py

`

刷写工具选择 APP / 实车底盘调试, 默认镜像位于包内source/build/app-chassis-arm-Release/boards/sentinel_f407/sentinel_app.elf. 操作使用“烧录已有固件”, 不必先构建. 固件标识以app-chassis-开头, 完整标识与SHA256见PACKAGE.json.

工具设置中填写本机OpenOCD、其scripts目录、ARM GNU Toolchain根目录和PowerShell 7路径; Python选择本包.venv/Scripts/python.exe. 工具不会替你全局安装这些软件. 仅刷现有固件不需要CMake、Ninja或STM32CubeF4; 重建才需要它们.

烧录核对唯一ST-Link、STM32F405/407及1MiB Flash, 只擦写镜像覆盖扇区并校验. 不备份Flash、不整片擦除、不改Option Bytes. 不刷S5、裸四电机、capture或实车占位版本替代本镜像.

3. 档位和上电行为

拨杆左右均指手持遥控器正常操作时的左右; 本版完全忽略拨轮.

右拨杆左拨杆本版行为
下任意人工整车停止, 撤输出, 维护台也不能驱动
上中待机, 允许PC显式申请维护
中上遥控底盘驾驶
其它组合待机, 不开放Jetson/云台/射击/小陀螺

刚上电不自动行驶或回零. 需要真实有效遥控帧完成首启, 维护台不能绕过. 连接PC不自动授权或发送目标. 若上电就是驾驶档, 三个驾驶通道回中过后推杆即可产生运动, 不必点击GUI.

接管驾驶、解除停止或遥控失联恢复后, 左杆X/Y与右杆X须回中一次再接管. 遥控驾驶失联撤输出, 不自动转为Jetson或维护. 已显式申请的PC维护以自身会话/目标时效管理, 遥控掉线不自动替它按停止; 人工停止使用右下或物理硬切.

4. 四轮离地, 用维护台逐轮检查

`powershell

.venv/Scripts/python.exe source/robots/sentinel/host/sentinel_console.py --serial COM3 --mechanism chassis --log-dir records/app

`

1. 电机供电, 先保持右下. 连接并检查四轮有新鲜反馈、固件标识正确; 不在线直接查ID/接线, 不必额外采集映射日志.

2. 改为右上＋左中, 点击维护台“申请维护”.

3. 不勾选twist, 勾选四轮目标通道并全部填写, 未测三轮填0. 每次只测一轮, 从输出轴+0.5 → 0 → -0.5 → 0 rad/s开始, 每次点击“下发 / 更新目标”. 确认只对应车轮转动, 速度读回跟随且无明显振动.

4. 对照图中绿色箭头确认该轮的程序正滚动方向. 初始原生方向均为+1, 不是CAD能确认的电机正号. 不符则F8撤目标, 修正对应chassis_motor_directions后重刷再测, 不填负PID. 轮位错误优先改硬件ID.

5. PID可逐项调整并查看MCU读回; 抖动或异常时撤目标, 必要时物理断动力, 保存参数/日志. 速度比例异常检查传动与反馈, 不用PID掩盖.

6. 完成四轮正反检查后F8撤目标. 参数“保存候选”写在PC, 不写MCU Flash.

维护台F8只撤维护目标, 不代表遥控驾驶时的整车停止. 速度0是零速闭环, 也不等于撤输出. ACK接受不等于已执行, 看执行状态和实际反馈.

5. 落地后直接用遥控测试

1. 四轮全部方向正确且离地响应稳定后, 在右下停止时落地, 周围留空. 不需要切换另一份固件.

2. PC先F8、保存参数, 再“释放维护”. 不复位MCU就会继续使用已热调参数; 断电将恢复编译默认值.

3. 左右摇杆回中, 切到右中＋左上:

- 左杆前/后: 车头方向前进/后退.

- 左杆左/右: 向车体左/右横移.

- 右杆左/右: 俯视逆时针/顺时针旋转.

- 右杆前后、拨轮: 不使用.

4. 小幅逐项推杆, 先前后、再横移、最后旋转, 每项回中观察停止, 再尝试组合移动. 此处前方是车头, 不是云台.

5. 左杆每轴满量程0.4m/s, 右杆旋转满量程0.8rad/s; 混合指令超过轮速上限时整体同比缩小. 摇杆回中为零速度闭环; 右下为撤输出.

6. 需要再调参时回中、右下停车, 改为右上＋左中, 在PC重新申请维护. 遥控接管会作废先前维护申请, 不自动复用旧目标.

首次离地时也核对实际拨杆与摇杆对应. 若与表不一致, 保持右下/断动力并反馈, 不尝试靠未知档位在地面摸索. 小陀螺需要云台参考与稳向联调, 不在本镜像内.

结束: 右下停止 → PC撤目标/释放维护 → 保存候选和日志 → 断动力. 仅反馈实际异常、方向修正和调参结果, 不重填已有CAD数据.

本包通过离线原生契约、主机回归与ARM角色审计; 不代表已完成实车CAN负载、轮向、DT7物理对应或地面运动验收. 完整七路CAN2反馈频率仍需现场诊断核对; 总线错误增加或四轮反馈断续时先处理链路, 不继续加大PID.
